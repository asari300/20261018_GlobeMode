## 依頼

S367 のあと、MSL の例題で自前の flat が断るのは 5 本。うち `non-constant-dim` の 4 本は FFT で、`realFFTsamplePoints(...)` のような `algorithm` を持つ関数を評価しないと配列の大きさが決まらない。S367 は `anyTrue`・`isPowerOf2` を名前で決め打った。flat の定数の評価（`eval`）に、入力が定数に決まる `function` の `algorithm`（代入・`if`・`for`・`while`・`return`・整数・実数・論理のスカラーと 1 次元の配列・組み込みの数学関数）を実行する最小の評価器を足す。`external` と副作用（`assert` は可）は評価しない。反復の上限と再帰の深さの上限を置く。可能なら決め打ちを置き換える（MSL の本体を評価して同じ結果になることを確かめてから）。FFT の 4 本を平らにし、Rumoca と名前・方程式の数を突き合わせる。小さな回帰試験。最後に全体の検査を 1 回回し、回帰 0 と数字を書く。

## 決めたこと

- **評価器は `flatten/fneval.rs` の別のモジュール**。`eval` の `Ctx` の局所変数（`Vec<(String, i64)>`）を広げず、関数の変数は評価器の中の `Frame`（名前 → 型の印と値）に持つ。評価器の式 `fx` は、局所変数・配列・関数の呼び出しを自分で見て、それ以外（リテラル・パッケージの定数・列挙・`size` の外側の配列）は `eval` に任せる。`Ctx` の作り方（10 か所）に触らない。
- **`eval` と共有した部品**: 組み込みの表 `BUILTINS`・`builtin`・`extremum`・`unop`。`eval` の `abs`・`floor`・`ceil`・`integer`・`div`・`mod`・`sqrt` の腕と、単項演算の腕をこれに置き換えた。結果として `eval` も `sin`・`cos`・`tan`・`exp`・`log`・`atan2`・`sign`・`rem` などを評価できる（今まで「分からない」だったものが定数になるだけ）。`mod` は実数の引数も、`div` はゼロ除算を `None` に、単項の `-i64::MIN` と `abs(i64::MIN)` の溢れを `None` にした。
- **上限**: 文と反復は 1 回の呼び出し（入れ子の呼び出しを含む）で `MAX_ITERS`（S365 と同じ定数。試験では 1 万）、呼び出しの入れ子は 32。上限に届いた関数は `fn_blown` に覚えて、同じ関数を繰り返し評価しない（`eval` は同じ式を何度も評価するので、終わらない関数が 1 回ごとに数秒かかるのを防ぐ）。
- **実行しないもの**: `external`・`impure`・入力や出力を持つ基底への `extends`・Real・Integer・Boolean 以外の型・`when`・`assert` 以外の呼び出しの文・複数の左辺。
- **`and`・`or` は左で決まれば右を評価しない**（`anyTrue` の `size(b, 1) > 0 and max(b)` は空の配列で `max` が決まらない）。
- **決め打ちの 3 つ（`anyTrue`・`isPowerOf2`・`numberOfSymmetricBaseSystems`）は消した**。MSL の本体（注釈・説明を除く）を貼った試験で同じ値になる。S367 の試験の `anyTrue` は偽物の本体（常に `false`）で、決め打ち前提だったので MSL の本体に直した。
- **FFT の 4 本は Rumoca と突き合わせられない**: Rumoca v0.10.2 は `ET004`、手元の CLI v0.10.4 も `RealFFT1` で `E008`（`unevaluable array dimensions for 'fi'`）。代わりに omc の `checkModel` の数（`doc/omc-compare.md`）と、自前の DAE の方程式と未知数の数を比べて、4 本とも一致した（5853・5386・245・224）。依頼の「Rumoca と名前・方程式の数を突き合わせる」は、Rumoca が通らないのでできなかった。
