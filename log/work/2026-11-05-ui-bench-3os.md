## 依頼

P7 の完了条件「3 UI × 3 OS の比較」の残り、Windows と macOS の列。手動の `ui-bench.yml`（ubuntu-latest・windows-latest・macos-latest）で Svelte・Leptos・Dioxus のブラウザ版をビルドして測り、artifact `ui-bench-<os>` に JSON を出す。`bench_ui.py` で `doc/bench/ui.md` に「<UI> Windows」「<UI> macOS」「<UI> Linux（Actions）」の列を足し、ランナーの仕様と「共有で、値は目安」を書く。Tauri の測定、CPU・フレーム時間、UI のコード、ci.yml は対象外。

## 決めたこと

- Rust は全 OS でランナーの rustup（Windows で mise の shim の cargo が失敗した前例）。node・pnpm・uv・wasm-bindgen だけ mise-action。
- ビルドは bash で `wasm:build`・`leptos:build`・`dioxus:build` の中身を書き写した（Windows で mise の task の shell に頼らない。LTO の環境変数はビルドの step だけ）。
- Python は `uv run --no-project --with playwright==1.64.0`。`uv sync` は maturin で Rust をビルドするので使わない。
- 列は `<UI>/linux-actions`（表では「Linux（Actions）」）を足し、手元の WSL2 の列は残した。Svelte Tauri の `linux-actions` 列は作らない（desktop.yml の 1 列だけ）。
- Windows・macOS の RSS は psutil（Windows は `peak_wset`、macOS は終了時点の rss）。ユーザーの指示にない追加だが、RSS の行が 2 OS で「未」のままになるのを避けた。
- 新しい workflow は default ブランチに無いと dispatch できないので、feature ブランチの `push` トリガで回し、消してからコミットした。
