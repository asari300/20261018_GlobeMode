## 決めたこと

- **#132 の門は `resolve` に答えさせる。** 案は「`declared` の型が `replaceable` か `Walk.redecl` のときだけ `redeclared_types` を先にする」だったが、`Walk` は `resolve_path` の中で作られて `members_of` から見えず、判定を書き写すと `step` と食い違う（S345 は「LSP に規則を複製しない」で切り出した）。そこで `members_of` が、`scope` で引いた参照に**空の名前を足した参照**（`p.` の続き）を `resolve` に引かせ、`Unresolved(Redeclare)` のときだけ差し替えた型を先にする。`step` の `why == Redeclare`（`Walk` の `redecl`・型の `replaceable`・`Fail(Redeclare)`）が、そのまま門になる。補完 1 回につき `resolve` が 1 回増える（今の道で候補が出ないときだけ通る道）。
- **#133 は DAE の `record_leaves` だけを広げた。** flat の `count`（S337 で Rumoca の `equation_count` に合わせた数）は変えない（並行の flat の WP と衝突しない）。`t.` の欄（スカラーのレコード）で引けなかったときだけ、`t[k].x` の変数を全部集める（`array_leaves`。`t` が変数そのもの・末尾が `]` なら対象外）。長さ 1 の配列（flat の数が 1）も 2 本と数える。
- **Rumoca との関係**（issue に「未確認」とあった）: 小さな模型 2 本（`aw = {…}` と `aw = bw`）で `diff-frontend` の検証枠に入れて調べた。Rumoca の flat は方程式を要素の数（3）で持つが、DAE の釣り合いまで通らない（`rumoca_balance` 0/2。for 文の形は通って自前と一致 2/2）。MSL の `ShowTransferFunction` も 0/1。**Rumoca と比べられないので、MLS の意味（要素ごとのレコードの方程式 = スカラー 6 本）で数えた。**
- **#134 は issue の案どおり**（`catch` と `missing` のときに `lazy.blob = null`）。c/*.json の束は元から直れば通るので変えない。
