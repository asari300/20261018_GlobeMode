## 依頼

S039 の持ち越し「Arrow での結果の受け渡し」。Python の `Workspace.simulate` は CSV の文字列を返し `table()` が polars で解析する。列の道を足す。設計 (a) numpy・(b) Arrow IPC・(c) 列を `bytes` を比べて小さいほうを取る。`table()` は新しい道を使い、CSV の道は残す。10 万点 × 7 列で時間を比べる。

## 決めたこと

- **(c) を取った**（親の目安どおり）。新しい依存が 0 で、Rust 側は py crate の中だけ（約 30 行）。(a) は crate `numpy` と Python の numpy（今の環境に無い）が要る。(b) は `arrow` crate（S039 で依存が約 25 増えると見積もった）と `pyarrow` が要り、Python の中の受け渡しにはファイル形式が要らない。
- API は wasm と同じ名前の `Workspace.simulate_columns`。`simulate` と同じ dict に `columns`（名前 → `pl.Series`、`time` が先頭）を足し、`csv` は `None`（`no_csv = true`）。`_native` は `(結果の JSON, 名前, bytes の列)` の組を返す。
- facade・protocol に列の関数を足さず、py crate が `simulate_with` の `run.trajectory` から作った（別の WP が同時に facade を変えているため）。
- polars へは `pl.Series(n, memoryview(c).cast("d"), pl.Float64)`。`bin.reinterpret` で Array にして `reshape` する案は 1 列 1.5〜5 ms と速いが読みにくい。`memoryview` は 1 列 4〜15 ms（ばらつきは WSL）で、10 万点 × 7 列でも呼び出し全体が 80 ms に収まるので読みやすいほうを取った。
- `memoryview` の `"d"` は native-endian。対象の wheel（x86_64・aarch64）はどれも little-endian なので shortcut の注記だけにした。
- marimo の `sim_app.py` は列の道に変えた。`SimulationPlot`（S078）は `table()` 経由なのでそのまま両方を受ける。
