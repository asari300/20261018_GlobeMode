## 依頼

S051 の持ち越し。ブラウザ UI の実行結果が CSV（`simulate` → `parseCsv`）なので、`Backend` に列ごとの道（`simulate_columns`）を足し、`Plot` がそれを使うようにする。

## 決めたこと

- `Columns`（`plot/csv.ts`）に `points` を足し、`data` を `ArrayLike<number | null>[]` にして、`parseCsv` の結果と wasm の `Float64Array` を同じ型で扱う。
- `TauriBackend` は sidecar に列の道が無いので、`simulate` の CSV を `parseCsv` して同じ形にする。`simulate` は残した。
- `App.svelte` の状態は `$state.raw`（`$state` だと配列を丸ごと Proxy にする）。
- 確認は `.plot` の `data-typed`（先頭の列が `Float64Array` か）。`data-parse-ms` は消した。
- NaN / Inf は `gapNonFinite`（csv.ts）で、非有限が 1 つでもある列だけ null の配列にする（有限だけの列は Float64Array のまま）。WorkerBackend が通す。試験は `tests/test_columns.mjs`（test_ui.py が呼ぶ）。
- wasm（`lib.rs`）と Rust は変えていない。wasm:build は回さず、同じ main 付近（14:47）で作られた共有 target の `wasm-pkg` を worktree の隣にコピーして使った（`simulate_columns` が含まれることを確認）。
