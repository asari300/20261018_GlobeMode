## 依頼

計画書の WP-I「v0.1 のリリース工程」を最小で実装する。`globe` の CLI を 3 ターゲットで配るワークフロー、CHANGELOG、Cargo の metadata、README の Install。余計な機能は足さない。

## 決めたこと

- **cargo-dist は使わない**: 3 ターゲット・1 バイナリは matrix で足りる。依存と設定を増やさず、`/add-dependency` の手順も要らない。
- **aarch64 はネイティブランナー（`ubuntu-24.04-arm`）**: public リポジトリで無料。クロスコンパイルの linker を避ける。Windows は ci.yml の `rust-windows` と同じく rustup を直接使い、Linux は mise-action。
- **Release の付け方**: タグ `v*` の push のときだけ `softprops/action-gh-release@v2`。`contents: write` は `release` ジョブだけ。`-` を含むタグは prerelease。手動（`workflow_dispatch`）は dry-run で artifact だけ。
- **`--features sundials` は付けない**: cmake と C コンパイラが要る。README に配布物へ入らないと書いた。
- **metadata は CLI だけ継承**: 他の crate は自前の description を持ち、publish しないので揃えない。`publish = false` と version は変えない。
- ユーザーと決めたこと: 範囲（最小、cargo-dist なし）は依頼どおり。それ以外は既定のまま。
