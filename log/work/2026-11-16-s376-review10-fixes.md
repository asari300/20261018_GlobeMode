## 決めたこと

- **7 件とも再現して直した（見送り 0、誤りの指摘 0）**。再現は `target-shared/review10/repro/`。#155・#156 は直す前の `flatprobe`（`p1`〜`p6` の値が issue のとおり。omc の値と照らした）、ほかは試験が直す前に落ちること（6 本とも 1 回の実行で全部落ちた）で確かめた。#158 の連鎖の試験は、直す前は約 25 秒かかって落ちる。
- **#156 は issue の案の「最小」でなく、`heir` を通す形にした**。呼び出しを通した package を関数の `Frame` の `heir` に入れる（案の 1 つ目）。`call_target`（新）が名前から決める: `cenv` に先頭のある `P.f` は差し替え先、`P5.f` のような静的な名前は名前の前半が指す package（`via_class`）、単純な名前は呼び出しの文脈（`PKG` なら評価中の package、それ以外は `ctx.heir`）。`fn_memo` の鍵の `heir` はそのまま効く。**issue に無い同じ根の誤りが 1 つあった**: 関数を通さない `Real a[P5.n]` も、`pkg_binding` に `heir` が渡らず 1 になっていた（5 のはず）。`via_class`（参照の名前の前半を型として解決し、宣言した package を受け継ぐなら）を `pkg_binding` に渡して一緒に直した。
- **#155 は「差し替え先を引く」まで直した**（issue は「まず断るだけで十分」）。`redeclare function f = f3` は `redeclaration` が `Ok(None)` で捨てていたので、短い形の関数の差し替えを `cenv` に入れ（`Redecl::Class`。引けない・`(…)` の修飾つきは今までどおり捨てる／断る）、`call_target` が引く。`P.f` は `member_class` で差し替え先を引くので、`P3` の `redeclare function f` の本体が走る（omc の値と一致）。`partial` の関数と、出力が代入されないまま終わる関数（`Slot.set`）は評価しない（以前は 0 を返した）。**`(…)` の修飾つきの関数の差し替えは断る**: `extra` を評価器が見ないので、見ないまま走らせると黙って違う値になる。
- **#154 は鍵に中身の hash を入れた**（issue の「中身を鍵にするほうがよい」）。`Rc::as_ptr` は S374 で捨てた理由（解放後に別のものが同じアドレスを取る）と同じなので使わない。`cenv` の（名前、クラス）の組を hash する `cenv_hash`。`(…)` の修飾つきの差し替えが 1 つでもあれば鍵にしない（`None`）。
- **#153 は最上位の失敗だけ覚える**（issue の「最上位で予算内に失敗したものだけ覚える」）。入れ子の失敗は呼び出しの深さに、予算切れのあとの失敗は残りの予算に依る。最上位は深さ 0 から数えるので、深さの上限に当たる失敗も決まっている。評価中の `pkg_env` の仮の空に依る失敗は、`pkg_env` を作っている間（`collect`）に関数を評価する道が無いので、外していない。
- **#158 は `eval` の束縛の式の成功した値を覚える**（issue の案の 1 つ目）。鍵は `Rc<Ctx>` の同一性でなく**文脈の中身の hash**（`pfx`・系統・`for` の値・`heir`・差し替えの組）と式の場所。理由: パッケージの定数の文脈は `pkg_const` が評価のたびに作り直し（同一性は毎回違う）、`Rc` の解放後に別の文脈が同じアドレスを取りうる（S374 で `cenv` の鍵に使わなかった理由）。`cardinality` を決める段階の前後で空にする。**関数の中の tick は `fx` から `eval` に任せるときに 1 回**（`ev`。リテラルは数えない）。覚えた値があっても 1 回ごとの 1 tick は残るので、ループの中で読む定数は反復の数に比例して予算を使う。
- **#157 は範囲の位置だけを全要素に広げた**（issue の案どおり。`range_vars`）。範囲が複数なら直積、要素が無くなるまで進める。
- **#159 は else の枝にも `effects` を付けた**（issue の案どおり）。`tab.model` の手の更新は残す（view の無い state では `updateListener` が動かない）。
- **コミットは issue の組ごと**（flat の 5 件は `fneval.rs` の `run_fn`・`call_target` と `flatten.rs` の `eval` が絡むので 1 コミットに `Fixes #153〜#156・#158` を 1 行ずつ。#157 と #159 は別のコミット）。S374 と同じ事情で、flat の 5 件を 1 件ずつに切ると途中がビルドできない（`run_fn` の署名と鍵の変更が #153・#154・#155・#156 に共通）。
