## 決めたこと

- **issue の番号は本文の指摘の番号で扱う。** 題が本文より 1 つずれている（#122 の題は #121 の本文、…。#121 と #126 の題は `x`）。依頼の中継では「#121・#126 は #122・#127 の重複」とされたが、`gh issue view` で本文を 11 件とも読むと、#121・#126 の本文は別の指摘（Complex の展開・方程式の数の上限）で、重複ではない。題だけを見ると、本文が #125（`isRoot`）と #131（`diff-frontend`）の 2 件は題に当たる issue が無い。重複とするコメントは付けず、親に報告した。
- #121: 上限は式の長さ 64 KiB（実部＋虚部）。MSL の `Complex` の式は短い（小さい式は今までどおり展開する試験を残した）。
- #124: issue は「項の `Vec` の作り直し」を指摘したが、直しても debug の n = 3000 で 10.2 s → 9.6 s とほとんど変わらなかった（マシンの負荷でぶれる）。残りは `children().any(Comprehension)` が要素ごとに全項を走査していたためで、同じ表に載せた（n = 3000 で 0.26 s）。
- #125: `members` を二分探索でなく、**節点 → 優先度の表を成分の節点の側から引く**形にした（成分の大きさ O(M)。多数の成分で O(C×P) になるのも避ける）。
- #126: 上限は `MAX_VARS` の 5 倍の 100 万本。置き場所は `F::equation` の入口（`for_eq`・`section` の両方が通る）。`connect` の本数（`lv.conns`）も足す。試験は `cfg(test)` で 1 万本に下げた単体試験（debug で 1 本 50 µs。本物の上限で試すと 52 s）。
- #128: issue の案のうち「跳びの前後 1 点を外す」を採った（`[min, max]` との距離は、なめらかな信号でも刻みの分だけ差が隠れる）。ただし「同じ時刻の行がある点」を一律に外すと、本物の食い違い（`δt` を超えるずれ）まで消えるので、**両方の時系列にイベントがあり、同じ瞬間でなく δt 以内**のときだけ外す。最初は「時刻が完全に一致する行」でイベントを探したが、`Ball` の実機で効かなかった（Rumoca は同じイベントの行を誤差だけ違う時刻で書く: 1.7519116998239728・…772・…816）ので、`SAME_INSTANT` 以内の隣り合う行をイベントにした。実機の確認で 7.659e4 → 2.562e-4。`deviations` に `TubeOptions` を足した（呼び出しは `globe-mode` の 1 か所）。
- #129: `check_out_dir` と `check_writable_file` が使う `resolve` を直した。`..` は字面で畳む（存在しない部品の後ろの `..`）。
- #130: `dims_product` を作った（`by_dims` は見積もれなければ `None`、`equalityConstraint` の戻り値の大きさは 0）。
- #131: `Elems = BTreeMap<名前, (個数, 落とした添字の数)>`。Rumoca が展開しない（深さ 0）ときは個数を無視する（S332 の措置は保つ）。部分的な展開（深さが違う）も個数を無視する。
