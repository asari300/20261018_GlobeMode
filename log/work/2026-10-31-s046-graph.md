## 依頼

計画書の WP-E を最小の形で実施する。wasm に `graph(model, depth)` を足して Worker・Backend に通し、`Graph.svelte`（sigma.js + graphology + ForceAtlas2）で描く。App.svelte への組み込みは S042 と競合するので親がやる。実装は Sonnet のサブエージェント 1 人。

## 決めたこと

- wasm の `graph` は S041 の `check` と同じ形（facade の `graph` → `to_graphology()` の JSON 文字列。`GraphError` は例外の文字列）。
- 型は `GraphJson` を手書き。ForceAtlas2 は円に置いて 100 反復、同期（`inferSettings` に任せる）。worker の layout は入れない。
- sigma 4.0.4 は 3 までと API が違う（設定は `settings` の下、WebGL2）。`settings.hideEdgesOnMove` と `hideLabelsOnMove` を有効にした。最初に `new Sigma(g, host, { hideEdgesOnMove })` と書いたが、svelte-check が型エラーにして気づいた（`settings` の下に直した）。
- 試験の入口は `graph-test.html` + `src/graph-test.ts`（vite の複数入口）。Graph を単体で mount し、本物の Worker のバックエンドと合成グラフのバックエンドの両方で回す。`App.svelte`・`mise.toml` は触らない。
- **wasm の `graph` は `set_file` の文書のモデルだけ引ける。** ライブラリ（`new Workspace(libraryJson)`）として読んだモデルは索引に無く、「索引に無い」と断る（S039 の Python と同じ制約）。このため MSL の `Electrical.Analog.Examples` での 5k ノードの測定はやらず、合成グラフで測った。
