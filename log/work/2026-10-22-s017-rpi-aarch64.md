## 依頼

「ここまでの作業を振り返り、RPi 環境で作業を再開して。サブエージェントは Opus-effort-medium で」。roadmap の「S017 の最初にやること」（2026-10-22 のユーザーの指示）の 3 つ:

1. `cargo xtask fetch-rumoca` を aarch64 に対応させる
2. RPi の環境をそろえる（mise・uv・MSL・`mise run check`）
3. `msl:funnel` のメモリ（x86_64 で最大 RSS 7.2 GiB）を RPi で回せるか確かめる

前置きとして `~/.claude/settings.json` の先頭の不正な 1 バイト（0x7F）を取り除いた（`/model`・`/effort` が保存できなかった原因。リポジトリの外）。

## 機械

Raspberry Pi（aarch64、Linux 6.12.109+rpt-rpi-2712、4 コア、RAM 7.9 GiB、swap 512 MiB、glibc 2.36（Debian 12）、ディスクの空き 66 GB）。S001〜S016 は x86_64 の機械だった。

## 決めたこと

- **作業ツリー**（ユーザーと決めた）: orca が作った worktree（ブランチ `asari300/acornworm`）ではなく、規約どおり main から `feature/s017-rpi-aarch64` を切って `.git-worktree/s017-rpi-aarch64` で作業する。finish-session の手順をそのまま使えるため。
- **mise のツール**（ユーザーと決めた）: 全部入れる。`mise install --locked` で rust stable（1.99.1）・cargo-deny 0.20.2・wasm-bindgen 0.2.129・zig 0.17.0・julia 1.13.2・gleam 1.19.2・erlang 27.3.4.19・uv 0.13.1 は入った。**elixir 1.18.3-otp-27 だけ失敗**: `mise.lock` の erlang の linux-arm64 は hex.pm の ubuntu-26.04 向けビルドで、`GLIBC_2.38`（libm は 2.43）を要求し、RPi の glibc 2.36 では beam.smp が動かない。このセッションでは `MISE_DISABLE_TOOLS=elixir` で外して進めた（既定のまま）。対処（erlang を kerl でソースビルドするか、apt の erlang を使うか）は持ち越し。
- **メモリ**（ユーザーと決めた）: `msl:funnel` の最大 RSS 7.1 GiB（x86_64）に対し、RPi は RAM 7.9 GiB のうちデスクトップ（orca-ide・chromium・ghostty）で約 2.7 GiB を使っていて、swap は dphys-swapfile の 512 MB だった。選択肢は「先に実測して足りなければ swap」「今すぐ swap を 8 GB」「分割実行の道を xtask に足す」「RPi では全体を回さない」。ユーザーは **今すぐ swap を 8 GB** を選んだ。`/etc/dphys-swapfile` の `CONF_SWAPSIZE` と `CONF_MAXSWAP` を 8192 にして `/var/swap` を作り直した（元の設定は `/etc/dphys-swapfile.bak-s017`。再起動後も残る）。決定は ADR-0019 に書く。
- **`fetch-rumoca` の aarch64**（既定のまま）: `RUMOCA_ASSET: Option<(ファイル名, sha256)>` を `cfg!(target_arch)` で選ぶ const にし、URL は `RUMOCA_VERSION` と組み立てる。`msl-compare` の `--rumoca` の既定も `RUMOCA_DEFAULT_PATH` で同じ名前にする。対応していない機械（Windows の CI）では `None` で、ビルドは通し実行時に断る。

## やったこと

- `src/Rust/xtask/src/main.rs`: 上の `RUMOCA_ASSET` / `RUMOCA_DEFAULT_PATH`。`fetch_rumoca` は `let Some((file, sha256)) = RUMOCA_ASSET else { Err }`。
- `doc/roadmap.md`: `fetch-rumoca` の説明を「Linux の x86_64 と aarch64」に。

## 残したこと

- elixir: erlang の arm64 ビルド（hex.pm の ubuntu-26.04 向け）が glibc 2.38 を要求する。kerl でソースビルド（`mise.toml` の `compile = true`、apt の依存が要る）か apt の erlang か。Elixir のラッパを触るセッションで決める。それまで mise は `MISE_DISABLE_TOOLS=elixir` で使う（CLAUDE.md に書いた）。
- `msl:sim` は実行系を変えていないので回していない。参照結果（約 1 GB）も未取得。前回の `target/msl-sim.json` は Git に無いので、次に回すときは差が出ない。
- RPi は遅い: `mise run check`（debug ビルド込み）約 63 分、`msl:compare`（release ビルド込み）約 18 分、`msl:funnel` 約 25 分。同じ worktree で cargo を 2 つ同時に走らせない（ロック）。
- `~/.claude/settings.json` の先頭に 0x7F が入った原因は分かっていない（編集時の誤打の見込み）。`.bak` を残した。
- RPi の作業は orca の worktree（`asari300/acornworm`）ではなく、規約の `.git-worktree/` で続ける。
