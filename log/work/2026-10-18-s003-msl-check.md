## 決めたこと

- **片付けの手順**（`feature/ops-worktree-cleanup`、main にマージ済み `6573dc8`）:
  - finish-session の「7」に置いた。条件は次のとおり。
    - CI が成功している
    - 最新から数えて 2 つ以上前
    - 未コミットの変更が無い
    - main に取り込み済み
  - `git branch -d`（取り込み済みだけを消す）を使う。
  - CI の結果の確認を `gh` に置き換えた（ユーザーが認証した）。
  - 同じ内容をメモリにも書いた。
  - push は S003 の締めでまとめて行う（finish-session の手順どおり）。
- **MSL の取得**: Rust の xtask に置いた。
  - ダウンロードは `curl` を呼ぶ。Rust の HTTP の crate を足さずに済み、Windows にも `curl` があるため。
  - sha256 は定数で固定した。
- **zip の版**: cargo deny が zip 2 系の脆弱性 3 件を検出したので、9 系にした。xtask は該当する API（`extract()`）を使わないが、脆弱な版には依存しない。
- **アダプタのコンパイル**: `compile_model_strict()` に替えた。
  - `compile_model_phases()` と `model_names()` は、MSL の解決時の警告（WR006・WR001）まで Err として返した。
  - Rumoca の CLI が使っている経路に合わせた。
- **照合の相手**: Rumoca の CLI（別プロセス）にした。
  - GlobeMode も同じ Rumoca を使っているが、アダプタ（ライブラリの読み込み、結果の対応づけ、数え方）が CLI と同じ答えを出すかを確かめる意味がある。
  - 実際に、数え方の違い（スカラー / 配列ごと / 操作）が見つかった。
- **数え方**: 突き合わせは DAE の変数単位（配列は 1 個）にした。
  - 方程式数は、CLI の `-v` の `[rumoca] Continuous equations` を使う（DAE の方程式数）。
  - `dae-json` の operations は「操作」の数なので使わない。
  - `BalanceCount`（スカラー）は S5 の釣り合い用に残した。
- **例題 20 本の選び方**:
  - Electrical・Mechanics・Thermal・Blocks・Machines・MultiBody に、Fluid（stream）と StateGraph を加え、分野をまたいで選んだ。
  - 失敗しそうなものも入れ、「両方とも同じように失敗する」ことも一致に数える。
- **`globe-mode-testkit`** は作らず、突き合わせは xtask に置いた。今は CLI のタスク 1 つで足りるため。
- CI の `msl` ジョブは、全体を検査するときだけ動かす。重いため（MSL と Rumoca の CLI の取得、20 本の検査、xtask のリリースビルド）。
