## 依頼

roadmap の表「機能の穴（P4）結果の入出力」の MAT v4 の読み込み。`read_mat4` を xtask から sim へ移し、CLI `globe results` と Python `read_results` を足す。UI は触らない。

## 決めたこと

- `read_mat4` は着手時点で既に `globe-mode-sim::mat` にあり、xtask に写しは無かった（S203 で omc の実物の fixture `tests/data/omc_decay_res.mat` と `tests/omc_mat.rs` も sim にある）。移す作業は無し。
- 拡張子で読み分ける `mat::read_results` を足し、CLI と Python が同じ関数を呼ぶ。
- `write_mat4` の本体を `write_mat4_parts(trajectory, parameters, span, out)` に出した。`SimRun` を偽造しない。
- CLI の書き先は `check_writable_file(出力, [入力], [])`。入力と同じファイルは読む前に断る（2）。
- Python は `simulate_columns` と同じ形の dict に `parameters` を足す。誤りは既存の `ResultError`。
