## 依頼

S381。`release.yml` の dry run で、`build (aarch64-unknown-linux-gnu)` の wheel の pytest `test_export_fmu_p5b` が「`--target aarch64-linux: FMI 2.0 に置き場の名前が無い`」で落ちる（run 43868055458 など。11-08 以降ずっと）。原因は `globe-mode-fmi/src/export.rs` の `platform` が aarch64 Linux の FMI 2.0 を断ること。ユーザーの決定: **断るのを正しい動きとし、試験のほうを直す。Rust の動作は変えない。** 試験を、aarch64 Linux のホストでは FMI 2.0 を断ること（エラーの内容）を確かめ、それ以外では今までどおり FMU を作るように、最小の変更で直す。同じ前提の試験が他にもあれば `git grep` で洗い出す。必要なら既知の限界に一行。

## 決めたこと

- ユーザーと決めたこと: 断るのが正しい動き。試験を直し、Rust は変えない。
- 試験は host で分ける: `sys.platform == "linux" and platform.machine() == "aarch64"` なら `ExportError`（`match="FMI 2.0 に置き場の名前が無い"`）、そうでなければ今までの確認。p5a の旗との組み合わせ（`build=True`）と不正な `runtime`（`"p6"`）は host に依らず確かめる。
- `runtime_lib` が無い場合の試験は else 側に置いた。`export_fmu_p5b` は `platform` を `runtime_lib` の存在の検査より前に引くので、aarch64 Linux では `runtime_lib` の文面に届かない（`ExportError` の文面が `FMI 2.0 に置き場の名前が無い` になる）。
- 既知の限界は CHANGELOG に一行足した。`doc/features.md` の FMU の行は、すでに長く、S381 の事実（試験の直し）は機能の説明ではないので触らない。
- FMI 2.0 の規格の `binaries/` の名前は `linux64`・`win64`・`darwin64`（と 32 bit 版）。Reference-FMUs の FMU は `aarch64-linux` で置いている（[doc/research/fmi-2026-11-01.md](../../doc/research/fmi-2026-11-01.md)）が、規格の名前ではない。aarch64 Linux の FMI 2.0 を作れるようにするかは決めていない（持ち越し）。
