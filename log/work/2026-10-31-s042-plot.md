## 依頼

S041 の UI に「実行」とプロットを足す（計画書の WP-D の最小の形）。「実行」ボタンで `Backend.simulate({ model })` を呼び、結果の CSV を列に分けて uPlot で時系列に描く。信号はチェックボックスで選ぶ（既定は最初の数本）。ズームは uPlot の既定。2 軸・凝った凡例・MAT v4 は入れない。実装は Sonnet のサブエージェント 1 人、締めは Fable。

## 決めたこと

- **uPlot 1.6.32**（MIT、依存なし）を足した。`pnpm licenses list` は 58 パッケージ（MIT 50 / Apache-2.0 4 / MPL-2.0 2 / ISC 1 / BSD-3-Clause 1）、GPL・LGPL・AGPL・NC は 0。配布物に入る prod は CodeMirror の 12 個と uPlot で全部 MIT。ADR は書かない（描画ライブラリの置き換えは容易で、設計の選択肢を減らさない）。選ばなかった候補は計画書の記載に従い比べていない（Plotly・Chart.js は 10 万点 × 数系列に重い、という一般論だけで、実測はしていない【未確認】）。
- **CSV の解析は UI 側の `csv.ts`**。wasm に列ごとの API を足すと Rust と protocol に触るので、今回は足さない。`write_csv` の形（見出しは二重引用符で囲み、中の `"` は `""`。値は数か `NaN` / `Inf` / `-Inf`）だけ読む。有限でない値は `null` にして線を切る。
- **信号の選択は uPlot の `setSeries(i, { show })`**。チェックボックスは自前の最小の表で、uPlot の凡例（クリックで切り替えも効く）はそのまま残した。
- **`App.svelte` の `check` と `simulate` は `run()` で共通化**（`setFile` → 本体 → busy の管理）。`refused` は赤字の `role="alert"`、診断は既存の診断パネル。
- **10 万点の試験は実際の経路で回す**: モデルに `annotation(experiment(StopTime = 1000, Interval = 0.01))` を書き、4 状態（`der(a) = -a` など）を実行して 100,001 点 × 4 列の CSV を得る。Plot に合成データを渡すための試験専用のコードを本番に足さずに済む。
- ヘッドレス Chromium の frame の件は S041 と同じ回避（`click(force=True)`）。

## 残したこと

- `parseCsv` は引用符つきの値の欄を読まない（`write_csv` の出力だけを前提）。他のツールの CSV を読むときは Rust の `parse_csv` に合わせる。
