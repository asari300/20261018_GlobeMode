## 依頼

コシミュレーションの spec（`CosimSpec`）から `.ssp` を書き出し、S253・S263 の読み取りで読み戻して同じ結果になる往復の最小版。

## 決めたこと

- 口は `globe fmu ssp-export <spec.json> -o system.ssp`。実装は `globe-mode-fmi-import` の `write_ssp`（facade にも出す）。依存は増やさない。
- `step`・`algorithm` は SSD の `ssc:Annotations` に独自の `Annotation`（型 `io.github.asari300.globe-mode.cosim`）で入れ、`parse_ssd` が拾う。XSD（modelica/ssp-standard の `SystemStructureCommon.xsd`）で `Annotation` の `type` は必須・自分たちのドメインの逆順・中身は任意と確認した。
- 刻みの優先順位は `--step` > Annotation > (終了 - 開始) / 100。
- `start` は `.ssv` を作らずインラインにした（小さい方）。
- 結線は Float64 だけ書く。読み取りが Real 以外のコネクタを断るので、Int32・Boolean の結線は書き出しの側で断る。
- `Error::Ssp` の表示を「SSP を読めない」から「SSP:」に変えた（書き出しの誤りにも使うため）。

## やったこと

- `globe-mode-fmi/src/ssp.rs`（Annotation の読み取り）、`globe-mode-fmi-import/src/ssp.rs`（`write_ssp`・`Ssp::open` の刻みと algorithm・試験）、`cosim.rs`（`valid_fmu_name` を取り出した）、`globe-mode/src/{lib,fmu_import}.rs`、`globe-mode-cli/src/fmu.rs`（`ssp-export`）と `tests/fmu_cosim.rs`。
- doc: ADR-0026 の (u)、roadmap・features の SSP の行、セッション文書と索引。

## 検証

- `cargo test -p globe-mode-fmi -p globe-mode-fmi-import -p globe-mode-cli`（`GLOBE_REQUIRE_REFERENCE_FMUS=1`）: 失敗 0。fmi-import の lib は 13 本、`fmu_cosim` は 10 本（新しい 1 本を含む）。clippy（`-D warnings`、4 crate、全ターゲット）警告 0。
- 往復: Jacobi と Gauss–Seidel + `start`（k = 2）で、`globe fmu cosim x.ssp`（`--step` なし）の CSV が JSON の CSV とバイト一致。偽の FMU（変数名に `<`・`&`・`"`）の往復も一致。

## 残したこと

- Int32・Boolean のコネクタ（読み取りと書き出し）、`.ssv`・`.ssm` の書き出し、単位、入れ子の System、FMU の重複排除、`.ssp` から spec.json への逆変換。
