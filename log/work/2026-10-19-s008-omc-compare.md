## 決めたこと

- **S008 の範囲は omc との照合だけ**（roadmap の S008 の候補 1）。候補 2〜8 は触らない。ユーザーの依頼は「omc を導入したので確認したのち作業を進めて」で、S007 で後回しにした項目を最初に再開する約束だった。
- **omc は `cargo xtask omc-compare` が別プロセスで呼ぶ。入力は `msl-funnel --json` の結果**（[ADR-0010](../../doc/adr/0010-omc-comparison.md)）。ファネルに omc を組み込む案は、ファネルが omc の有無に依存してしまうので採らなかった。omc が無い環境では `omc-compare` だけが動かない。
- **omc に読ませる MSL は `data/msl` の素の 4.1.0。** omc 同梱の `Modelica 4.1.0+maint.om` は OpenModelica 向けの修正が入っていて、globe check が読むものと中身が違う。素の 4.1.0 でも `setModelicaPath` + `loadModel(Modelica, {"4.1.0"})` で読めた（ModelicaServices が patch されていないという警告は出る）。
- **S5 の一致率は「合う / 合わない」の判定の一致で測る。** omc の `checkModel` は partial や数が合わないモデルでも「completed successfully」を返し、数だけが違うので、数から判定を作る。globe 側に判定が無いもの（GM-U、S4 以前で止まったもの）は分母に入れない。方程式数と未知数（スカラーの総数）が同じ数かは副次的な指標にし、そのために `msl-funnel` の JSON の `counts` に `unknowns` を足した（最初の JSON には配列を 1 個と数えた状態・代数・出力しか無く、omc の変数数と比べられなかった）。
- **S6 は omc の `translateModel` の失敗の文言で、S8 は「over specified」の警告だけで比べる。** omc は初期条件の不足を黙って start 値で埋め、`-d=initialization` でも警告を出さないので、不足は比べられない。S7（構造インデックス）は omc が数を出さないので比べない。
- **`checkModel` と `translateModel` は `.mos` の文として呼び、`print` は印だけに使う。** `print(String(translateModel(M)))` のように式の中で呼ぶと、失敗したときの `getErrorString()` が空になることを手元で確かめた（調査記録）。
- **`-d=initialization` を付けたまま回す**（過剰な初期方程式の本数が出る）。その代わり、反復変数の一覧が `true` / `false` の前に標準出力へ出るので、結果は区間の最後の行で読む（最初の全例題の実行で 52 本を「失敗」と読み違え、直した）。
- **報告の置き場は `doc/omc-compare.md`、タスクは `mise run msl:omc`。CI には入れない**（ランナーに omc が無い。`msl:funnel` と同じ扱い）。

## 残したこと

- **`AdvancedSolenoid` の真偽**（S6 の唯一の不一致）: globe は S6 を通して S7 でインデックス 2（方程式 175 本を微分）、omc は Pantelides の内部エラー。omc の `-d=bltdump` と globe の S6・S7 の詳細を見る。S009 の候補 1。
- **S8 の冗長な初期条件**（`NonCircularPipes`）: 数だけでは、与えられた初期条件の中の冗長さ（omc の「redundant」）を見られない。初期方程式の incidence を持つ S8 の精密化（S009 の候補 3）と同じ話。
- **omc が手前で止めるモデル**: `OpAmpCircuits.Der` など 5 本は、omc が「fixed なパラメータに値が無い」を Error にして止まる。globe は S8 の `GM-W8003`（警告）だが、S6 で止まると S8 に来ない。報告の順序を見直すかは S009 で決める。
- **数の差**: `Clocked` の 72 本などで omc の方程式数・変数数が globe より 2〜30 多い（両側に同じだけ）。omc が数えているもの（クロック変数など）の内訳は調べていない。判定には影響しない。
- **CI には入れない**: ランナーに omc が無い。`msl:funnel` と同じく手元で回す。
- 検証モデル `Invalid.*` を omc で検査する自動化はしていない（手で確かめて README に書いた）。
- `omc-compare` の報告には omc の文言をそのまま載せるので、絶対パスが入りうる（今回の報告は 0 件。JSON には入るが `target/` でコミットしない）。伏せ字にするなら次回。
- 候補 2〜8（閉包の切り替えの費用、S8 の精密化、when の区別、S9・S10、`Checker` のメモリ、上流報告、`class_index` の残り）は roadmap のまま。
