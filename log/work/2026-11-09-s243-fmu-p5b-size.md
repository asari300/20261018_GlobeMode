## 依頼

S238・S239 の持ち越し。P5b の FMU の大きさ: cdylib を小さく、`resources/lib` をクラス単位に。

## 決めたこと

- cdylib: `opt-level z`・fat LTO・cgu 1・`panic = abort`・strip を環境変数で与える（facade の `build_runtime`、`fmu-export.yml` の直接ビルドの step）。workspace の profile は変えない。利用者が同じ変数を決めていればそれを使う。
- `resources/lib`: `globe-mode-fmt::prune_classes`（字句の名前の一致、広めに残す）と `globe-mode-frontend::library_slice`（閉包を取り直す）。facade の `stage` が呼ぶ。
- 依存の整理はしない（大半は Rumoca の compile 段。`cargo-bloat` は無く `nm -S` の crate ごとの合計で見た）。

## 数字

- cdylib（strip 後）: 33.2 → 25.4（LTO + cgu 1）、s だけ 27.6、s + LTO + cgu 1 19.1、+ abort 17.1、z 15.1 MB。FMU 全体 12.9 → 6.3 MB。
- Accelerate の `resources/lib`: 294 → 90 ファイル、2.37 MB → 393 KB（zip 590 → 131 KB）。`globe fmu run` 1.07 → 0.29 s（同じ cdylib）、z の cdylib で 0.24 s。
- MSL の 20 本（FMPy、`--runtime p5b`、z の cdylib）: 16/20（落ちる 4 本は S237 と同じ）。

## 検証

- `mise run check` 通過（fmt・clippy・test・deny・`uv sync --locked`。`prune_classes` の単体試験 2 本、CLI の `p5b_runtime_ships_only_the_used_library_files` は 50〜150 ファイル・1 MB 未満を確かめる）。
- `check_docs.py`: 切れ 0 件。`render_slides.py`（S243 のデッキ）: 問題 0 件。
- CI: 後で書く。

## 残したこと

- cdylib の「数 MB」は Rumoca の compile 段が大半で届かない。`globe-mode-exec` の積分器の feature 分けは 1 MB 未満。
- 残るファイル内の `annotation(Icon…)` の削除、配布物への cdylib の同梱、cross。
