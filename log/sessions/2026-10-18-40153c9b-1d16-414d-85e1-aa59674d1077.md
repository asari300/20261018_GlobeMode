## B. WSL2 から Windows のサービスにつなぐ

公式 docs: ✔ https://learn.microsoft.com/en-us/windows/wsl/networking と ✔ https://learn.microsoft.com/en-us/windows/wsl/wsl-config

**NAT モード（既定）**
- ホストの IP は `ip route show | grep -i default | awk '{ print $3}'` で取る。
- LAN からの接続として扱われるので、サーバは `0.0.0.0` にバインドする必要がある（LM Studio なら `--bind 0.0.0.0` か Serve on Local Network）。
- **注意:** dnsTunneling は既定で有効で、そのとき `/etc/resolv.conf` の nameserver は `10.255.255.254` になる。この場合 resolv.conf ではホストの IP を取れないので、`ip route` を使う ✔
- 受信を許すファイアウォール規則の例。標準の cmdlet の書式で、MS docs から取った例ではない【未確認】。

  ```powershell
  New-NetFirewallRule -DisplayName "LM Studio 1234" -Direction Inbound -Protocol TCP -LocalPort 1234 -Action Allow -Profile Private
  ```

**mirrored モード**（Windows 11 22H2 以降）
- `%UserProfile%\.wslconfig` の `[wsl2]` に `networkingMode=mirrored` と書くと、`127.0.0.1` で Windows 側のサーバに届く（`::1` は使えない）。
- `hostAddressLoopback=true` は `[experimental]` に書く。127.0.0.1 以外のホストの IPv4 アドレスでもつながるようになる。
- Hyper-V ファイアウォールを許可するには、管理者の PowerShell で次を実行する。

  ```powershell
  Set-NetFirewallHyperVVMSetting -Name '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -DefaultInboundAction Allow
  ```

  またはポートを絞って `New-NetFirewallHyperVRule ... -LocalPorts 1234` を使う。
- 設定を変えたら `wsl --shutdown` で再起動する。MS は .wslconfig を手で編集するより、スタートメニューの「WSL Settings」アプリを使うよう勧めている ✔
