## 5. XML パーサ

| crate | 版 | ライセンス | 依存（normal） | 性質 |
| --- | --- | --- | --- | --- |
| `roxmltree` | 0.21.2（2026-10-24） | MIT OR Apache-2.0 | `memchr` のみ（1 つ） | 読み取り専用の DOM。MSRV 1.60（crates.io の rust_version 欄） |
| `quick-xml` | 0.42.0（2026-08-22） | MIT | `memchr` のみ（serde は任意） | ストリーム型。DOM は無い。MSRV 1.86 |
| `serde-xml-rs` | 0.8.2（2025-11-14） | MIT | `log`、`serde`、`thiserror`、`xml`（xml-rs） | serde 経由。属性とテキストの扱いに癖がある（推測。使っていない） |
| `hard-xml` | 1.43.0 | MIT | `xmlparser` など | `fmi-schema` の下の層。マクロで型に写す |

- 選んだのは `roxmltree`。理由: 依存が `memchr` だけで、`memchr` は Cargo.lock に既にある。modelDescription.xml は数十 KB〜数 MB で、DOM を丸ごと持って構わない。属性と子要素の走査が直接書ける。wasm32 で通る（S057 で `cargo check --target wasm32-unknown-unknown -p globe-mode-fmi` が通った）。fmusim と fmi-rs も `roxmltree` を使っている（上の fmusim の Cargo.toml）。
- 規模の比較（推測）: `fmi-schema` を使うと推移的依存が 42 パッケージ増える。`roxmltree` は 1 つ（`memchr` は Cargo.lock に既にある）。実際に S057 で Cargo.lock に増えたのは `roxmltree` と `globe-mode-fmi` の 2 行。

## 6. 自前で書く場合の設計

### 6.1 層

```text
modelDescription.xml ──▶ globe-mode-fmi::parse_model_description ──▶ ModelDescription（変数表、ME / CS / SE の有無）   … S057 で済み。wasm でも通る
binaries/<platform>/<id>.{so,dll,dylib} ──▶ libloading ──▶ fmi2*/fmi3* の C 関数                                  … P5。Desktop・CLI だけ
ME: 導関数・イベント指標・状態を FMU から読み、積分は GlobeMode のソルバ（HybridSystem の driver）            … P5
CS: FMU の内部の積分器に do_step する。マスターが刻みを決める                                                     … P5
```

- 共有ライブラリを読むのは Desktop と CLI だけ。ブラウザ（wasm32-unknown-unknown）は `dlopen` できないので、`modelDescription.xml` の閲覧までに限る（architecture.md §3.4 の「ブラウザでの制約」と同じ）。Android は libloading が使えるが、FMU の Android 向けバイナリは Reference-FMUs に無い（platform 名の表に Android が無い）。
- ME は GlobeMode のソルバで積分する。FMU の `fmi2GetDerivatives` / `fmi3GetContinuousStateDerivatives` を RHS として、`HybridSystem` を実装する（architecture.md §3.3 の「Modelica のモデルと FMI-ME の FMU は同じ driver を使う」目標）。CS は FMU 側の積分器に任せ、マスターが `do_step` する。
- 実装すべき C 関数は多くない。ME の 2.0 では `Instantiate`、`SetupExperiment`、`EnterInitializationMode`、`ExitInitializationMode`、`SetTime`、`SetContinuousStates`、`GetContinuousStates`、`GetDerivatives`、`GetEventIndicators`、`CompletedIntegratorStep`、`NewDiscreteStates`、`EnterEventMode`、`EnterContinuousTimeMode`、`Get*` / `Set*`（型ごと）、`Terminate`、`FreeInstance` あたり（推測: 仕様の関数名の記憶に基づく。P5 の最初にヘッダと突き合わせる【未確認】）。

### 6.2 Rumoca の FMI ME 風の host との関係

- Rumoca の `rumoca_solver::fmi_me`（`MeModelArtifact`・`MeSimulationSession`・`MeIntegratorBackend`）は、**Modelica のモデルを FMI ME に似た形の host で回すもの**であって、外部の FMU を読む道ではない（[rumoca.md](rumoca.md)、[ADR-0014](../adr/0014-session-route-wasm.md)）。GlobeMode はこの host に数値積分のプラグインを差している。
- よって FMU の Import（`globe-mode-fmi`）は Rumoca とは別の道になる。Rumoca の `finish_fmi_component`（Solve IR を FMI の部品にする）は Export（P5a）の側で効く可能性がある【未確認】。
- 自前の `HybridSystem` の driver（architecture.md §3.3）は P5 で FMU の ME に使い、その上で Modelica のモデルも載せるかは、ADR-0013 が「P5 の前に決める」と持ち越している。この調査では決めない。

### 6.3 自前にするときの工数の見積り（推測）

- `modelDescription.xml` の読み取り: S057 の骨格が約 250 行（変数表まで）。単位・型の定義・start 値・依存関係（`ModelStructure`）・DefaultExperiment を足して 2〜3 倍。
- C ABI の型と関数のテーブル（2.0 と 3.0）: ヘッダを見ながら手書きして各 300〜500 行（推測）。bindgen は使わない（libclang が要る）。
