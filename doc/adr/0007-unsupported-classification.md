# ADR-0007 「コンパイラが未対応」（GM-U）を、コードの規則と既知の制約の一覧で振り分ける

- 状態: Accepted（2026-10-18、S005）

## 背景

- [ADR-0005](0005-lazy-query-db.md) と [architecture.md §3.2](../architecture.md#32-遅延評価とシミュレーション前のアサーション) は、「コンパイラが未対応」を GM-U コードとして「モデルの誤り」（GM-E）と分けると決めた。
  - 見分け方は決めていなかった。
- S004 で 3 つの案を比べた（[S004 の解説書](../sessions/S004-lazy-queries/解説書.md#gm-u-の振り分け検討のみs005-で決める)）。そのときは「B を既定にし、C を任意にする」案だった。

  | 案 | やり方 | 短所 |
  | --- | --- | --- |
  | A. コードで決める | Rumoca のエラーコードごとに、GM-U かどうかを決めておく | ED001（数が合わない）はモデルの誤りでも出るので、区別できない |
  | B. 既知の制約の一覧 | MSL の例題と Rumoca のコードの組を一覧にし、当たれば GM-U | MSL の外のモデルには効かない |
  | C. omc と照合 | Rumoca で失敗したときだけ omc（別プロセス）で検査し、omc が通れば GM-U | omc が要る。遅い |

- S005 で Rumoca v0.10.2（rev `276e82bd`）のエラーコードを読んだ（[research/rumoca.md](../research/rumoca.md#s005-で調べた-apiv0102)）。
  - コードの一覧表は無い。phase ごとの `errors.rs` などに散らばっている。
  - 名前とコメントから、**モデルに依らずに**「未対応の言語機能・実装の制限」と読めるもの（ED019 など）と、「コンパイラの内部の不変条件が崩れた」と読めるもの（ED008 など）がある。
  - ED001（数が合わない）・EF002（接続の型が合わない）・ER003（基底クラスが無い）は、モデルの誤りでも出る。
- MSL の例題は、正しいモデルとみなせる。MSL の全例題（566 本）を Rumoca で検査して止まったものは、原則として Rumoca の制約である。
- `omc` はこの環境に入っていない。C は S005 では試せない。

## 決定

- **A（コードの規則）と B（既知の制約の一覧）を併用する。C（omc との照合）は任意とし、S005 では行わない。**
- 規則は上から順に当てる（`src/Rust/mod/globe-mode-frontend/src/unsupported.rs`）。

  | 順 | 規則 | GM コード | Rumoca のコード |
  | --- | --- | --- | --- |
  | 1 | 未対応の言語機能・実装の制限（コードで決まる） | `GM-U0001` | ED009・ED013・ED018・ED019・ED020、EF004・EF020・EF031・EF033、EI030・EI035、ER073 |
  | 1 | コンパイラの内部エラー（コードで決まる） | `GM-U0002` | ED003・ED007・ED008・ED021、EF005・EF008・EF009・EF014・EF015・EF017・EF019・EF023・EF024・EF025・EF029、EI033・EI098・EI000、ER098、ES014 |
  | 2 | 既知の制約の一覧に、（モデル, コード）の組がある | `GM-U0003` | ED001・ET004・ED010・ER130 など、コードだけでは決まらないもの |
  | — | どれにも当たらない | GM-E のまま | — |

- **ED001・EF002・ER003 は、コードだけでは決めない。** 一覧に載っているときだけ GM-U にする。
- **一覧**は `src/Modelica/msl-known-unsupported.txt` に置く。
  - 1 行は `<モデルの完全修飾名> <Rumoca のコード> # 理由`。`#` で始まる行と空行は飛ばす。形の誤った行は読み飛ばす（panic しない）。
  - `globe-mode-frontend` が `include_str!` で埋め込む。実行時にファイルを探さない（wasm でも同じに動く）。
  - 中身は `cargo xtask msl-funnel` の報告の「既知の制約の一覧の原稿」から作る。理由を確かめて書いてから移す。
- 一覧が効くのは、そこに載っている MSL の例題だけ。MSL の外のモデルには、規則 1 だけが効く。
- **severity は Error のまま**にする。`--force` を付けなければ実行しない点は、モデルの誤りと同じ。
  - `Diagnostic::is_unsupported()`（コードが `GM-U` で始まる）で見分ける。
  - CLI は `unsupported[GM-U0001]` のように表示し、`error[GM-E…]` と分ける。
  - Rumoca のコードと理由は、診断の `notes` に残す。
- Rumoca の rev を上げたら（`xtask bump-rumoca`）、コードの表を見直す。一覧のうち、当たらなくなった行は消す。

## 結果

- **S005 で実装した**（2026-10-18）。
  - `globe-mode-core`: `codes::{UNSUPPORTED, COMPILER_BUG, KNOWN_LIMITATION}`（`GM-U0001` / `GM-U0002` / `GM-U0003`）と `Diagnostic::is_unsupported()`。
  - `globe-mode-frontend`: `unsupported::classify`。アダプタが GM-E を GM-U に付け替え、理由を `notes` に入れる。
  - CI の差分判定では、一覧を変えると frontend とその依存元を検査する（`.github/scripts/ci_plan.py` の `EXTRA_INPUTS`）。
- **一覧は 50 行**になった（MSL 4.1.0 の全例題を回した結果から作った）。

  | Rumoca のコード | 行 | 理由（要約） |
  | --- | ---: | --- |
  | ED001 | 41 | Rumoca v0.10.2 の数え方では方程式数と変数数が合わない（例: 誘導機の例題で差 -27） |
  | ET004 | 4 | 配列の次元が関数 `realFFTsamplePoints` の呼び出しで決まり、評価できない |
  | ED010 | 3 | 離散の方程式の形（Appendix B の解いた形）を受け付けない |
  | ER130 | 2 | 入れ子のクラスから定数でない変数への参照を、MLS §5.3.1 違反として拒む |

- **MSL の全例題 566 本で GM-U に振り分けたもの**（[msl-funnel.md](../sessions/S005-check-queries/msl-funnel.md)）:

  | | 最初の実行（S6 を直す前） | 最終の実行 |
  | --- | ---: | ---: |
  | GM-U0001（未対応） | 82 | 82 |
  | GM-U0002（内部エラー） | 52 | 52 |
  | GM-U0003（一覧） | 50 | 50 |
  | 合計 | 184 | 184 |

  - 多いコードは ED019（52 本）、ED001（41 本、すべて一覧）、ED008（28 本）、ED013（21 本）、EF023（17 本）だった（最初の実行）。
- C（omc との照合）は、omc を入れるかどうかをユーザーが決めてから行う。入れたら、GM-U0003 の一覧の行が本当に Rumoca の制約か（omc では通るか）を確かめる。
- 一覧が MSL の外のモデルに効かないことは、受け入れる。ユーザーのモデルで ED001 が出たら、モデルの誤り（GM-E5002）として報告する。
