検査の終わり・タブの切り替えで配置が動く

S360 は試験の押下を押し直して吸収した。利用者が押す直前にずれると別の場所を押す

タブ列の上端を 5 ms ごとに記録して、動かす原因を 3 つ見つけ、先に場所を確保した
原因

動かしていたもの（直す前）

場面動き原因
検査のあと+15 px（1280）・+59 px（390）「パラメータ」の details が、一覧が届いて初めて出る（ボタンが戻った約 200 ms 後）
初回の検査（740 px）+19.6 pxソルバの一覧が wasm から後で届き、選択欄が 48 → 83 px に伸びて同じ行が折り返す
タブの切り替え+40 px（約 2 ms）モデルの候補が前のタブのままで、select に長い選択肢が足される
直し

出し入れをやめ、先に場所を取る

  • details は検査の前から出す。1 行に固定（nowrap と省略記号、全文は title）
  • ソルバの選択欄は min-width: 7rem
  • モデルの候補はタブごとに持つ（Tab.models。離れるとき写し、戻るとき入れる）
  • 変更は SimSettings.svelte と App.svelte の十数行
試験

layout_shift: タブ列の上端が ±1 px 動かない

  • 幅 1280・740・390 px で、初回の検査・2 つのモデルのファイルのタブ切り替えと検査（2 周）
  • 直す前は 1280 px の初回の検査（15.2 px）で落ちる
  • 3 つの直しを 1 つずつ外すと、それぞれ別の段で落ちる（40.0・19.6・19.6 px）
残したこと

押した操作の結果は直さない

  • 実行の開始の p.run・終了の p.last は、押した結果が見える場所に出す設計のまま（終了時はタブのボタンが無効のうち）
  • 保存された設定が「複数」のとき、ソルバの一覧が届くまでチェックボックスの欄が空
  • CI のフォントでの値は【未確認】（ci.yml の ui で確かめる）
