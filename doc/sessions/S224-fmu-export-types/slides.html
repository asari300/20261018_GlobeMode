Export した FMU に Enumeration と String の型を書く

P5a の FMI 2.0 と P5b の 2.0・3.0。dependencies は情報源が無く持ち越し

Enumeration を持たないモデルの XML は1 バイトも変わらない
目的

これまで

  • Rumoca のテンプレートは Enumeration を <Integer> で描き、型の名前もリテラルも落ちていた。
  • P5b は Enumeration の変数を載せず、String のパラメータは Real の 0.0 になっていた（FMPy の validate が「名前が重複」で落ちる）。
  • DAE は Enumeration の型の名前もリテラルの名前も持たない。
決定と理由

決めたこと

項目決定
型の元flat の variable_type_names と enum_literal_ordinals。CompiledModel::enum_type_of
P5a 2.0<Integer> を <Enumeration declaredType> に、SimpleType を足す
P5a 3.0Int32 のまま。Rumoca の C が Int64 未対応で、書くと読めない
P5b2.0・3.0 とも型の定義を書き、Integer（3.0 は Int64）で読み書き、String は GetString
dependencies出力ごとの依存の情報が無い。持ち越し

検証

  • 手元で Rumoca の C を --build した 2.0・3.0 の FMU が、FMPy の validate を通り、ME・CS の x(1) が e⁻² と 9e-9 差。
  • P5b は C ABI の試験と FMPy の validate・ME（2.0・3.0）。
  • fmu-export.yml に EnumString の step を足し、FMPy と fmusim で確かめる。
