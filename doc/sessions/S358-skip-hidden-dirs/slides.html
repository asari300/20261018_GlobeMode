ライブラリの走査も隠しフォルダを飛ばす

S357 の D-3 の残り。resolve と flat の mo_files

走査の規則 4 か所 → 同じ規則
背景

走査の抜けが 2 か所残っていた

  • S357 で CLI の expand_inputs を collect_mo_files（fmt・LSP と同じ規則）に替えた
  • globe-mode-resolve の Library::from_dirs と globe-mode-flat の Project::read_dirs は、自前の mo_files で .history/ の .mo も読んだ
  • 同名のクラスが二重になる（--library のディレクトリに古い写しがあるとき）
直し

resolve に 1 つだけ置いて flat も使う

  • resolve::mo_files が . で始まる名前（ファイルもフォルダも）を飛ばし、pub で公開する
  • flat は自前の関数を消して globe_mode_resolve::mo_files を呼ぶ（flat は resolve に依存している）
  • frontend の collect_mo_files は使えない: frontend が resolve に依存するので向きが逆になる
確かめた

直す前なら落ちる試験を 1 本ずつ

crate試験直す前
resolvefrom_dirs_skips_hidden_dirs読んだファイル 2 本
flatread_dirs_skips_hidden_dirs読んだファイル 2 本

MSL に隠しフォルダの .mo は無い（data/msl の隠しは .download の zip と .globe-mode-msl）ので、Track B の数え方は変わらない

残し

S068 の規則はそのまま

  • X.mo と X/（package.mo 無し）が並ぶ配置は、frontend だけが X.mo を正にする。resolve・flat には足していない
  • 隠しフォルダだけを揃えた（今回の範囲）
