library-closure

ネイティブの --library も、モデルが使うファイルの閉包だけを読む

ChuaCircuit の check：1,493 → 128 MiB
目的

このセッションでやること

  • globe check --library data/msl は MSL の 2,556 ファイルを全部読み、最大 RSS が約 1.5 GiB
  • wasm には S037 の分割読み込みがある（S047 で 566 本すべて全部読みと同じ結果）
  • これを facade の Workspace::with_libraries の既定にする（CLI・globe lsp・Desktop の sidecar が使う道）
  • S051 の削減案 1 の実装
決定と理由

決めたこと（ADR-0025）

項目決定理由
どこで切り替えるかfacade の with_libraries だけCLI・LSP・Python・Desktop は呼び出しのまま変わる。CLI の main.rs は触らない
全部読む道with_libraries_full に残す比べるため。1 ファイルに複数のトップレベルのクラスがあるライブラリ向け
戻る条件パスが空、またはディレクトリでない既存の挙動を壊さない
2 つ目のモデル閉包が増えたら読み足すS037 の ensure_library がそのまま使える。globe lsp は順に検査する

結果

検査の結果は変わらない

  • facade の試験 tests/library_closure.rs: GlobeModeValidation の全モデルと MSL の 3 モデルを 1 つの Workspace で順に検査し、CheckResponse の JSON が全部読みと一致
  • 手元で globe check の出力の md5 は 3 モデルとも前後で一致。ChuaCircuit の simulate の CSV も一致
  • msl:compare（Rumoca の CLI と 20 本）は xtask が Checker::new を直接呼ぶので、この変更の外
