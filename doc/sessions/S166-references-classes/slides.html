クラス名の参照とリネーム

S161 の持ち越し。部品に加えて、型（クラス名）でも Shift+F12 と F2 が働く

extends Base の Base を Core に変えると、宣言も end Base; も 1 回で変わる
目的

このセッションでやること

  • カーソルがクラス名の上なら、その文書の中で定義ジャンプと同じ解決で同じクラスに行き着く識別子を一覧にし、リネームで置き換える
  • 字面の一致ではない。別の入れ子の同名のクラス（P.M と P.Q.M）は混ざらない
  • 口の形は変えない（globe/references・globe/rename・Backend.references・rename）
  • 足したもの: textDocument/prepareRename、ほかの開いた文書の参照の扱い
決定と理由

決めたこと

項目決定理由
一致識別子のトークンごとに Resolver::definition で引き、同じ定義のものだけ解決は 1 つ（定義ジャンプと同じ）。同名の入れ子を混ぜない
宣言と end見出しの語の次と end の次は、中身のクラスそのもの解決すると自分の中の同名のクラスに行ってしまう
断る別のファイルのクラス、import の別名、同じ階層に既にある名前書き換えても使う側が置き去りになる
ほかの文書

開いているほかのタブ

  • LSP は開いた文書を複数持つ。textDocument/references はクラス名ならほかの文書の参照も返す
  • リネームは 1 文書だけ。ほかの文書に参照があれば「ほかの文書に n 箇所の参照がある」と断る
  • UI の Workspace は今の文書しか持たない（離れたタブは setFile(…, "")）ので、UI の一覧は今の文書だけ
prepareRename

リネームできない所では入力欄を出さない

  • LSP: textDocument/prepareRename は識別子の範囲か、rename と同じ理由（-32803）
  • UI: F2 でまず今の名前のまま rename を試す（編集は入れない）。断られたら理由を role="alert" に出す
  • 新しい Backend の口は足していない
結果

試験

  • Rust の単体: 同名の入れ子を混ぜない、end も変わる、別ファイルのクラスは断る、文字列・コメントは変えない
  • LSP の RPC 1 本: 参照・リネーム・prepareRename、ほかの文書の参照で断る
  • test_ui.py: Base を Core に変えて検査が通り、Ctrl+Z で戻る
次回

持ち越し

  • ライブラリ全体・未開封のファイルにまたがる参照、複数ファイルの一括リネーム
  • 継承した部品のリネーム、import の別名の参照
  • UI でほかのタブの参照を一覧に含める（Workspace が複数の文書を持つ必要がある）
