## 1. 目的

S249 のコシミュレーションのマスター（Jacobi・固定刻み・Real だけ）の持ち越しのうち、小さく効く 3 つを足す。JSON の既存の鍵の意味は変えない（足すだけ）。

## 2. 決定と理由

詳細は [ADR-0026](../../adr/0026-fmi-import-placement.md) の (s)。

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| Gauss–Seidel | `"algorithm": "gauss-seidel"`（省略時は jacobi）。FMU を結線の元 → 先の順に 1 つずつ進め、直前にその入力へ元のいまの出力を渡す | Jacobi の 1 刻み遅れが無くなる。`fmus` は順序を持たないので、順序は結線から決める（ループは名前の順） |
| 初期値 | `"start": {"a.k": 2.0}`。instantiate の後・初期化の前に設定 | `run_cs` の `--set` と同じ位置。Int32（整数値）と Boolean（0 / 1）も受ける（Int の接続を試験で見るため） |
| Int32・Boolean の接続 | 始点と終点が同じ型のときだけ。値は f64 で受け渡す。列は接続の始点だけ追加 | 型違いは明確な誤りのまま。今までの列は変わらない |
| SSP の `.ssv` | やらない（次回） | `ParameterBindings` の読みは SSD の XML・`.ssv` の XML・Component への紐づけを足す必要があり、小さく済まない |

## 3. 図

```text
Jacobi:        読む(全部) → 渡す(全部) → a.step, b.step      （b は a の 1 刻み前の値）
Gauss–Seidel:  a.step → (a の出力を b の入力へ) → b.step     （b は同じ刻みの a の値）
```

## 4. 再現手順

```bash
cargo xtask fetch-reference-fmus
GLOBE_REQUIRE_REFERENCE_FMUS=1 cargo test -p globe-mode-cli --test fmu_cosim
```

試験は 3 本。Gauss–Seidel は Dahlquist → Feedthrough で b の出力が同じ刻みの a.x にちょうど等しい。`start` は Dahlquist の k = 2 で x(1) = 0.8^10。Int32・Boolean は 2.0 と 3.0 の Feedthrough をたすき掛けにして 7, 0, 7, 0, 7 が出る（型違い・小数の Int の `start` は断る）。Reference-FMUs の Feedthrough に Int32・Boolean の入出力があったので、省いた試験は無い。
