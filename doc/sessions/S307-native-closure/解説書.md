## 1. 目的

[S305](../S305-check-native/解説書.md) の持ち越しのうち 2 つ。(1) native の検査が毎回ライブラリ全体（MSL 2556 ファイル）を読む点を、モデルが使うファイルの閉包だけにする。(2) `GM-E6001`（構造特異）に位置を付ける。

## 2. 決定と理由

| 決めたこと | 理由 |
| --- | --- |
| Rumoca の道の `SplitLibrary`（字句の索引）を native でも使う | 名前の連なり・`import`・外側のパッケージをたどる走査が既にあり、MSL の 566 本で確かめてある（[ADR-0025](../../adr/0025-native-library-closure.md)）。`globe-mode-resolve` の木を遅延に作り直すより小さい |
| `split_library.rs` を feature `rumoca` と `native` のどちらでも作る | Rumoca に依存しない字句の走査だけ。native だけのビルドで使わない 2 つの関数は `allow(dead_code)` |
| `Project::read_dirs`（本文を読むだけ）を足し、`from_dirs_with` はそれを使う | 閉包を選ぶには、パースの前に本文が要る。`flatten.rs` には触れない |
| `GM-E6001` の位置は今回やらない | 下の 4 |

## 3. 図

```text
check_native
  Project::read_dirs（本文だけ）→ SplitLibrary（先頭のクラスの名前で索引）
  → closure(model, 入力の本文) ＋ 外側の package.mo ＋ クラスの見つからないファイル
  → Project::from_sources（290〜320 ファイルだけを parse・resolve）→ flatten → dae → analyze
```

## 4. 結果と、やらなかったこと

- 前後（`globe check -L data/msl --frontend native`、debug）: `PID_Controller` 15.8 s・最大 RSS 227 MB → 2.9 s・67 MB、`Rotational.Examples.First` 14.4 s → 2.3 s、`ChuaCircuit` は後が 2.2 s・67 MB。
- release（ライブラリの段だけ。`tests/native_closure.rs` の `#[ignore]`）: 全部読み 1.15 s、閉包は 1 モデル 0.24〜0.56 s。最大 RSS は閉包の道だけで 82 MB、全部読みを足して 208 MB。release の `globe` は作っていない。
- 平坦化の結果: MSL の 10 モデルで閉包だけと全部読みが一致（成功 5・断る 5、理由まで一致）。
- **`GM-E6001` の位置**: 自前の `DaeStructure` の `file`・`range` は `globe-mode-dae` が `None` を入れる。`globe-mode-flat` の `Equation`・`Var` が元の CST の範囲を持たないのが理由で、持たせるには `flatten.rs` の構築 7 か所と、展開（`connect`・配列・`for`）で由来を運ぶ変更が要る。別の担当が `flatten.rs` を触っているのでやっていない。

詳しくは [ADR-0039](../../adr/0039-native-cst-parser.md) の付記（S307）と [ADR-0025](../../adr/0025-native-library-closure.md) の付記。
