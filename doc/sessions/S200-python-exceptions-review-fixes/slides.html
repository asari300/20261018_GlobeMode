GlobeModeError と、束縛のレビューの修正

ユーザーの決定「例外を入れる」と、Opus のレビューの指摘 1〜10 を 1 件ずつ再現してから直した

モデルの誤りは今までどおり例外にせず、結果の dict で返す
階層

GlobeModeError の子は 6 つ

型継ぐ型出る場合

方針

入れないものを決めた

  • 既存の except ValueError / RuntimeError は壊れない（多重継承）
  • 基底に .diagnostics（無ければ空）と .code（最初の診断、無ければ None）
  • 呼び方の誤り（未知のキー、呼べない on_progress）は素の TypeError。打ち間違いまで握りつぶさせない
  • コールバックの例外と Rust の panic はそのまま通す
  • 「未知のモデルを例外に」は変えない（check は passed: False）
指摘と再現

動作の指摘は再現してから直した

#指摘状態
1targets に文字列再現して直した
2GIL を離すのは on_progress のときだけ再現して直した
3・7numpy の数・NaN・None の設定再現して直した

8コールバックの枝の試験3 つとも元から通った。試験だけ足した

GIL

実行の間は必ず GIL を離す

  • simulate と simulate_columns を 1 本の道に。on_progress が無くても進捗のたびに Ctrl-C を見る
  • check・graph・deps・flat・export_fmu も py.detach で包む
  • PyO3 0.30.1 のソースで確認: detach はスレッドを移さず、unsendable の検査は同じスレッドなら通る
  • 前は別スレッドが実行中に 4 回しか動けず、Ctrl-C は約 1.1 s の実行が終わるまで効かなかった
  • 既定のソルバは積分の中に通知が無いので、Ctrl-C は段の変わり目まで
