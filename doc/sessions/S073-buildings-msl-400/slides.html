Buildings を MSL 4.0.0 で回し直す（S067・S068 の持ち越し）

Buildings の実行できた本数 61 → 88（4.1.0 と同じ）
目的

確かめ残しが 2 つあった

  • S068 で external "builtin" を書き換えたが、Buildings（分割 4 の 1 本が約 70 分）は回し直していない
  • S067 で 4.0.0 だけ実行できない Buildings の 27 本。そのうち Interior・InteriorConvection の 2 本は別のメッセージ（invalid Solve IR contract）
  • 調査が中心。Rust のコードは変えない
決定と理由

CI は 1 本、手元も 1 本ずつ

  • libraries.yml は concurrency の group が 1 つ。動いている run が無いのを見てから Buildings だけを 1 本出した
  • 手元は RAM 3 GB。release の globe simulate を 1 本ずつ、端末から切り離して回した
  • 原因の確かめは「S068 の書き換えを一時的に外す」と「MSL を使わない最小の再現」の 2 つ。どちらもコミットしない

図

同じ穴、場所でメッセージが変わる

原因

invalid Solve IR contract の出所

  • Rumoca の rumoca-phase-solve（error.rs）と rumoca-ir-solve の InvalidCallInterface。GlobeMode は文字列を GM-U0004 に写すだけ
  • 2 本とも final parameter Real cosTil = Modelica.Math.cos(til)（sin も）。4.0.0 の cos・sin は external "builtin"
  • 書き換えを外すと 2 本とも同じエラーに戻る。今の main では 4.0.0 で走り、CSV は 4.1.0 と同じ
  • 判定: Rumoca の穴（上流の下書き 16 に追記）。名前を出さないのは診断の質の問題
再現手順

再現

gh workflow run libraries.yml --ref main \
  -f libraries='["Buildings"]' -f msl=4.0.0
cargo xtask fetch-library Buildings
globe simulate -L data/msl-4.0.0 -L data/libs/Buildings \
  -m Buildings.HeatTransfer.Convection.Examples.Interior -o out.csv
