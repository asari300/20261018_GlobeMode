リソースの内訳を数字にし、列ごとの結果を足した（コアは変えない）

2 GiB に 336 本目で達する。1 本で 3.7 GiB
目的

このセッションでやること

  • wasm の線形メモリが ADR-0023 (c) の上限 2 GiB に達するかを、MSL の 566 本で測る
  • 結果を CSV の文字列でなく列ごとの Float64Array で返す simulate_columns
  • globe check / simulate の最大 RSS をランナーで取る
  • メモリの見立てと削減の案を doc/research/resources-2026-10-31.md に
決定と理由

決めたこと

項目決定理由
列の渡し方SimColumns を返し、column(i) で 1 列ずつ Float64Arraywasm の中で 1 本に束ねる複製が要らない。.slice() の新しい buffer は Worker から転送できる
ゼロコピーの view使わない線形メモリが伸びると view が無効になる
protocolColumnsLayout を追加だけ既存の型と CLI の JSON は 1 バイトも変えない
計測の道手動の resources.yml手元は RAM が足りない。push の CI には入れない
