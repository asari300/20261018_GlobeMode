## 1. 目的

Track B の自前の段（`globe-mode-syntax`・`-resolve`・`-flat`・`-dae`）を、初めて検査の入口につなぐ。試しに使える形として `globe check --frontend native` を足す。既定は Rumoca のまま。

## 2. 決定と理由

| 決めたこと | 理由 |
| --- | --- |
| `globe-mode-frontend` の feature `native`（`NativeFrontend`、`Frontend::check`）として作った | [roadmap](../../roadmap.md) の計画どおり。`Frontend` の trait があり、実装を足すだけで済んだ |
| CLI のオプション `--frontend <rumoca\|native>`（既定 `rumoca`） | 環境変数より見えやすく、help に出る |
| 自前の段が断ったものは `GM-U0006`（終了コード 3）で `native では未対応: …` と出し、Rumoca に切り替えない | どちらの段で通ったかが曖昧にならない。既存の GM-U の扱い（`failure_code`）に合う |
| 診断の番号は既存の `GM-E0001`・`1001`・`1002`・`5002`・`6001` を使い、新しいのは `GM-U0006` だけ | 範囲を足す必要が無かった |
| S7 以降は検査しない（最後の行にそう書く） | 自前の段は DAE の構造と釣り合いまで |
| `Frontend::outline` は構文の誤りだけ返し、読めるファイルは `GM-U0006` | 自前の段にアウトラインを作る道が無い（LSP は構文の木を直接読む） |

詳しくは [ADR-0039](../../adr/0039-native-cst-parser.md) の付記（S305）。

## 3. 図

```text
globe check --frontend native
  └ NativeFrontend::check
      S0 parse（入力ファイル、位置つき）→ S1 resolve（届く参照、位置つき）
      → S4 Project::flatten → S5 dae::build → S6 analyze
      断る → GM-U0006（終了コード 3）
```

## 4. 再現手順

```bash
cargo run -p globe-mode-cli -- check src/Modelica/GlobeModeValidation \
  -m GlobeModeValidation.Simulation.Decay --frontend native
cargo test -p globe-mode-cli --test check_native
```
