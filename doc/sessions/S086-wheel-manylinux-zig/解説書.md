## 1. 目的

[S077](../S077-ci-lang-wheel/解説書.md) の持ち越し。`release.yml` の Linux の wheel は `manylinux_2_39` で、Debian 12（glibc 2.36）や RHEL 9（2.34）には pip で入らなかった。ランナー（ubuntu-24.04、glibc 2.39）でそのままビルドするので、`manylinux_2_34` を指定すると maturin が `GLIBC_2.39`（libc）と `GLIBC_2.35`（libm）の記号を見つけて落ちた（run 41376053596）。`release.yml` の wheel の段だけを変え、古い glibc を狙う。工程は [roadmap.md](../../roadmap.md) の P8。

## 2. 決定と理由

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 道 | maturin の `--zig` | zig は `mise.toml` にすでにある。manylinux の docker image は要らない |
| 段 | `manylinux_2_28` | Debian 10・RHEL 8 以降に入る。手元の wheel の最大の記号は `GLIBC_2.28` |
| 渡し方 | `MATURIN_PEP517_ARGS="--compatibility manylinux_2_28 --zig"` | `uv build --wheel` のまま。`maturin[zig]`（ziglang の pip パッケージ）は足さない（PATH の zig を使う） |
| zig の入れ方 | `jdx/mise-action` の `install_args: rust uv zig` | `mise.lock` の 0.17.0 |
| aarch64 | 同じ行 | ネイティブのランナー（ubuntu-24.04-arm）で `--zig`。クロスはしない |
| CLI 本体 | 変えない | `globe` の `build` の段は glibc の縛りを気にしていない |

## 4. 再現手順

```bash
uvx maturin build --release --zig --compatibility manylinux_2_28 --out /tmp/s086-wheel
objdump -T <展開した _native の .so> | grep -o 'GLIBC_[0-9.]*' | sort -uV | tail -1
uv run --isolated --no-project --with /tmp/s086-wheel/*.whl --with pytest pytest -q src/Python/tests
gh workflow run release.yml --ref feature/s086-wheel-manylinux-zig
```

検証の結果（数字）:

- 手元（WSL、x86_64）: `globe_mode-0.1.0-cp312-abi3-manylinux_2_28_x86_64.whl`（16,050,735 B）、release のビルド 14 分 05 秒、最大の記号 `GLIBC_2.28`、pytest 4 passed
- CI（release.yml の dry-run、run 41393637221）: success。`globe_mode-0.1.0-cp312-abi3-manylinux_2_28_x86_64.whl`（16,077,951 B）・`manylinux_2_28_aarch64`（14,137,068 B）・`win_amd64`（16,039,284 B）、pytest は 3 つとも 4 passed。build の段は x86_64 13 分 33 秒・aarch64 11 分 26 秒・Windows 17 分
