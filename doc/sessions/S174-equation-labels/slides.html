診断の方程式の名前に、変数の宣言が並ばない

S164 の監査と S173 が見つけた不具合。GM-I7001 と GM-E6001 の方程式の名前を直した

接続・流れ・束縛の方程式は 式の形 で名指す
現状

何が困っていたか

  • Cauer の検査で GM-I7001 の「微分した方程式」に SI.ElectricPotential v が並ぶ
  • SimpleSolenoid の GM-E6001「過剰な方程式」に SI.Current i や Real i
  • 原因は structure.rs の label()。来歴の span が指すソース片をそのまま名前にしていた
  • 接続・流れの和・束縛から生まれた方程式の span は、書かれた方程式でなく宣言か右辺だけを指す
決定

由来が Source でないものは残差を式にする

由来前後
接続Real va.p.v = b.n.v
流れの和Real ia.p.i + b.n.i = 0
束縛3 * k（右辺だけ）a.w = 3 * a.k
書かれた方程式v = p.v - n.v同じ
取れた情報

Rumoca から取れたもの、取れなかったもの

情報公開 API
由来（接続・流れ・束縛・ソース）取れる（origin()）
残差の式木と変数名取れる（DaeView）。名前にはこれを使う
元の connect(a.p, b.n) の文の位置取れない（span は宣言を指す）

connect 文そのものは出せないので式の形にした。上流の下書きは作らない（診断の範囲は変えず、アダプタの中で足りた）

診断の前後

CauerLowPassAnalog と SimpleSolenoid

診断前後
GM-I7001 の微分した方程式SI.ElectricPotential v（1 回）が 4 件C1.p.v = L1.p.v（1 回）ほか
GM-E6001 の過剰な方程式SI.Current ir.p.i + -p.i = 0、p.i = 0

診断の範囲（波線の位置）は変えていない。名前だけ

検査

確かめたこと

  • 単体: 接続・流れ・束縛の名前に Real が入らない、書かれた方程式は今までどおり
  • mise run check、msl:compare、wasm:node
  • 検査の判定（OK・GM-U・panic）は変わらない変更なので msl:funnel は回さない
