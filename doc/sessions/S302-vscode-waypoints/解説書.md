## 1. 目的

S299 の結線の途中の点の移動と追加（Svelte の DiagramView）を、VS Code の側のパネルにも入れる。Rust・LSP は変えない。

## 2. 決定と理由

| 決めたこと | 理由 |
| --- | --- |
| つまみの決め方・足す点の決め方・つまみの要素の木を `src/Svelte/src/lib/diagram-waypoint.ts`（`handlesOf`・`halfOf`・`addWaypointOf`・`handleNode`）に出す | `DiagramView` に埋まっていた計算が図のデータだけで書けたので、`diagram-select.ts` と同じく写しを作らずに済む。node の試験に偽の図を渡せる |
| Svelte の `rect.wp` は Svelte のテンプレートのまま | キー付きの `{#each}` で、図が変わるたびに新しい要素にして transform を残さない挙動を変えないため |
| `edit.js` に `moveWaypoint`・`addWaypoint` を足す。端は `deleteConnect` と同じ、index は 0 以上 1 万以下の整数、座標は有限で 1e6 以下、ends は 2 点 | webview は信頼の境界の外。座標は Rust 側の `coord` も見るが、拡張でも先に落とす |
| `file`・`class` は webview から受け取らない | S264 と同じ。パネルが最後に描かせた図のものを使う |
| つまみは選びが変わったときだけ作り直す | つまみのクリック（ドラッグの終わり）では選びが変わらないので、掴んだ要素を差し替えない |
| e2e は `panel.handle` へメッセージを渡す | webview の DOM は拡張ホストから操作できない（S264・S293 と同じ）。ドラッグ・つまみは `pnpm test` の偽の要素で見る |

## 3. 図

```text
webview: 結線を選ぶ（S293）→ handlesOf → rect.wp を svg に足す
         つまみのドラッグ → diagramDrag.onWaypoint → postMessage {moveWaypoint}
         線（.hit）のダブルクリック → addWaypointOf → postMessage {addWaypoint}
拡張:    parseEdit（検査）→ globe/moveWaypoint | globe/addWaypoint
         → TextEdit の配列 → WorkspaceEdit（undo 可）→ 図の引き直し
```
