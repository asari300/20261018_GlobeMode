cdylib を別 crate に出して doctest を戻す

S239 の持ち越し。facade が依存する rlib を、入れ子の cargo build に書き換えさせない

globe-mode-fmu-cdylib
原因

cdylib 兼 rlib の 1 crate だった

  • globe-mode-fmu の試験と CLI の試験は、共有ライブラリを作るために入れ子で cargo build -p globe-mode-fmu を回す。
  • crate-type に cdylib が入ると rlib は hash の無い名前になり、入れ子のビルドがそれを書き換える。
  • facade が feature fmu-p5b で依存したため、doctest の rustdoc が E0460 / E0463 で落ち、5 crate に doctest = false を置いた。

何がどちらへ

crate中身
globe-mode-fmurlib だけ。本体と fmi2*・fmi3* の入口、tests/fmpy.rs

入口 119 個は共有ライブラリから出る（nm -D で確認）。

結果

doctest が戻った

  • facade・globe-mode-c・-lsp・-py・-wasm の doctest = false を外した。
  • 共有ライブラリの名前は libglobe_mode_fmu_cdylib.so など。FMU の中では今まで通り globe_mode_fmu.<拡張子>。
