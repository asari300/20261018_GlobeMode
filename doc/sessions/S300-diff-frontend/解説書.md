## 1. 目的

Track B の自前の段（`globe-mode-syntax`・`globe-mode-resolve`・`globe-mode-flat`・`globe-mode-dae`）の突き合わせは、各 crate の `tests/compare.rs`（`#[ignore]`）に散っていた。[roadmap](../../roadmap.md) の Track B の行にある `xtask diff-frontend` を作り、一度に回して回帰を測れるようにする。

## 2. 決定と理由

| 決めたこと | 理由 |
| --- | --- |
| 数え方を `src/Rust/xtask/src/diff_frontend.rs` の 1 か所にし、flat・dae の `compare.rs` と `globe-mode-frontend` の dev 依存を消した | 同じ数え方を 2 か所に書かない。`#[ignore]` の試験は薄い形にするより消す方が小さい。dev 依存を消した結果、CI の判定で frontend の変更が flat・dae の試験を回さなくなった（`test_ci_plan.py` の期待値を直した） |
| 段ごとの検査を旗（はい / いいえ）にして JSON に書き、前回の JSON との差を回帰とする | `msl-sim` の `--baseline-json` と同じ流儀。回帰が 0 件という基準を数で測れる |
| 例題の選び方は `msl-funnel` の `msl_examples` を再利用（566 本）。`GlobeModeValidation` は `--validation`（既定 `src/Modelica`）の下の、親がパッケージの model・block・class（partial 除く） | Rumoca の基準値と同じ母集団で比べるため |
| Rumoca は自前で平らにできたものにだけ呼ぶ | 1 回の `check` で flat・釣り合い・構造が取れ、時間と RSS を抑えられる（全体 77〜99 秒、1.1 GiB） |
| resolve は、例題のクラスから中のクラス・`extends`・部品の型（解決できたもの）をたどって届くクラスすべての参照を数える | 例題のクラスの中だけだと未解決が 0 になり、段の判定にならなかった（初版で 566/566 になり、たどるようにして 467/566） |
| 回帰があれば終了コード 1（報告と JSON は書く） | mise のタスクや手元のスクリプトで落ちる |

## 3. 図

```text
Project（自前: parse・resolve）─ flatten ─ build（dae）─┐
                                                          ├─ 旗 → JSON ─ 前回との差 → 報告
Checker（Rumoca: flat・balance・structure）──────────────┘
```

## 4. 再現手順

```bash
mise run msl:diff-frontend     # 取得のあと cargo xtask diff-frontend --report doc/frontend-diff.md --json target/frontend-diff.json
cargo test -p xtask diff_frontend
```

報告は [frontend-diff.md](../../frontend-diff.md)（手で編集しない）。
