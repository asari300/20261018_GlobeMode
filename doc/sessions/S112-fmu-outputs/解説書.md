## 1. 目的

- [S109](../S109-fmu-events/解説書.md) の持ち越しの 1 つ目。今の値参照は状態・微分・tunable なパラメータだけで、SampleCounter の `n`（Integer）や `xs`（discrete Real）、代数変数を FMU の外から読めない。
- `ModelInstance` に代数・離散の変数の値を返す公開 API を足し、`globe-mode-fmu` の `modelDescription.xml` と `fmi2GetReal`・`fmi2GetInteger`・`fmi2GetBoolean` につなぐ。Rumoca は改変しない。
- `initial()` の事象、MSL を使うモデル、P5a との共有、CS・FMI 3.0・Windows は範囲の外。

## 2. 決定と理由

詳細は [ADR-0032](../../adr/0032-p5b-own-runtime.md) の追記（S112）。

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 値の求め方 | `full_solver_y` の y とパラメータの枠で `SolveRuntime::visible_values` を評価する | Rumoca の host が結果の列を作る `record_outputs`・`get_outputs` と同じ部品（公開）。exec の `run` の列と同じ値になる |
| 並びと役割 | `visible_names` の順。役割と型は `variable_meta` を `convert_variable_meta` で直し、exec の結果と同じ `role` で振り分ける | 結果の `Trajectory` と同じ規則にそろえる。状態・パラメータ・入力は除く |
| API の形 | `variables()`（名前・`VariableRole`・`ValueType`）と `variable_values()`（f64） | 代数と離散を別の関数に分けず 1 つの表にした。Rumoca は離散の値も f64 で持つ |
| 値参照 | `2n+p..`。`causality` は Output なら `output`（`Outputs` にも並べる）、ほかは `local`。Integer・Boolean と離散の Real は `discrete` | FMI 2.0 では Integer・Boolean は continuous にできない |
| 型違い・書き込み | `fmi2Error` | 書き込みは入力の扱いと一緒に持ち越す |
| Enumeration・String | 載せない（`shortcut:`） | FMI 2.0 の Enumeration は型の定義（`TypeDefinitions`）が要る |
| 代数変数の試験のモデル | NonlinearLoop | HarmonicOscillator・BouncingBall には代数変数が無い |

- S109 の SampleCounter の試験は Event Mode の回数ではなく FMU の中の `n` の値（10）で確かめるようにした。BouncingBall も `n` を足した。
