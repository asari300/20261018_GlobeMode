zig の取得を安定させる

ci.yml の lang が、zig のコミュニティのミラーの障害で落ちた（run 41702810070）

ミラーを飛ばして ziglang.org から直接取る
原因

run 41702810070 のログ

  • mise 2026.10.25 は、ミラー 17 件を順不同で先に試す
  • zigmirror.hryx.net は 502、zig.mirror.mschae23.de は 500（各 3 回）
  • ziglang.org に戻っても、ファイル名が zig-linux-x86_64-… で 404（正しくは zig-x86_64-linux-…）
  • 直後の run 41705882970 は同じ mise.lock で成功。名前の取り違えの理由は【未確認】
決定と理由

3 つの案

案判断理由
(a) actions/cache採らないmise-action が既にキャッシュしている。外れた回の取得を直さない
(b) MISE_ZIG_USE_COMMUNITY_MIRRORS=false採るmise 公式の設定。1 行。署名の検証は同じ
(c) setup-zig採らないzig の版を二重に持つ

取得の経路

結果

当てた所

  • ci.yml の lang、fmu-export.yml、release.yml（cargo-zigbuild の zig）
  • zig の版・mise.lock・src/Zig は変えない
  • ziglang.org は稼働率を保証しない。落ちたらこの設定を消せばミラーに戻る
次回

持ち越し

  • 名前の取り違えは再発したら MISE_VERBOSE=1 のログを取って mise に報告
  • ziglang.org 側で落ちたら、zig の install 先を actions/cache に載せる
