決定と理由 · S6 の判定を直した

der の形の完全マッチングは、正しい例題でも無いことがある

最初の版（der の形 = Rumoca と同じ）

  • 未知数は der(x)・代数・出力。状態 x は既知とみなす
  • MSL の全例題を回すと、正しい例題 166 本が「構造特異」になった
  • 例: Rotational.Examples.First（52 / 54）、MultiBody.Examples.Elementary.Pendulum（891 / 898）、Blocks.Examples.PID_Controller（83 / 86）
  • これらは微分インデックスが 1 より大きい DAE。der の形に完全マッチングが無いのは正常で、インデックスの低減で解く

直した版

  • S6 は x と der(x) を 1 つの列にまとめたグラフで判定する。Pantelides 法が失敗するのは、ここに完全マッチングが無いときだけ
  • 無ければ GM-E6001（Error）。過剰な方程式と不足している未知数を、位置つきで示す（粗い DM 分解）
  • der の形の結果は S7 の情報 GM-I7001（微分インデックスが 1 より大きい見込み）。実行は止めない
  • IR に state_refs（状態そのものの参照）を足した
  • Rumoca の analyze との照合は der の形のまま（最初の実行で 381 / 381 一致）
図 · 二部グラフ

位置を時間で与えた質点（x = sin(time)）

色の付いた線は、マッチングに使った辺。globe check の出力も同じ: 「S6: 完全マッチング 3 / 3。der の形では 2 / 3（インデックス低減が要る見込み）」。

決定と理由 · GM-U（ADR-0007）

「コンパイラが未対応」は、コードの規則と一覧で振り分ける

順規則GM コードRumoca のコード（例）
1未対応の言語機能・実装の制限（コードで決まる）GM-U0001ED019・ED013・ED018・ED020・EF020・ER073 など 12 個
1コンパイラの内部エラー（コードで決まる）GM-U0002ED008・EF023・EF024・EF025・ES014 など 20 個
2既知の制約の一覧に（モデル, コード）があるGM-U0003ED001 41 行・ET004 4 行・ED010 3 行・ER130 2 行
—どれにも当たらないGM-E のままED001・EF002・ER003 はコードだけでは決めない
  • 一覧は src/Modelica/msl-known-unsupported.txt。1 行 = <モデル> <コード> # 理由。frontend に include_str! で埋め込む
  • 中身は msl-funnel の報告の「一覧の原稿」から、理由を確かめて移す
  • severity は Error のまま（--force 無しでは実行しない）。CLI は unsupported[GM-U…] と表示
  • 案 C（omc と照合）は任意。omc を入れていないので S005 では行わない
