Android でも、止めた列は残るか

S157 の持ち越し。Tauri の WebView に COOP と COEP を付けて確かめた

答え: 付けても isolated にならない。Android は作り直しのまま
確かめ方

smoke の行に 2 項目

  • isolated=1|0: WebView の crossOriginIsolated
  • cancel_path=flag|restart|sidecar: 止めたのが SharedArrayBuffer のフラグか、Worker の作り直しか、Desktop の sidecar か
  • 行の def=ok の後、ready_ms の前に足したので、既存の grep と bench_ui.py は変えていない
  • ブラウザ（test_ui.py）は isolated=1 cancel_path=flag を assert
結果

emulator の GM-SMOKE の行

設定isolatedcancel_pathほか
ヘッダなし（S147 まで）未計測未計測止める cancel=ok
COOP same-origin と COEP require-corp0restart全項目 ok（msl・fetch・アセットは壊れない）

追加の診断: 応答のヘッダは coop=same-origin coep=require-corp で届いているが、typeof SharedArrayBuffer は undefined

決定と理由

ヘッダは外す

  • Tauri 2.12.5 の app.security.headers は使えて、応答に付いた（Android の wry も応答のヘッダを WebView に渡す）
  • それでも WebView は cross-origin isolated にならない。ヘッダは効かず、リスクだけ増える
  • よって tauri.android.conf.json は元のまま。Desktop の設定も触らない
  • android.yml の合格条件に isolated=0 cancel_path=restart を足し、事実を固定した
  • WebView 側が対応したら isolated=1 になるので、条件を flag に直す
