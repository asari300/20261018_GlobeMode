aarch64 Linux の FMI 2.0 の試験

dry run で落ち続けていた wheel の pytest を直した

断るのが正しい動き。直したのは試験のほうで、Rust は変えていない
目的

なぜ落ちていたか

  • build (aarch64-unknown-linux-gnu) の wheel の pytest test_export_fmu_p5b が 11-08 から失敗
  • 落ちると release ジョブが skipped になり、タグの前の dry run が通らない
  • P5b は host の OS・arch の名前で binaries/ に置く。FMI 2.0 の名前は linux64・win64・darwin64 だけ
  • aarch64 Linux の host では FMI 2.0 に置き場の名前が無い で断られる
決定と理由

決めたこと

項目決定理由
どちらを直すか試験（Rust は変えない）断る理由が規格にあり、platform の Rust の試験も断ることを確かめている
試験の形aarch64 Linux は ExportError の文面、他は今までどおり最小の変更。他の host の確認は減らさない
他の試験同じ前提のものは無いgit grep で洗った
文書CHANGELOG の既知の限界に一行利用者が読める場所に無かった
