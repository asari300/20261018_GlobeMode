進捗と中断の C・NIF の段

ADR-0033 の実装の順の 4: C・Zig・Julia と NIF・Elixir・Gleam

C はコールバックの戻り値、NIF は cancel(token) で止まる
目的

このセッションでやること

  • S123 の facade の simulate_observed を C ABI と NIF から呼べるようにする
  • S129（Python）を型にし、進捗の 4 つの値（stage・time・start_time・stop_time）をそろえる
  • Zig・Julia・Elixir・Gleam の包みと試験を 1 本ずつ
  • wasm・LSP・Desktop は持ち越し。exec と facade は変えない
決定と理由

C ABI の口

項目決定理由
進捗構造体 GmProgress を callback(progress, user_data) で渡す位置引数 5 つより足しやすい。Python の dict と同じ値
time が無いときNaN と has_time = 0NaN だけだと比べ方を間違えやすい
口gm_simulate_observed・gm_simulate_columns_observed既存の (model, settings_json) のまま。列の版は前の関数の包み元
NULL のときSimulateHandle::default()前と同じ道で結果が変わらない
Julia固定の trampoline に関数を Any で渡す閉包の @cfunction を使わない
決定と理由

NIF の口

項目決定理由
トークンcancel_token() で先に作る（ResourceArc）DirtyCpu の NIF は戻るまで値を返せない
実行simulate_observed(ws, model, settings_json, pid, token)結果は今の simulate と同じ JSON
進捗pid へ {:globe_progress, map}（NifMap）呼び出し元の env の send で送る
中断別のプロセスから cancel(token)ADR の (3) の表と同じ
Gleam不透明な CancelToken・Pidgleam_erlang を足さない
