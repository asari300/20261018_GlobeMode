FMU を別プロセスで回す

FMU は任意のネイティブコード。落ちても globe が落ちないように、読み込みと実行をワーカーに隔離した

abort・segfault・無限ループ・メモリの食いつぶしを、誤りとして受け取る
設計

親と子

  • 親: globe fmu run は FMU に触れず、自分自身を fmu __worker で子として起動する
  • 要求: 標準入力に 1 行の JSON（FMU のパス、kind、時刻、刻み、出力、set）
  • 結果: 標準出力の行だけ。印 \u0001GW の無い行は FMU の printf として捨てる
  • 行の種類: P 進捗、H 名前、M ME の要約、R 値の行、D 終わりの印、E 失敗
  • D が来ないまま閉じたら「落ちた」。終了の状態と標準エラーの末尾を誤りに添える
API

呼び出し側が実行ファイルを渡す

名前役目
run_in_worker(spec, req, progress)親。WorkerSpec に実行ファイル、引数、時間、メモリを持つ
worker_main()子。呼び出し側の副命令から呼ぶ
run_in_process(req, progress)子の中身。プロセス内で回したい人向け

将来の facade・Desktop の sidecar・Python が同じ形を使える（今回は口を足していない）。

上限

何を隔離し、何をしないか

対象扱い
クラッシュ隔離する。終了の状態（signal など）を誤りに
無限ループ--timeout 秒 で kill
メモリ--memory-limit MiB。Linux だけ（ulimit -v）
zombie・孤児drop で kill と wait。親が消えたら子は標準入力の EOF で終わる
ディスク・ネットワーク隔離しない（sandbox は持ち越し）
試験

落ちる FMU を作って確かめる

FMU親の誤り
Instantiate で abortsignal: 6 (SIGABRT)
DoStep で segfaultsignal: 11 (SIGSEGV)
DoStep が戻らない1.500 s で終わらないので止めた
GetReal が malloc を繰り返す（1 GiB）signal: 6 (SIGABRT)

どれも親は落ちず、子のプロセスが残らない。普通の FMU はプロセス内の結果とビット単位で同じ。
