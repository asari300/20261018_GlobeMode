設計 · FMI 2.0 / 3.0

Import は既存の crate の上に、FMI 2 の Export は自前で

Import（fmi 0.8 の上に作る）

  • ME: HybridSystem として扱い、全ソルバを使える
  • CS: do_step、状態の保存と復元、early return
  • SE（3.0）: 優先度付きのクロックスケジューラ
  • マスター: 固定刻みの Jacobi / Gauss–Seidel → ロールバック付きの可変刻み。系の構成は SSP か .gmsys
  • ブラウザでは、ネイティブの FMU は中身の閲覧だけ。wasm バイナリ付きの FMU なら実行できる

Export

  • P5a: Rumoca の fmi2 / fmi3 テンプレート → cc / zig cc
  • P5b: 自前の fmu-runtime（BSD-2 のヘッダの上に作る）。IR を埋め込んで解釈実行するので、ブラウザや Android からも出力できる
  • fmi-export は FMI 3 しか出力できないので、代替手段にとどめる

検証

Reference-FMUs（BSD-2）・fmpy.validate_fmu・fmusim・fmuCheck（FMI 2）・往復（Export → Import）

設計 · connect グラフ

connect() から Obsidian 風のネットワークグラフを描く

  • データ: connect_graph(path, depth) が graphology の JSON と、編集ごとの差分を返す。flatten しなくても描ける
  • ノード: コンポーネントとコネクタ。色は connector の種類、大きさは次数（接続の数）
  • エッジ: connect 文、継承、包含
  • 描画: sigma.js（WebGL）＋ ForceAtlas2。レイアウトは Worker で回し、反復回数に上限を設ける。1 万ノードを超えたら cosmos.gl
  • 操作: 階層の展開と折り畳み、検索、近傍のハイライト。S4〜S6 の問題を色で示す
  • Cosmograph は NC ライセンスなので使わない（cosmos.gl とは別物）
