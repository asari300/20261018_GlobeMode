## 1. 目的

main `cc846ba` の CLI と frontend の案内を読んだレビュー（10 件）を直す。指摘は「読んで論証しただけ」なので、1 件ずつ失敗する試験（または古い `globe` での手動の再現）で確かめてから直した。あわせて、ユーザーが「CLI は任せる」と決めた終了コードの体系を実装した（[roadmap.md](../../roadmap.md) の 2026-11-06 の決まり）。

## 2. 決定と理由

### 2.1 利用者のファイルを壊す 2 件（指摘 1・2）

| 指摘 | 古い `globe`（手動で再現） | 直し |
| --- | --- | --- |
| 1 `-o` が入力を指す | `simulate m.mo -m Decay -o m.mo` が終了コード 0 で、`m.mo` が CSV になった | 計算の前に終了コード 2。`-o` の先が (a) 拡張子 `.mo`（大文字小文字を問わず、リンク先も）、(b) 入力のファイル（正規化して比べる）、(c) `-L` の配下、のどれかなら断る |
| 1 の続き `fmu export --out` | `write_fmu` は `<out>/<名前>/` を `remove_dir_all` で消す | その `<out>/<名前>/` が在って `.mo` を含む、または入力・ライブラリを含むなら終了コード 2。シンボリックリンクは辿らない（輪になっても止まる） |
| 2 壊れた symlink | `path.exists()` はリンクを辿るので偽。作って消す道に入り、リンクが消え、リンク先に空のファイルが残った | `symlink_metadata` で調べ、リンク先の無い symlink は触らず終了コード 2 |

事前検査は、既にあるファイルを追記で開くだけ（中身・権限・更新時刻は変わらない）で、無いファイルは作って消す。計算に失敗したら新しいファイルは残らない（結果は計算の後でしか書かない）。この 2 点は、指摘 10 の試験で固定した。

### 2.2 終了コードの体系（指摘 5。ユーザーの決定）

| コード | 意味 | 変更 |
| --- | --- | --- |
| 0 | 成功 | |
| 1 | モデルの誤り（Error の診断）・整形が要る（`fmt --check`）・lint の指摘 | 未対応だけのときは 3 になった |
| 2 | 使い方の誤り・入力を読めない・結果を書けない | ディスク満杯は panic の 101 だった。`fmt`・`lint` にパスも `-` も無いときが加わった |
| 3 | 未対応（GM-U）だけで止まった（`check`・`simulate`） | 新しい |

- **読み手が先に閉じたとき（`| head`）は、結果の終了コードを保つ。** 前は何でも 0 で、`pipefail` の CI で `globe fmt --check src | head` の失敗を見逃した。SIGPIPE の 141 にもしない（成功した検査を `| head` しただけで非 0 になる）。実装は `STDOUT_CLOSED` の旗で、標準出力への書き込みが BrokenPipe になったら以後の出力を黙って捨て、処理は最後まで進める。
- **本物の書き込みの失敗**（`> /dev/full`）は `error: 標準出力に書けない: …` を 1 行出して終了コード 2。
- **3 の判定は CLI に規則を置かず**、S173 が protocol に置いた `unsupported_summary` を使う。Error がすべて GM-U のときだけ 3、混ざれば 1。`simulate --force` で実行できたときは従来どおり（実行できた＝GM-U の Error は無い）。
- `-o -` のとき CSV が標準出力を使うので、診断・要約・`--json` の報告・ライブラリを読めない報告は標準エラーに回す（指摘 3・4・9）。`print_diagnostics` の重複していた約 20 行と `severity()` は、表示行を作る `diagnostic_lines` 1 つにして消した。

### 2.3 `fmt` の標準入力は `-` を明示したときだけ

パスを 1 つも渡さず `-` も無いときは、端末かパイプかに関係なく `error: 対象のパスが無い。使い方: globe fmt <FILES…>…か globe fmt -` を出して終了コード 2（`lint` も同じ形）。以前は入力がパイプなら標準入力を読み、`globe fmt --check` が何も検査せず 0 で終わった。

呼び出し元を調べた結果:

| 呼び出し元 | 呼び方 | 影響 |
| --- | --- | --- |
| ウェブアプリ（Actix・Axum・Loco・Rocket の Rust 版、Astro、FastAPI、Phoenix、Wisp）、marimo、streamlit | `fmt --json` / `lint --json`（標準入力） | なし |
| VS Code の拡張 | `globe lsp` | なし |
| CI・`mise run check` | `fmt --check src/Modelica` | なし |
| 試験 `piped_stdin_still_formats_stdin` | パスなしの `fmt` | `fmt -` に直した |

パスなしの `--json` は標準入力のままにした。[web-apps.md](../../web-apps.md) の契約（`echo … | globe fmt --json`）で、10 種のアプリが頼っているため。`--json` はパスなしでは標準入力の意味しか無い。

### 2.4 案内（指摘 6・7・8）

- **6**: `add_workspace_candidates` は、診断の補足が空のときだけ、名前の前からの一致が長い順に最大 5 件（「ほか n 件」）。パッケージ名の診断（補足に「直下のモデル」がある）には足さない。
- **7**: 並べ替えの鍵を（段, 開いている文書が先, 距離, 前からの一致）にした。[S187 の閾値の表](../S187-cli-hints-followup/解説書.md)（どれを候補にするか）は変えていない。変わったのは並びだけで、遠い開いている文書のモデル（段 3）が、ライブラリの近い一致（段 0〜2）より先に出なくなった。
- **8**: 名前が 64 文字を超えたら編集距離を飛ばす（綴りの候補は出ず、完全修飾名の案内になる）。`format!(".{query}")` はループの外へ。

### 2.5 `main.rs` の分割（指摘 10 の後半）

`check` の人間向けの表示 `print_s7`〜`print_s10` と `state_name` を `report.rs` へ。行を移しただけで、ロジックは変えていない（別のコミット）。
