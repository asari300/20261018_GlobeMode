決定と理由

なぜ 141 にしないか

  • 成功した検査を | head しただけで非 0 になり、pipefail の CI を壊す
  • 実装は、BrokenPipe になったら以後の標準出力を黙って捨て、処理は最後まで進める
  • -o - | head でも、--json の報告は標準エラーに出て、終了コードは本来のまま
決定と理由

fmt の標準入力は - を明示したときだけ

  • パスも - も無ければ使い方の 1 行を出して終了コード 2。lint も同じ
  • 以前は入力がパイプなら標準入力を読み、fmt --check が何も検査せず 0 で終わった
  • 呼び出し元を調べた: ウェブアプリ 10 種・marimo・streamlit は fmt --json、CI は fmt --check src/Modelica で、パスなしの標準入力は 0 件
  • パスなしの --json は標準入力のまま（ウェブアプリの契約）
