決定と理由 · .mos と印

文として呼び、印だけを print する

1 本分の .mos（omc.rs の script()）

print("@@BEGIN M\n");
checkModel(M);
print("@@ERR\n"); getErrorString();
print("@@TRANSLATE\n");
translateModel(M);
print("@@ERR\n"); getErrorString();
print("@@END\n");

先頭で setModelicaPath、loadModel(Modelica, {"4.1.0"})、setCommandLineOptions("-d=initialization")。M は Modelica.… の完全修飾名。

読み方

  • @@BEGIN で切り、@@END まであればそのモデルの結果。無ければ「落ちた」
  • checkModel の文字列から方程式数と変数数を取る
  • translateModel の結果は、区間の最後の空でない行が true か
  • @@ERR の後の getErrorString() の文言で、特異（structurally singular・pantelidesIndexReduction failed・error found sorting equations）/ 不均衡（imbalanced number of equations）/ その他に分ける
  • 「over specified」と、冗長な初期方程式の本数（The following N initial equations are redundant）を取る

落ちたとき

プロセス単位の制限は既定 900 s。落ちたり時間切れになったりしたら、印の無いモデルを 1 本ずつ再実行し、それでも駄目なら「結果なし」にして続ける。

決定と理由 · omc の振る舞い

手元で確かめた omc 1.27.1 の振る舞いと、その対応

omc の振る舞い（確認日 2026-10-19）そのままだと対応
checkModel は partial や数が合わないモデルでも「completed successfully」。数だけが違う（PartialOpAmp は 23 / 27）成否では判定できない合う / 合わないは数で判断する
print(String(translateModel(M))) のように式の中で呼ぶと、失敗したときの getErrorString() が空失敗の理由が読めない文として呼ぶ。print は印だけ
-d=initialization を付けると、反復変数の一覧が true / false の前に標準出力へ出る最初の全例題の実行で 52 本を「失敗」と読み違えた結果は区間の最後の行で読む。単体テストを足した
初期条件の不足は、黙って start 値で埋めて警告を出さない（-d=initialization でも）不足は比べられないS8 は過剰だけ比べる
過剰は The initial conditions are over specified。-d=initialization で冗長な本数も出る—本数も globe の差と比べる
構造インデックスの数を出さない—S7 は比べない
同梱の MSL は 4.1.0+maint.om。素の 4.1.0 も読める（ModelicaServices が patch されていない警告、Complex を読み飛ばす通知は出る）—素の 4.1.0 で照合
