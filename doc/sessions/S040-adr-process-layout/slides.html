Desktop と Web のプロセス構成（ADR-0023）

計画書の WP-J。Tauri のシェル（WP-C）を作る前に、検査と実行をどこで回すかを決める

UI のプロセスでは計算しない。Desktop は globe を sidecar、Web は Web Worker
目的

なぜ今決めるか

  • architecture §4 は「Tauri のプロセス内でネイティブ実行」だった
  • 検査は 1 モデルでも GiB の単位（msl:funnel 7.2 GiB、msl:sim のワーカー 3.4 GiB、wasm は ChuaCircuit で 513 MiB）
  • 終わらない計算（DrumBoiler）は同じプロセスでは止められない。msl:sim は別プロセスを外から止めて回し直している
  • 入口はそろった: facade（S035）、globe lsp の stdio の枠（S038）、Worker の直列化と作り直し（S036）
決定

ADR-0023 の 3 つ

項目決定理由
(a) 分ける計算は 1 つのワーカーに送り、1 度に 1 要求。落ちたら作り直して再生panic・OOM・時間切れを UI から切り離す。S036 と同じ手順
(b) Desktopglobe を Tauri の sidecar にし、globe lsp の stdio の枠に独自の要求を足すコアの実体が 1 つ。外から kill できる。WP-I のバイナリがそのまま使える
(c) WebWeb Worker のまま。線形メモリは目標 128 MiB / 1 GiB、上限 2 GiB で作り直しS037 の分割読み込みの目標値。上限は未実測
