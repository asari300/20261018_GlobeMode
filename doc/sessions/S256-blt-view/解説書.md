## 1. 目的

モデルの方程式の BLT（Block Lower Triangular）分解を、人が読める形で出す（[roadmap](../../roadmap.md) の P8、[features](../../features.md) の BLT の行）。S9（[ADR-0012](../../adr/0012-loops-and-preflight.md)）は内部で BLT を作るが、大きさ 2 以上のブロック（代数ループ）しか外に出していなかった。

## 2. 決定と理由

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 算法 | 新しく書かない。`analyze_loops` の前半を `solve` に切り出し、`analyze_blt` と共有する | マッチング（Hopcroft–Karp）と強連結成分（Tarjan 法）を 2 つ持つと食い違うおそれがある |
| 型 | `BltBlock`（大きさ・代数ループか・非線形か・解く変数の名前・方程式のラベル）と `BltReport` | `LoopReport` に足すと S9 の JSON と snapshot が変わる。別の型なら既存の出力は動かない |
| 経路 | `GlobeDb::blt` → facade の `Workspace::blt`。`dae_shape` と `index_report`（位置を落とした salsa クエリ）を使う | 検査（S0〜S5）が通らなければ診断を返し、構造特異などは `skipped` に理由を入れる |
| CLI | `globe blt [files] [-L lib] -m <model> [--json]`。`Command` の末尾に足した | 代数ループは見出しと「**」で目立たせ、大きさ 1 は 1 行 |
| 並び | 解く順（依存の先が先）。ブロックの中の変数と式は添字の昇順 | ループの中はどの式でどの変数を解くかが定まらないので、組にしない |

インデックス 2 以上のモデルは、S9 と同じく Pantelides 法の最高階の系で分ける（状態選択の前の見込み。`reduced` と表の見出しで示す）。

## 3. 図

```text
DaeStructure + IndexReport ─► solve（解く系 → 完全マッチング → Tarjan）
                                 ├─► analyze_loops（大きさ 2 以上 + tearing）  既存
                                 └─► analyze_blt（全ブロックに名前を付ける）  今回
```

## 4. 再現手順

```bash

globe blt src/Modelica/GlobeModeValidation -m GlobeModeValidation.Loops.LinearLoop --json
```
