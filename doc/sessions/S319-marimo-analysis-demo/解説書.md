## 1. 目的

直近に Python へ入った解析の機能（`Workspace.linearize`・`blt`・`stages`・`check(frontend="native")`、`cosim`）を、利用者がそのまま開いて試せる marimo のノートブック 1 本にまとめる。

## 2. 決定と理由

| 決めたこと | 理由 |
| --- | --- |
| `src/Python/marimo/analysis_app.py` に 4 節を置く | 既存の `sim_app.py` と同じ置き場・同じ流儀（`.py` の marimo アプリ、入力欄にライブラリのディレクトリ） |
| 図は plotly（既存の依存）、表は polars | 新しい依存を足さない。numpy が無くても `linearize` の list のリストを同じに読む |
| コシミュレーションは Jacobi と Gauss–Seidel の `|a.x - b.out|` を比べる（最初の行は除く） | Feedthrough は入力を返すだけなので、差が通信の順序の差そのもの。最初の行は初期化直後で出力が 0 |
| Reference-FMUs か `globe` が無ければ、その節は案内の文だけ | `data/reference-fmus` は取得物でコミットしない。ノートブックは他の節だけでも開ける |
| 試験は `test_analysis_app.py`。`app.run()` で全セルを実行し、`defs` の値を確かめる | 見本が壊れたことに気づける。A・D の値、安定性、Pendulum の index 3、LinearLoop の大きさ 2 のループ、frontend 2 行。FMU があれば Gauss–Seidel の遅れが 0 |

## 3. 図

```text
analysis_app.py
  ├ linearize ── LinearSystem → A・B・C・D の表、固有値、stable
  ├ blt/stages ─ LinearLoop（size 2 のループ）、Pendulum（index 3）
  ├ cosim ────── jacobi / gauss-seidel の b.out と a.x の折れ線
  └ check ────── rumoca と native の 2 行の表
```

## 4. 結果と、やらなかったこと

- pytest 2 本 pass。`marimo check` の警告 0、`marimo export html` でエラー 0。
- やらなかったこと: ブラウザ（Playwright）での表示の確認、wasm（Pyodide）版、パラメータを動かす UI（`linearize` の `parameters`）。

## 5. 再現手順

```bash
uv sync
uv run marimo run src/Python/marimo/analysis_app.py
GLOBE_BIN=target/debug/globe uv run pytest src/Python/marimo/test_analysis_app.py
```

コシミュレーションの節は `cargo xtask fetch-reference-fmus` と `cargo build -p globe-mode-cli` が要る。
