## 1. 目的

[roadmap.md](../../roadmap.md) の P8「Diagram ビュー」。S250（部品のドラッグ移動）と S261（結線の追加）は Svelte の UI だけだった。VS Code 拡張の側のパネル（S247）でも同じ 2 つをできるようにする。Rust と LSP は変えない。

## 2. 決定と理由

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| ドラッグの処理 | `DiagramView.svelte` から `src/Svelte/src/lib/diagram-drag.ts` の `diagramDrag(svg, {onMove, onConnect})` に出し、Svelte と webview が読む | 吸着・しきい値・ポインタの捕まえ先・結線の判定を 2 か所に書かない。S247 の `shape-svg.ts` と同じ置き方 |
| 試験のしやすさ | svg の API だけを呼ぶ（`DOMPoint`・グローバルの `document` を使わない） | node の試験に偽の svg を渡せる |
| 編集の経路 | webview は `postMessage`、拡張が LSP を呼び `WorkspaceEdit` で適用 | webview は LSP に話せない。undo 可・保存しないは Svelte 版と同じ |
| 信頼の境界 | `edit.js` の `parseEdit` で型と値を検査。`file`・`class` は受け取らず、最後に描かせた図（`panel.target`）のものを使う | webview が別の文書・クラスを書き換えさせられないように |
| 競合 | LSP の応答を待つあいだに文書の版が変われば入れない | 古い本文に対する編集を入れないため |
| 図の更新 | 既存の `onDidChangeTextDocument` → 300 ms の再取得で足りる | `show` が DOM ごと作り直すので見た目の `transform` も消える |
| 失敗時 | `edited`（ok）を待ち、false か 10 秒で見た目を戻す | Svelte 版の `onMove` が false を返すのと同じ |

## 3. 図

```text
webview: pointerdown → pointermove（見た目だけ） → pointerup
  → postMessage {type: move | connect, id, …}
拡張:   parseEdit（検査）→ client.sendRequest(globe/movePart | globe/addConnect, {file, class は拡張が決める})
  → WorkspaceEdit.set(asTextEdits) → applyEdit（undo 1 回）→ postMessage {type: edited, id, ok}
  → 文書の変更 → 300 ms → refresh → show（図が作り直される）
```

## 4. 再現手順

```bash
cd src/VSCode/globe-mode
pnpm install --frozen-lockfile && pnpm build
GLOBE_BIN=<globe> pnpm test          # diagram-edit.test.mjs を含む
cd ../../Svelte && pnpm install --frozen-lockfile && pnpm check
gh workflow run vscode.yml --ref feature/s264-vscode-diagram-edit   # 3 OS の e2e
```
