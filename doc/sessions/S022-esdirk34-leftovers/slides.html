esdirk34 の残り

OvervoltageProtection で黙って誤った軌道になる原因は、diffsol の SDIRK がヤコビ行列を状態の約 1.4 倍の点で取ること。刻みの始めの状態で取るようにして直した

Electrical.Analog.Examples 54 本の esdirk34: 実行 45 → 48、管 42 → 46。trbdf2 も 48・45。全体 356 本は 282・273 / 281（S021 は 272・262 / 271）
目的

このセッションでやること

  • S021 の残し: esdirk34 が OvervoltageProtection で終了時刻まで進むが誤った軌道になる（CL.v(0.4) = -1.64 V、参照 -0.0006 V）
  • 残りの 3 本（CauerLowPassSC・HeatingRectifier・ThyristorBehaviourTest）の原因の分類
  • 調査はサブエージェント（Sonnet、high）2 本に分けた: 機構と直し / 3 本の分類
原因

ヤコビ行列を間違った点で取っていた

どこ何をしている結果
diffsol op/sdirk.rs段の方程式 F(x) = M x − h f(phi + c x)。ヤコビ行列は phi + c·x で f' を呼ぶx が段の未知数なら正しい
runge_kutta.rs:637、sdirk.rs:261,277reset_jacobian(op, &state.y, t)。x の位置に状態 y を渡すphi + c·y ≈ 1.4 倍の電圧で f' を取る
ツェナーの指数その点の J は 1e15（正しい点では 5e5）Newton 法の更新量と誤差の見積もりが 1e12 分の 1 に潰れる

受理した点 t = 0.0184、CL.v = 5.41 の導関数は -2.8e5。段の Newton 法は CL.v = -3839 まで飛んでから「収束」していた。代数ループは与えられた状態に対しては正しく解けている

決定と理由

決めたこと

項目決定理由
ヤコビ行列の点diffsol が渡す点を使わず、刻みの始めの受理した状態（anchor）で取る一歩分だけ古いが、SDIRK はもともと刻みの中で行列を使い回す。rk.rs の閉包だけで済み、vendor を patch しない
試しの点の番人入れない受理点から 1e3 倍離れたら NaN を返す案は 1e-5 で効いたが閾値が恣意的
回帰の試験DiodeSwitching の許容を 1e-4 → 1e-5直す前の差 1.3e-5 で落ち、直した後は 1.3e-6。新しいモデルは足さない
CauerLowPassSC・ThyristorBehaviourTest分類だけ。直さない前者は再開の後に刻みが縮む（未分類）、後者は host の射影（確信は低い）
