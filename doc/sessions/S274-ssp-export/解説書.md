## 1. 目的

S253・S263 で `.ssp` を読めるようになった。逆向きに、Co-Simulation の spec（JSON）から `.ssp` を書き出し、読み戻すと同じ結果になる「往復」の最小版を作る。

## 2. 決定と理由

詳細は [ADR-0026](../../adr/0026-fmi-import-placement.md) の (u)。

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 口 | `globe fmu ssp-export <spec.json> -o system.ssp`、実装は `write_ssp` | `fmu cosim` と同じ spec を渡せる |
| XML | 文字列の組み立てと `& < > "` の escape | 依存を足さない（roxmltree は読むだけ） |
| `start` | `ParameterBindings` のインライン | `.ssv` を増やさない方が小さい |
| `step`・`algorithm` | SSD 独自の `Annotation`（型は自分たちのドメインの逆順） | SSD に置き場が無く、XSD の `TAnnotations` が任意の中身を許す。`--step` は Annotation に勝つ |
| 結線の型 | Real（Float64）だけ | 読み取りが Real 以外のコネクタを断る。書けても読み戻せないものは書かずに断る |

## 3. 図

```text
spec.json ──► write_ssp ──► system.ssp
 fmus            │            ├─ SystemStructure.ssd（Component・Connectors・Connection・DefaultExperiment・Annotation）
 connections     │            └─ resources/<名前>.fmu（FMU をそのまま）
 start/step/…    ▼
              globe fmu cosim system.ssp ──► spec と同じ CSV
```

## 4. 再現手順

```bash
cargo xtask fetch-reference-fmus
GLOBE_REQUIRE_REFERENCE_FMUS=1 cargo test -p globe-mode-cli --test fmu_cosim
cargo test -p globe-mode-fmi-import --lib ssp
globe fmu ssp-export spec.json -o system.ssp && globe fmu cosim system.ssp
```
