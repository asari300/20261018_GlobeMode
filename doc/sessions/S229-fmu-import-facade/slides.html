FMI Import を CLI の外へ

facade、Python、Desktop の UI から FMU を読んで回せる

ワーカーは呼び手が渡す。ネイティブコードは別プロセスのまま
facade

口は 2 つだけ

  • import_fmu_info(path): globe fmu info と同じ情報。ネイティブコードは実行しない
  • run_fmu(worker, path, request, on_progress, cancel): ワーカーで回す
  • 結果の列は OpenedResults::columns()（S222）で、実行の結果と同じ形
  • CLI の fmu info / run も同じ関数を呼ぶ（写しは作らない）
ワーカー

実行ファイルの探し方

呼び手ワーカー
CLI・Desktop の sidecar（LSP）current_exe()（globe 自身）
PythonGLOBE_BIN、無ければ PATH の globe。無ければ FmuError

wheel の中には実行ファイルが無いので、Python は外の globe を使う

中断

旗が立てば 50 ms で kill

  • WorkerSpec::cancel（AtomicBool）を親が 50 ms おきに見る
  • DoStep が戻らない FMU も止まる（進捗に頼らない）
  • Desktop は既存の $/cancelRequest で届き、Python は on_progress が真を返すか Ctrl-C
Desktop

「開く」で .fmu

  1. globe/fmuInfo の警告と要約を confirm に出す（断れば回さない）
  2. globe/fmuRun を sidecar のワーカーで回す。進捗は $/progress、「止める」で kill
  3. 結果は S222 の結果のタブにプロット

ブラウザ・Android は zip を読まず「Desktop だけ」と理由を出す。RPC_METHODS は 20 から 22

試験

確かめたこと

  • facade: Dahlquist の CS・ME、JSON の request、失敗、遅い FMU の中断（子が残らない）
  • LSP: globe lsp を起動して info・run・-32000・-32602
  • Python: 同じ FMU で FmuError の各場合
  • Playwright: ブラウザは「Desktop だけ」、Desktop は確認から結果のタブまで
