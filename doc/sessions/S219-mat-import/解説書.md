## 1. 目的

[roadmap](../../roadmap.md) の「機能の穴（P4）結果の入出力」にあった MAT v4 の読み込みを、CLI と Python から使えるようにする。UI の「結果を開く」は別の仕事。

## 2. 決定と理由

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| `read_mat4` の置き場 | 動かさない | 指示は xtask から sim への移動だったが、着手時点で `globe-mode-sim::mat::read_mat4` に既にあり（S203 の omc の実物の試験も `tests/omc_mat.rs`）、xtask に写しは無かった |
| 読み込みの入口 | `mat::read_results(path)`。拡張子 `.mat` なら MAT v4、それ以外は `store::read_csv` | `globe simulate -o` の書き分けと同じ規則。CLI と Python の 2 か所から同じ関数を呼ぶ |
| MAT の書き直し | `write_mat4(&SimRun, …)` の本体を `write_mat4_parts(trajectory, parameters, span, …)` に出す | 読んだ結果は `SimRun` ではない。CLI で `SimRun` を偽造するより、本体を 1 つ分けるほうが小さい |
| CLI | `globe results <入力> [-o 出力]`。出力の形は拡張子、`-o` 無しと `-` は CSV を標準出力へ | 新しい整形器は書かず `store::write_csv` と `write_mat4_parts` を呼ぶ |
| 書き先の守り | `check_writable_file(出力, [入力], [])`（S182・S199）。入力と同じファイル・`.mo` を断る | `globe results a.mat -o a.mat` で入力を壊さない。終了コードは `simulate` と同じく 2 |
| Python | `read_results(path)` は `simulate_columns` と同じ形の dict（`ok`・`columns`・`csv: None`）に `parameters` を足す。読めなければ `ResultError` | `table(res)` がそのまま使える。新しい型は作らない |
| MAT のパラメータ | CSV に移さない | CSV に列がない。MAT から MAT への直しでは残る |

## 3. 図

```text
.mat ─ read_mat4 ─┐                        ┌─ write_csv        ─ .csv / 標準出力
                  ├─ MatContents ──────────┤
.csv ─ read_csv ──┘ (trajectory,parameters) └─ write_mat4_parts ─ .mat
                         │
                         └─ Python: columns と parameters
```
