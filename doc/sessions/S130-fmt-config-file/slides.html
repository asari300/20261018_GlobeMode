整形と lint の設定ファイル

features.md の「設定ファイルは未」を埋める

プロジェクトに globe-mode.toml を置けば、CLI と LSP が同じ設定で整形・lint する
目的

このセッションでやること

  • ruff の ruff.toml のように、整形のインデント・行幅などと lint の止める規則をファイルで決める
  • CLI globe fmt / globe lint は対象から上へたどって探す。引数が優先
  • LSP はワークスペースの根から探し、didChangeConfiguration で読み直す
  • wasm とブラウザ UI は対象外（設定ファイルが無い。引数で渡すまま）
決定と理由

形

[fmt]
indent = 2
width = 80
insert_origin = true
blank_around_sections = true
format_html = true

[lint]
disable = ["missing-description",
           "GM-L0004"]
  • 書いていないキーは既定
  • disable は規則の名前でも LSP のコードでもよい（RULES の表で名前にそろえる）
  • 知らない表・キー・規則、型の違う値は誤り
  • CLI は終了コード 2、LSP は window/showMessage で知らせて既定で続ける
決定と理由

どこで読むか

項目決定理由
読む処理globe-mode-fmt の optional な feature configCLI と LSP に別々に書くと規則が 2 か所に分かれる
依存 0既定と wasm では保つ（feature を立てるのは CLI と LSP だけ）ADR-0024 の決定 1
TOMLtoml 0.8.23rumoca-core の依存で Cargo.lock に既にある。新しい crate は 0
LSP の indent設定ファイルがあれば tabSize より設定ファイルruff と同じ。エディタの既定 4 に負けない
探し方（CLI）ファイルごとに上へたどるサブディレクトリに別の設定を置ける

試験

場所中身結果
fmt の単体 2 本正常な設定と、知らないキー・表・規則・負の数・型の違い・壊れた TOML通過
