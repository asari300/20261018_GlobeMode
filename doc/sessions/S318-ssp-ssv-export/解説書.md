## 1. 目的

`write_ssp` は `start` を SSD の中のインラインの `ParameterValues` に書いていた。これを `.ssv` のファイルとしても書けるようにする（`globe fmu ssp-export --ssv`。既定は今のまま）。

## 2. 決定と理由

| 決めたこと | 理由 |
| --- | --- |
| `write_ssp_with(spec, out, ssv: bool)` を足し、`write_ssp` は `ssv = false` の別名にする | 既存の呼び手（facade・Python 以外）を変えず、既定の出力を変えない |
| `start` のある Component ごとに `resources/<名前>.ssv`、SSD は `ParameterBinding source="resources/<名前>.ssv"` | 読み取り (t) が受ける形そのまま。名前は検査済みの FMU の名前なので `resources/` の外へ出ない |
| 値の組み立て・名前の escape はインライン版と同じ行を使う | 型の検査（有限の Real・整数の Integer・0/1 の Boolean）を二重に持たない |
| 型の要素は `ssv:Real`・`ssv:Integer`・`ssv:Boolean` | 仕様のリポジトリ v2.0.1 の XSD が `elementFormDefault="qualified"`（[調査](../../research/ssp-2026-11-15.md)） |

詳しくは [ADR-0026](../../adr/0026-fmi-import-placement.md) の (y)。

## 3. 図

```text
spec.json ──ssp-export --ssv──▶ SystemStructure.ssd（ParameterBinding source=...）
                              + resources/<名前>.fmu + resources/<名前>.ssv
cosim ◀── 読み戻す（(t)）── 同じ start・同じ CSV
```

## 4. 結果と、やらなかったこと

- 試験: `ssp.rs` に 1 本（読み戻した `start` がインライン版と同じ、`.ssv` の名前空間・要素名、`start` の無い Component に `.ssv` が無い）、`fmu_cosim.rs` の往復の試験に `--ssv` の場合を足した（CSV がバイトで一致）。
- やらなかったこと: 1 つの `.ssv` を複数の Component で共有する書き方、`.ssm` の書き出し、UI・LSP からの `--ssv`。
