## 1. 目的

[roadmap](../../roadmap.md) の「エディタの言語サービス」の先頭にあった、参照・リネームが開いている文書の中にしか届かない穴（[S166](../S166-references-classes/解説書.md)）を、ワークスペースの根の下の開いていない `.mo` と、ライブラリ（`globe lsp -L`）のファイルに広げる。

## 2. 決定と理由

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 走査 | frontend の `collect_mo_files`（facade が再公開）。隠しフォルダは読まない。LSP の `collect_mo` は薄い包みにした | S212 で共通化した走査と食い違わない |
| 絞り込み | 名前を含まないファイルは `str::contains` で落とし、字句に分けない | MSL 約 2,500 本でも、読むだけで済むファイルが大半 |
| アウトライン | `Resolver::outline(path)` が、開いていないファイルを `scratch` に読んで引く | `class_hits` と `Resolver::definition` を変えずに、ディスクのファイルにも掛けられる |
| 参照 | `textDocument/references` はクラス名の上で、開いている文書、根の下、ライブラリの順に足す。`uri` は `file://` | 部品の参照は今まで通り同じ文書の中だけ |
| リネーム | `textDocument/rename` の `changes` に、自分・開いているほかの文書・根の下の開いていない `.mo` を入れる。ライブラリのファイルは入れず、`window/showMessage` で「ライブラリの N 箇所は変えない」 | ライブラリは利用者の持ち物でない。VS Code は `changes` の開いていないファイルを開いて適用する |
| UI の `globe/*` | 変えない（メモリ上の文書だけ。ほかの開いた文書に参照があれば断る） | 配列の応答は複数ファイルを表せず、ディスクの版は UI の未保存の本文と食い違う |
| S198 の守り | 「開いていない `.mo` に同じ名前の識別子があれば断る」を外した。ファイル名に対応する最上位のクラスを断る守りは残す | 一括編集で実際の参照を直せる。同名の部品や別のクラスは `class_hits` が除く |

## 3. 図

```text
カーソル: Defs.mo の model Base
  |-- 開いている文書          class_hits
  |-- 根の下の開いていない .mo  contains -> 読む -> class_hits  -> changes
  `-- ライブラリ (-L)         contains -> 読む -> class_hits  -> 参照にだけ出す
```

届く範囲の前後は次のとおり。

| 場所 | 参照（前） | 参照（後） | リネーム（前） | リネーム（後） |
| --- | --- | --- | --- | --- |
| 開いている文書 | ○ | ○ | 断る | `changes` に入る |
| 根の下の開いていない `.mo` | × | ○ | 同名の識別子があれば断る | `changes` に入る |
| ライブラリ | × | ○ | × | 変えない（知らせる） |
| 継承した部品・`import` の別名 | × | × | × | × |

## 4. 測定

MSL 4.1.0（`-L data/msl`、release の `globe lsp`）で、`Modelica.Blocks.Interfaces.RealInput` の使い方の上の `textDocument/references`。

| 呼び出し | 時間 | 結果 |
| --- | --- | --- |
| 初回（213 本のアウトラインを `scratch` に読む。木の構築は含まない） | 2.0 s | 465 箇所、213 ファイル |
| 2 回目以降 | 0.29 s | 同じ |

初回が目安の 1 s を超えるのは、213 本が実際に `RealInput` を使っていて、絞り込みでは減らせないため。読んだアウトラインは `scratch` に残り、ディスクで更新時刻が変わるまで使い回す。

## 6. 次回

- 継承した部品（`extends` の先の部品名）と `import` の別名のリネームは対象外。
- 開いていない `.mo` の中の、開いていない中間のパッケージの `import` を通る参照は引けず、リネームの `changes` に入らない。要るなら根の下の `.mo` の索引を持つ。
- UI の `globe/references`・`globe/rename` はメモリ上の文書のまま。
