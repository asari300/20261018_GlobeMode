S018 · 2026-10-22 · P3

初期化の結果を初期化系にもう一度入れて確かめる（GM-W10004）

Rumoca が解き直さない初期化を、GlobeMode のプリフライトで 2 回解いて見つける

残差は公開されていない。もう一度解いて動いたら警告。実行は変えない
目的

このセッションでやること

  • S016 で見つけた: MSL の EngineV6 は filter.x が t = 0 から参照と外れる。原因は Rumoca の初期化で、初期化方程式が読む関係式 v_rel < 0 を既定値 false の枝で解き、反転しても解き直さない
  • GlobeMode は初期化の後に初期化方程式を見ていないので、誤った初期値のまま黙って積分する
  • roadmap の候補 4「初期化の後の初期化方程式の検査」。Rumoca に残差を評価する公開の入口があるかは未確認だった
  • 決定は ADR-0020。実行系の結果は変えない（警告だけ）
決定と理由

決めたこと

項目決定理由
残差か解き直しか初期化系を 2 回解き、2 回目で動いたら警告eval_initial_residual は crate の中の trait で公開されていない。settle_initialization_system は公開
1 回目の作り方Rumoca の FMI ME の kernel と同じ順（初期化系 → 関係式の記憶 → 代数変数）、同じ許容誤差実行が始まる点をそのまま再現する
動いたと見る差max(10 tol, 1e-6) × max(1, |y1|, |y2|)Newton の丸めを拾わず、EngineV6（0.066 → 563）は拾う
警告の判定2 回目と実行の t0 の値が違うものだけ（run だけが出す）MSL の IMC_Initialize は 1 回目と 2 回目が違っても、初期イベントの反復で解き直され、実行は 2 回目から始まる
2 回目の失敗黙るTanksWithOverflow: 解いた点から homotopy の掃引をやり直すと収束しない。始まる点の誤りではない
実行変えない初期化の後の状態を差し替える公開の入口が無い。CLI と食い違わない
対象全部のモデル関係式の記憶以外の原因（固定点でない初期化）も拾う。費用は msl:sim で測る
置き場プリフライト（組み立ての lowering の結果、1 回）GM-W10002 と同じ実行時オブジェクトを使う（ADR-0016）
