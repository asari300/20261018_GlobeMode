## 1. 目的

[features.md](../../features.md) の「結果のプロット」の行で未だった、系列の選択・2 軸・パラメトリックを作る（P4、[roadmap](../../roadmap.md)）。
これまでの `Plot.svelte`（S042・S048）は simulate の列を全部 1 つの軸に渡し、チェックボックスで表示だけを切り替えていた。ChuaCircuit のように桁の違う変数が混ざると読めない。
ユーザーの方針は「先に全体の流れとして使えるアプリを完成させる」。見た目（ダークモードなど）は後回しにする。

## 2. 決定と理由

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 渡す系列 | 選んだ列だけを uPlot に渡し、選択・軸・x が変わるたびに作り直す | MSL の例題は列が数百ある。描かない列を uPlot に持たせない |
| 2 軸 | 選んだ系列ごとの「右」で scale を `y2` にする。軸は使う scale の分だけ出す | uPlot の `scales` と `axes` だけで足りる。系列の無い軸は出さない |
| パラメトリック | 「x 軸」の選択で x に時刻以外の列。uPlot は mode 1 のまま、x の範囲は列の最小・最大を渡す | mode 1 は x の範囲を両端の値から取るので、単調でない列では欠ける。mode 2 は凡例と scale の作りが変わる |
| 拡大 | パラメトリックのときだけ止める（`shortcut:` の注記） | uPlot の拡大は x が昇順の前提で添字を二分探索する |
| 選択の既定 | 新しい結果で先頭 3 本・左の軸・time に戻す（Svelte の書き換えのできる `$derived`） | 列が変われば前の添字は意味が無い |
| App.svelte | 触らない（props は `columns` のまま） | S125・S127 が近くを触っている |

## 4. 再現手順

```bash
cd src/Svelte
pnpm install --frozen-lockfile && pnpm check
CARGO_TARGET_DIR=<wasm-pkg のある target> pnpm build
cd ../.. && python -I src/Svelte/tests/test_ui.py
```

検証の結果（数字）:

- `pnpm check`: 260 ファイル、error 0・warning 0
- `test_ui.py`: ok。Decay で系列を外す・付け直す（`data-series` 0 → 1）、右の軸（`data-right=1`、軸は x と右の 2 本）、x を `x` に（`data-x=x`）。ChuaCircuit は列 44 本、x を `C1.v` にして `C2.v` を足した（系列 4 本）。10 万点の最初の描画 20.8 ms
