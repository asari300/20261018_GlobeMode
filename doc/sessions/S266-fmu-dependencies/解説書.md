## 1. 目的

Export した FMU の `modelDescription.xml` の `ModelStructure` に、出力と状態の導関数の `dependencies`（どの状態・入力に依るか）を書く。S224 で「出力ごとの依存の情報が無く持ち越し」とした件（[ADR-0031](../../adr/0031-fmi-export-p5a-first.md)、[roadmap](../../roadmap.md)）。

## 2. 決定と理由

仕様の調べは [research/fmi-model-structure-dependencies-2026-11-15.md](../../research/fmi-model-structure-dependencies-2026-11-15.md)。

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 依存の求め方 | `globe_mode_analysis::analyze_dependencies`。BLT の解く順（S256 の `solve`）にブロックを進め、ブロックの方程式が直接参照する既知の値と、参照する別ブロックの依存を足す | 代数ループは塊で 1 つの集合。新しいグラフ算法は要らず、集合の和だけ |
| 既知の値の取り出し | frontend の `structure.rs` が、入力・パラメータ・`time`・「言い切れない参照」を `KnownRefs`（IR、`DaeStructure` と同じ行の順）で別に返す | `DaeStructure` は入力・パラメータを既知として数えず、型の変更は 10 か所以上の構築に及ぶ。別の表にして既存の解析の鍵を変えない |
| 言い切れない参照 | 離散変数・`pre()`・条件・遅れなどを参照するブロックと、それに依るブロックは `None`（書かない＝すべてに依存） | 離散の更新を経由する依存を連続の依存として言い切ると、`dependencies` が偽になる |
| 版ごとの既知 | 2.0 は状態と入力。3.0 はこれにパラメータと `time` | 仕様の表（調査の 2 章）。2.0 の `time` は定義が無ければ暗黙の依存で書かない（P5b）。定義があれば並べる（P5a） |
| 書かないもの | `dependenciesKind`、`InitialUnknown(s)` の依存 | 省略は「構造なしですべてに依存」で、仕様どおり安全。初期化の既知（`initial="exact"` の変数）と初期方程式を別に解く必要がある |
| 置き場 | 変数の表への引き当ては `globe-mode-fmi` の `model_structure_dependencies`（P5a・P5b 共通）。P5b は `describe` で、P5a は Rumoca の XML への後処理（`export.rs` の `add_dependencies`、`<DefaultExperiment>`・Enumeration と同じ流儀）で書く | Rumoca のテンプレートは改変しない。P5a は入力を持つモデルを出せない（既存の制約）ので、P5a の依存は状態（と 3.0 のパラメータ・`time`）だけ |

## 3. 図

```text
CompiledModel ─► DaeStructure + KnownRefs ─► analyze_index ─► BLT（解く順）
        └─► unknown_dependencies: 未知数名 ─► {状態, 入力, パラメータ, time}
                                  │
        modelDescription の変数の表に引き当て ─► ModelStructure.dependencies
        （引き当てられない名前があれば、その未知数は書かない）
```

## 4. 再現手順

```bash
cargo test -p globe-mode-analysis dependencies_follow_the_solving_order
cargo test -p globe-mode-fmu --test fmpy model_description_writes_dependencies
cargo test -p globe-mode-fmu --test fmpy fmpy_drives_input_step      # FMPy の validate_fmu を含む
cargo test -p globe-mode-cli --test fmu_export exports_a
```

`LinearSystem`（入力 u、状態 x1・x2、代数変数 w）では y1 → {x1, x2, u}、y2 → {x1, x2}、der(x1)・der(x2) → {x1, x2, u}。`fmu-export.yml`（fmusim）は feature ブランチで回して結果を作業記録に書く。

## 5. 次回

`InitialUnknown(s)` の `dependencies`（初期化の既知を別に求める）、`dependenciesKind`（`constant`・`fixed`・`tunable`・`discrete`）、離散変数を経由する依存を連続の依存にする分解。
