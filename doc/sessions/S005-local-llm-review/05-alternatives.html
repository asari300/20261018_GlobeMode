B · MCP（houtini-lm）

つながるが、サーバ側のタイムアウトで結果が切れる

# 登録（local scope = このプロジェクトのこの PC だけ）
claude mcp add --scope local houtini-lm \
  -e HOUTINI_LM_ENDPOINT_URL=http://localhost:1234 \
  -e HOUTINI_LM_MODEL=prism-ml/bonsai-27b \
  -e HOUTINI_LM_THINKING=off \
  -e HOUTINI_LM_MIN_TOKENS=512 \
  -- npx -y @houtini/lm@3.3.4
claude mcp list          # ✓ Connected を確かめる
# 試した後に外す
claude mcp remove --scope local houtini-lm

C · Claude Code を丸ごと向ける

ANTHROPIC_BASE_URL で動くが、この PC では遅すぎる

# そのコマンドだけに環境変数を付ける（本体のセッションに影響させない）
ANTHROPIC_BASE_URL=http://localhost:1234 \
ANTHROPIC_AUTH_TOKEN=lmstudio ANTHROPIC_API_KEY= \
CLAUDE_CODE_ATTRIBUTION_HEADER=0 \
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1 \
ANTHROPIC_DEFAULT_HAIKU_MODEL=prism-ml/bonsai-27b \
  claude --bare -p "Reply with the single word: pong" \
    --model prism-ml/bonsai-27b \
    --output-format json --max-turns 1
  • 結果は "pong"。入力 1,197 トークン、出力 99 トークン、最初のトークンまで 178 秒
  • --bare は hooks・スキル・MCP・CLAUDE.md を省き、システムプロンプトを最小にする
  • それでも、Claude Code はこのモデルの ctx を 200,000 と仮定した（contextWindow）。12K を超えるとエラーになる
  • LM Studio の公式の手順は 25K 以上の ctx を勧めている。Claude 以外のモデルは Anthropic のサポート外
  • ファイルを読ませるレビューでは入力が数千トークンになり、1 回で 10 分を超える見込み
D · hooks / サブエージェント

自動化はしない。サブエージェントでも接続先は変えられない

hooks（Stop / PostToolUse）

  • Stop フックが exit 2 を返すと会話が続き、出力が Claude に渡る。command のタイムアウトの既定は 600 秒
  • この PC では 1 塊に 10〜20 分かかり、毎ターンの終わりに会話が止まる
  • 小さいモデルの誤検知を、毎回 Claude が確かめることになる

サブエージェント

  • model に書けるのは sonnet / opus / haiku / fable / 完全なモデル ID / inherit
  • base URL をサブエージェントごとに変える欄は無い。接続先はセッションで 1 つ
  • →「Bonsai のサブエージェント」は作れない。スキルからスクリプトを呼ぶのが素直

出典: code.claude.com/docs の hooks、sub-agents、llm-gateway、headless（確認 2026-10-18）。
