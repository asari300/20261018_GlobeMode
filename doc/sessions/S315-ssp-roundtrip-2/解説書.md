## 1. 目的

SSP の往復の残り 2 つ。(1) `.ssp` から `fmu cosim` の spec.json への逆変換。(2) 名前に `.` を含む FMU（入れ子の System を平坦化した結果）を `write_ssp` が書くとき、入れ子に戻すかフラットなままか。

## 2. 決定と理由

| 決めたこと | 理由 |
| --- | --- |
| `globe fmu ssp-import <ssp> -o <dir>/spec.json [--stop-time] [--step]`。FMU は `<dir>/<名前>.fmu` に写し、JSON は相対パス | `Ssp` は drop で展開先を消すので、JSON に FMU を残すには外へ出すしかない。base64 で埋めるより小さく、`spec.json` の形も変わらない。同名のファイルは上書きしない |
| `.` を含む名前はフラットな Component のまま書く | SSD の XSD は `name` に `.` を禁じない（`xs:string`、長さ 1 以上）。入れ子に戻すと System のコネクタの素通しを書く必要があり、読み取り (w) の逆をまるごと書くことになる |
| `write_ssp` の名前の検査を「`.` でつないだ英数字・`_`・`-`」と 1024 バイトまでにし、`<FMU の名前>.<変数名>` は一番長く合う名前で割る | 読み取りと同じ規則にそろえる |

詳しくは [ADR-0026](../../adr/0026-fmi-import-placement.md) の (x)。

## 3. 図

```text
spec.json ──ssp-export──▶ system.ssp ──ssp-import──▶ dir/spec.json + dir/<名前>.fmu
入れ子の .ssp ──ssp-import──▶ s.a・s.b（フラット） ──ssp-export──▶ フラットな .ssp ──cosim──▶ 同じ CSV
```

## 4. 結果と、やらなかったこと

- 試験: `globe-mode-fmi-import` の `ssp.rs` に 1 本、`globe-mode-cli/tests/fmu_cosim.rs` に 2 本（逆変換の往復で CSV がバイト一致、入れ子の読み → 書き → 読みで CSV が一致）。
- やらなかったこと: 入れ子の System への書き出し（元の入れ子の形は残らない）、`.ssv` の書き出し、UI・LSP から `ssp-import` を呼ぶ口。

## 5. 再現手順

```bash
cargo test -p globe-mode-cli --test fmu_cosim   # data/reference-fmus が要る（cargo xtask fetch-reference-fmus）
```
