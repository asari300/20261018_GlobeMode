## 1. 目的

[S220](../S220-lsp-folding-indent/解説書.md) が持ち越した、Svelte の UI（CodeMirror 6）の折りたたみ。ブラウザ・Desktop・Android の同じ UI で、LSP の `textDocument/foldingRange` と同じ範囲（クラス・節・複数行の annotation・連続コメント）を畳めるようにする。

## 2. 決定と理由

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 範囲の計算 | Rust の `globe_mode_lsp::folding::folding_ranges` をそのまま呼ぶ | 新しい計算を書かない。LSP と UI の範囲が食い違わない |
| wasm | `Workspace.folding_ranges(file, text)`（先に `set_file`） | クラスと節の範囲に文書のアウトラインが要る。補完・ホバーと同じ呼び方 |
| Desktop | sidecar の `textDocument/foldingRange`。`shell.rs` の `RPC_METHODS` は 20 本 | 新しい method を作らず、LSP の既存の応答をそのまま使う |
| Backend | `foldingRanges(file): Promise<{startLine, endLine}[]>` | `setFile` 済みの file に対する問い合わせで、hover などと同じ形 |
| 取り直し | 入力が 300 ms 止まったら `setFile` と `foldingRanges`。応答が来たときに文書が変わっていれば捨てる | `foldService` は同期で、打鍵ごとに往復させない。検査（lint）は 500 ms の別の往復で、そこには相乗りしない（`file` を知らない・結合を避ける） |
| 印の引き直し | `foldGutter({ foldingChanged })` | 範囲の到着は文書の変更でも構文木の変更でもなく、既定では印が更新されない |
| 空の文書 | Backend に送らない | 結果のタブ（S222）は空のエディタで、`setFile` に結果のファイル名を渡さない |

## 3. 図

```text
model Decay            <- 印（⌄）。畳むと 0〜3 が隠れる
  Real x(...);
equation               <- 印。2〜3
  der(x) = -x;
end Decay;             <- 畳んでも残る
```

## 4. 再現手順

```bash
export CARGO_TARGET_DIR=<main>/.git-worktree/target-shared CARGO_BUILD_JOBS=2
mise run wasm:node      # smoke.mjs の「折りたたみ」: [[0,5],[2,5],[4,5]]
mise run ui:check       # test_ui.py: 印を押すと end Decay; が隣に来て、開くと戻る
```

## 5. 次回

- 構文が壊れてアウトラインが引けない間は、クラスと節の印が出ない（コメントと annotation は出る）。
- 畳んだ状態は再読み込みでは戻らない（タブの切り替えでは EditorState ごと残る）。
- Leptos・Dioxus の UI は未。
