annotation の行コメントと ,

issue #63: 並べ替えた引数の後ろの行コメントのせいで , が次の行の頭に出る

行コメントを引数に付け、, をコメントの前に置く
原因

コメントは次の引数の頭に付いていた

  • Icon(…), // b の // b は、字句を , で切る括弧の木（layout::seq）では次の引数の最初の字句
  • 名前で並べる annotation::position_in は先頭の字句を見る。コメントが先頭だと「その他」になり、並べ替えが外れる／コメントが取り残される
  • コメントが , の前（a // c の次の行に , b）だと、, は行コメントの後ろで改行され、行頭に出る
  • これは annotation だけでなく、どの括弧の引数でも同じ（修飾子 start = 1, // s、関数の引数）
直し

Arg.trail を足した

  • layout::Arg に trail（引数と同じ行の末尾の行コメント）。木を作るとき、区切りの直後の同じ行のコメントと、引数の末尾のコメントを入れる
  • 描画は 引数 → , → コメント。次の引数は必ず改行。flat（1 行に収める）はコメントがあれば断る
  • 並べ替えは Arg ごと動かすので、コメントは引数と一緒に動く。annotation.rs は Arg の作り直しの 3 か所に trail: Vec::new() を足しただけ
前後

同じ入力が、こうなる

入力（annotation の引数）前後
Doc, // a / Icon, // b / experiment // c並べ替えず、// a が別の行で字下げが崩れるexperiment, // c / Icon, // b / Doc // a
Doc // a の次の行に , Icon // b…, が行頭に出る上と同じ（2 回目で変わらない）

残したこと

  • コメントだけの行にあるコメントは、次の引数の頭に付いたまま。その引数は名前で位置を決められず「その他」（後ろ）に回る
  • 引数と同じ行の /* … */（ブロックコメント）は対象外。行コメントだけ
