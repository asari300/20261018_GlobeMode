### 参照・リネームが届く範囲（コードで確かめた）

| 入口 | 参照 | リネーム | 根拠 |
| --- | --- | --- | --- |
| LSP `textDocument/references`・`rename`（VS Code など） | 開いた文書・根の下の開いていない `.mo`・ライブラリ。部品は継承した先と `b.x` へ | `changes` に自分・開いた文書・根の下の `.mo`。ライブラリは変えず知らせる | `globe-mode-lsp/src/lib.rs` の `component_files`・`disk_class_hits`（S230・S235） |
| UI の `globe/references`・`globe/rename`（Desktop の sidecar） | `definition::references_at`。開いている 1 文書の中 | `definition::rename_at`。1 文書の中。ほかの開いた文書にそのクラスへの参照があれば断る | `lib.rs` の `globe/*` の分岐（`disk` は `textDocument/` だけ） |
| wasm の `references`・`rename`（ブラウザ・Android） | 同じ `references_at`・`rename_at` | 同じ | `globe-mode-wasm/src/lib.rs` |
| UI のエディタ（`Backend.references`・`rename`） | `App.svelte` は現在のタブだけを `setFile` して呼ぶ | 同じ | `src/Svelte/src/App.svelte`、`tauri-backend.ts`・`worker-backend.ts` |

- UI の部品の参照は `component_refs`（カーソルのあるいちばん内側のクラスの中の字句の一致）で、S235 の `component_hits`（継承した先・`b.x`）は LSP の `textDocument/*` だけが使う。UI のリネームは継承した部品を断る。
- `import` の別名（S235 の `alias_at`）は `references`・`rename` の共通の関数に入っているので、UI でもその文書の中で届く。
- S230 の解説書が「UI の `globe/*` は変えない」と決めた理由（配列の応答は複数ファイルを表せず、ディスクの版は UI の未保存の本文と食い違う）は今も有効。UI の範囲を広げるには、応答の形を変える必要がある。
