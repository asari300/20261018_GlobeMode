## 1. 目的

C ABI（`globe-mode-c`）と NIF（`globe-mode-nif`）のレビューの指摘 1〜6 を直す。読んで論証しただけの指摘なので、1 件ずつ再現してから直した。再現できないもの（未定義動作、Drop の panic）は新しい挙動を試験で固定した。

## 2. 決定と理由

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| `set_file`（指摘 1） | DirtyIo | Mutex を待つだけで CPU を使わない。DirtyCpu はスケジューラ数と同じ本数で、`+S 1` では 1 本なので待つ `set_file` が実行の席を取る |
| `format`・`lint`（3） | DirtyCpu | 本文の長さに比例（1 MB の `lint` が 2.3 s） |
| 再入の守り（2） | 使用中の印 | 注意書きだけでは未定義動作が残る。印は生のポインタからそのフィールドだけを読み、`&mut GmWorkspace` も、印を見る前の `&mut Workspace` も作らないので、実行中の `&mut Workspace` と別名にならない |
| `gm_workspace_free`（2・6） | 使用中なら放さず stderr に 1 行。Drop は `catch_unwind` の中 | 戻り値のない関数で、署名を変えない。放すのは実行が返ったあとにやり直す |
| 重複（5） | facade・exec に公開の関数 4 つ | 応答の JSON を変えず C と NIF から消す。Python・wasm・LSP は別の作業が触っているので持ち越し |

### NIF とスケジューラ

| NIF | スケジューラ |
| --- | --- |
| `new` `load_dir` `set_file` `export_fmu` | DirtyIo |
| `check` `graph` `outline` `deps` `flat` `simulate` `simulate_observed` `simulate_columns` `format` `lint` | DirtyCpu |
| `cancel_token` `cancel` `solvers` | 通常（Mutex を取らない定数時間。`cancel` は実行中でも即座に返る必要がある） |

## 4. 再現手順

```bash
export CARGO_TARGET_DIR=<main>/.git-worktree/target-shared CARGO_BUILD_JOBS=2
cargo test -p globe-mode-c -p globe-mode-exec
mise run c:zig && mise run c:julia && mise run elixir:test && mise run gleam:test
```

検証の結果（数字）:

- 旧 `.so` で `scheduler_test.exs`（通常のスケジューラを 1 本に絞る）は、`set_file` で 4506 ms、`lint` で 2209 ms（`format` と合わせて 4020 ms）止まって落ちた。直した後は通る。
- Zig・Julia の試験は、コールバックの中の `gm_check` が誤りを返し、`gm_workspace_free` が何もせず、その後も `ws` が使えることを確かめる。
- Miri は環境に無く回していない。
