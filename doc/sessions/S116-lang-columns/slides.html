列の道を C ABI と NIF に

S110 の埋める順の 4。CSV の入った JSON でなく、列ごとの f64 で結果を受け取る

simulate_columns が C・Zig・Julia・Elixir・Gleam でも使える
目的

このセッションでやること

  • 列の道は Python（S085）と wasm（S051）にだけあり、組み立てを別々に持っていた
  • facade に Simulated::columns を足して寄せ、C ABI と NIF に写す
  • 各言語の試験に「Decay の列の道で x(1) が JSON の道と同じ、点の数も同じ」を 1 本ずつ
  • 持ち越し: FMU export の facade、進捗と中断
決定と理由

口ごとの形

口形
facadeSimulated::columns() -> (ColumnsLayout, Vec<&[f64]>)（借用。写すのは束ね）
C ABIgm_simulate_columns(ws, model, settings, double **data, size_t *len) → {"response","names","points"}、列は 1 本の連続した配列。gm_doubles_free で放す
Zig・JuliaC を呼ぶ。Julia は配列に写してから放す
Elixir・GleamNIF の simulate_columns/3 → {layout_json, [binary]}（DirtyCpu、little-endian）
Python・wasm形は変えず、中を facade に寄せた

外部の依存の追加は 0。CI の定義は変えていない（ジョブ lang が同じ試験を回す）
