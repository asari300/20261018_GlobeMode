## 1. 目的

SSP（System Structure and Parameterization）2.0.1 の `.ssp` を読み、S249 のコシミュレーションのマスターで回す最小版（[roadmap](../../roadmap.md) の P8、[features](../../features.md) の SSP 2.0 の行）。

## 2. 決定と理由

詳細は [ADR-0026](../../adr/0026-fmi-import-placement.md) の (r)、仕様の要点と出典は [調査](../../research/ssp-2026-11-15.md)。

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 置き場 | SSD の XML は `globe-mode-fmi` の `ssp.rs`、zip の展開と変換は `globe-mode-fmi-import` の `ssp.rs` | roxmltree と zip は既にある。XML だけの部分は wasm32 でも通る。**依存は増えていない** |
| 入口 | `globe fmu cosim` が拡張子 `.ssp` を受ける（`--stop-time`・`--step`）。facade は `Ssp` を再公開 | 回すのは S249 のマスターそのまま（FMU は別プロセス）。小さい |
| 刻み | SSD に無いので引数。既定は (終了 - 開始) / 100。終了時刻は `DefaultExperiment` | SSP の `DefaultExperiment` は刻みを持たない（5.1.1） |
| 向き | FMU の causality で「出力 → 入力」に揃える | SSP の start / end はデータの向きではない（5.3.2） |
| 範囲外 | 入れ子の `System`・`ParameterBindings`・`SignalDictionary`・`LinearTransformation`・単位の名前が違う接続・Real 以外・システム自身のコネクタへの接続は明確な誤り | 黙って無視すると結果が変わる |

## 3. 図

```text
system.ssp ─► Ssp::open ─► 展開（zip slip・サイズ上限）─► SystemStructure.ssd ─► parse_ssd
                                                         │ Component / Connection / DefaultExperiment
                                                         ▼
                                   CosimSpec（FMU は展開先、向きを揃えた結線）─► run_cosim ─► CSV
```

## 4. 再現手順

```bash
cargo xtask fetch-reference-fmus
cargo test -p globe-mode-cli --test fmu_cosim
cargo test -p globe-mode-fmi ssp
globe fmu cosim system.ssp --step 0.1 -o out.csv
```

試験は Dahlquist（2.0）と Feedthrough（3.0）を入れた `.ssp` を試験の中で zip に組み、入力側を start に書いた接続でも JSON の spec と同じ CSV になることと、入れ子の `System` を断ることを見る。
