決定と理由 · アダプタ

MSL を読むために、Rumoca の CLI と同じ経路に合わせた

最初は S1 で止まった

model_names() と compile_model_phases() が、MSL を解決したときの警告（WR006 Evaluate、WR001 pure の宣言）まで失敗として返していた。

直したこと

  • コンパイルを compile_model_strict() に（Rumoca の CLI と同じ）
  • モデル名の事前確認は、ユーザーのファイルだけのときに限る
  • ライブラリは load_source_root_tolerant（DurableExternal）で読む。読めなければ GM-E1003

課題

正しい例題が「モデルの誤り」として出てしまう

CoupledClutches と Friction

MSL の正しい例題（OpenModelica では実行できる）だが、Rumoca は ED001（数が合わない）で止まる。GlobeMode は今これを S5 / GM-E5002 と出している。

クラッチや摩擦のモード切り替え（離散と連続の組み合わせ）を、Rumoca がまだ数え切れていないと考えられる【未確認】。

P2 で検討すること

  • 「コンパイラが未対応」を GM-U として分ける規則（例: MSL の例題での ED001）
  • Rumoca の上流に報告する
  • Filter の ED019 も同じく調べる
決定と理由 · CI

CI は差分のまま、重い突き合わせは全体のときだけ

  • 判定（ci_plan.py）に xtask を加えた。msl-compare.txt だけを変えたら xtask だけを検査する（最初に当たった規則を使う）

  • msl ジョブ: fetch-msl → fetch-rumoca → msl-compare。data/msl と data/rumoca は actions/cache v6 で使い回す。報告は artifact に残す
  • 判定のテストは 12 件から 15 件に。actionlint の指摘 0 件
