## 1. 目的

ユーザーの要望（2026-11-15）「比較閾値（10E-n）を指定してシミュレーションし比較」に近い数字も出す。S322 の比較は矩形の管で、出るのは管の外の点の数・最大のはみ出し量・最初の時刻だけだった（[ADR-0040](../../adr/0040-multi-solver-compare.md)）。管の判定は残し、変数ごと・ソルバごと・全体の**最大の相対差と最大の絶対差**を足す。

## 2. 決定と理由

| 決めたこと | 理由 |
| --- | --- |
| 判定は管のまま。相対差は数字として足す | 判定を相対差にするとゼロ交差の近くで閾値が安定しない（ADR-0040 決定 4）。管の判定と数え方を 2 か所に書かない |
| `compare::deviations` を別の関数にした（`compare` と `SignalComparison` は変えない） | MSL の参照結果の比較（xtask）と同じ型を使っているので、そちらの JSON と報告を動かさない |
| 基準の出力点の時刻に試験側を線形補間し、`\|a-b\| / max(\|b\|, 範囲 × 1e-12, MIN_POSITIVE)` | 0 割りを避ける最小の下駄だけにする。管の `δy` のような大きな下駄は、相対差の意味を変える |
| イベントの同じ時刻の行は、m 番目どうしを比べる | 左極限と右極限をそれぞれ比べ、跳びの前後を混ぜない |
| `comparison.pairs[i]` に `max_rel`・`max_abs`・`worst`、`failures[]` と全体にも | 既存のキーは変えず、足すだけ。比べた点が無ければキーを出さない。NaN の点は無限大で JSON は null |
| UI は比較の表に列を足し、`< 1e-6` か `≥ 1e-6` を文字で出す | 色だけに頼らない。有効数字 3 桁の指数表記 |

限界: 基準が 0 を通る点の近くでは相対差が大きく出る（範囲 2 の信号が 0 の点で 1e-6 ずれると 5e5）。合否と相対差が食い違うことがあるので、相対差は参考とする。
