## 1. 目的

[ADR-0037](../../adr/0037-icon-diagram-as-shape-data.md) の次。S244 の Icon ビューに続けて、Diagram ビュー（読み取り専用）を足す。カーソルのクラスの部品を、部品のクラスの Icon で `Placement` どおりに置き、`connect` を線で結ぶ。編集（ドラッグ・接続）はしない。

## 2. 決定と理由

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 渡す形 | S244 と同じ形のデータ（JSON）。部品は `transform`（行列）と部品のクラスの Icon の図形、connect は `Line` の図形 | UI は図形を描くだけ（`ShapeView.svelte` を Icon と共用）。Leptos・Dioxus・VS Code も同じ JSON を描ける |
| 読み方 | `globe-mode-fmt/src/diagram.rs`（`icon.rs` の隣）。字句解析・`split`・`class_spans` だけ。宣言は「型 名前 … `annotation(Placement(transformation(…)))`」の形 | Rumoca の構文解析も新しい依存も足さない |
| 部品 | Placement に `transformation` がある宣言だけ。`visible = false`・Placement が無い・`extent` が読めないものは飛ばす。配列（`R[3]`）は 1 つ | 描けるものだけを描く。パラメータなどは Placement が無いので出ない |
| 型の解決 | `import` の別名・`import A.B.*;`、内側から外側へのスコープ、の順。引けた型の Icon を `%name` を部品の名前にして引く（`extends` は 1 段）。引けなければ空のアイコン（UI は破線の枠） | MSL の部品はほぼ完全修飾名。ライブラリの中の相対名は外側のスコープで引ける |
| 変換 | Rust が行列 `[a, b, c, d, e, f]`。Icon の枠を Placement の `extent` に写し、`extent` の向きが逆なら反転、`origin` を中心に `rotation` 回す。UI は y を反転した座標に直して `<g transform="matrix(…)">` に置く | 数式を UI に置かない。反転は Modelica の規則（`extent` の点の順） |
| connect | `Line(points)` があればその折れ線（色・太さ・パターンも）、無ければ 2 つの部品の中心を結ぶ直線。端が部品でなく `Line` も無いものは飛ばす | 依頼のとおり |
| Diagram の枠 | `coordinateSystem(extent)`。無ければ部品・線が収まる枠（何も無ければ -100〜100） | 仕様の既定だと枠の外の部品が切れる |
| 口 | wasm `Workspace.diagram(class, text, line, character)`、LSP `globe/diagram`（`RPC_METHODS` 24 から 25）、`Backend.diagram(cls, at?)` | `icon` と同じ探し方 |
| UI | 右のパネルに「説明 / 図」のタブ。図のタブは幅 30rem・高さ 22rem。部品のクリック（Enter）で宣言の行へ（`App.svelte` の `onJump`）。地は常に明るい | App の変更は状態 1 つと `onJump`。新しい部品は `lib/` |

読まないもの: `extends` で継いだ部品、`import A.{B, C}`、`iconTransformation`、`DynamicSelect`、反転した部品の文字（鏡像のまま）、編集。


## 4. 再現手順

```bash
export CARGO_TARGET_DIR=…/target-shared CARGO_BUILD_JOBS=2
cargo test -p globe-mode-fmt --lib diagram
cargo test -p globe-mode-lsp --lib diagram
cargo test -p globe-mode-wasm --test decay diagram
mise run wasm:node       # smoke.mjs: 文書の図、MSL の ChuaCircuit は部品 7・connect 9
mise run ui:check        # pnpm check と test_ui.py の diagram_view
```

MSL の例題 20 本（`src/Modelica/msl-compare.txt`）の結果は、部品 174・connect 178・Diagram の図形 21 で、部品のアイコンはすべて引けた（空 0）。ソースを正規表現で数えた `connect(` と `Placement(transformation` の数と、独立したファイルを持つ最初の 13 本（Electrical・Mechanics・Thermal.HeatTransfer）はすべて一致した（残り 7 本は package.mo の中の入れ子のクラスで、数えていない）。
