## 1. 目的

S322 が作った `Backend.simulateMany` を、実行の設定の画面から使えるようにする。ユーザーの要望（2026-11-15）は、複数のソルバを選ぶ（既定は 1 つ、複数はチェックボックス）、1 つずつか並列かを選ぶ（既定は 1 つずつ）、全部終わったあとに自動で比べる（既定は off。最大積分次数・許容値・閾値 10^-n を指定）。判断は [ADR-0040](../../adr/0040-multi-solver-compare.md) の付記、機能表は [features.md](../../features.md)。

## 2. 決定と理由

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 欄の置き場 | 既存の `SimSettings.svelte`（`fieldset`・`legend`）。依頼の分は `many` として App に渡す | 設定のモデルごとの保存（S228）にそのまま乗る |
| 許容誤差・最大次数 | 1 つの欄を全部の実行に渡す。最大次数は 1〜5 の整数 | S322 の依頼の形（`settings` は全部に同じ） |
| ブラウザの並列 | 選べるが「ブラウザでは 1 つずつ回す」と出し、応答の `mode_note` も表に出す | wasm は逐次に落ちる（S322） |
| 重ね描き | 列を時刻の和集合に折れ線で補い、`x [bdf]` の名前で 1 つの `Columns` にする | `Plot` を変えずに凡例がソルバ名になる。出力の間隔が同じなら補いは起きない |
| 表 | 実行の表と比較の表（`<table>`、見出し行つき）。合否・状態は文字 | 色だけに頼らない |

## 3. 図

```text
SimSettings (many) → App.simulateMany → Backend.simulateMany
                                     → mergeRuns → Plot（重ね描き）
                                     → ManyResult（実行の表・比較の表）
```
