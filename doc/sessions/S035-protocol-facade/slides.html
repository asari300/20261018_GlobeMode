protocol と facade

計画書の WP-0。UI・LSP・Python・wasm が依存する 2 つの crate を作った

CLI と wasm を globe-mode 経由にし、JSON は 1 バイトも変えない
目的

このセッションでやること

  • S033 の計画書で決めた「次の 1 回は protocol と facade」を実施する
  • globe-mode-protocol: CLI の --json と wasm の JSON の serde 型
  • globe-mode: Workspace が検査・グラフ・コンパイル・実行を束ねる facade
  • 新しい計算は入れない。db・exec・sim・frontend・analysis の中身は触らない
  • ここが並行化の分岐点。次から WP-A / B / F / G を同時に始められる
決定と理由

決めたこと

項目決定理由
protocol の型今の JSON の形をそのまま struct に後方互換。serde_json は preserve_order が有効なので struct の順 = JSON の順
simulate_with(request, now)検査 → コンパイル → 実行を 1 本に。時計は引数CLI と wasm が別々に持っていた。wasm32 は std の時計が無い
Simulated { response, run, compiled }JSON と Rust だけの結果を分けるCLI は MAT に時系列とパラメータが要る。wasm の応答は太らせない
CLI の文字の表示ws.db().check_model() のまま未知数の一覧まで読む。--json だけ protocol の型にすれば外から見える形は守れる
断る文言--force → forcefacade は CLI のフラグ名を知らない。JSON で唯一の変化
JSON Schema持ち越しcore・ir・analysis の約 50 の型に derive が要る。WP-B が要るときに
