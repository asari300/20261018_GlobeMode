| #118 LSP の相対 `--library` で定義ジャンプの URI が `file:///data/msl/...` になる（Should） | 妥当（`file_uri` は `/` で始まらないパスに `file:///` を前置するだけ。#115 の `same_path_key` は比べる側だけで、返す URI は相対のまま。コードの読みと報告の出力が合う） | 直した | URI を作る共有の関数 `file_uri` の先頭で、`/` 始まりでも `C:` 始まり（`\` は先に `/` にしてある）でもないパスを `std::path::absolute`（相対なら cwd を足す。`same_path_key` と同じ道具）で絶対にした。定義・参照・リネーム・ライブラリの診断の URI がすべてこの 1 か所を通る。Windows のドライブ文字は絶対の判定でそのまま残し、絶対にした後の `\` は `/` にそろえる | `globe-mode-lsp` の `file_uri_makes_relative_paths_absolute`（`uri_path(file_uri("rel/A b.mo"))` が cwd つきの絶対になる。直す前は `/rel/A b.mo` で落ちる。絶対とドライブ文字つきが変わらないことも見る） | 同じものを同じ形で扱う（パスは境界で一度だけ正規化する） |
| #119 `--solvers -o DIR` が書けない出力先を計算のあとで断り、`-o -` で `-` というフォルダを作る（Nice） | 妥当（`simulate` は `args.many.is_none()` のときだけ `check_writable_file` を呼び、`simulate_many` は計算のあとで `create_dir_all` する。`-` を標準出力として扱う分岐が無い） | 直した | 計算の前に `check_out_dir` で確かめる。`-` は誤り（標準出力へ複数の結果は出せない）、`dir` から上へたどって最初に在るものがディレクトリでなければ誤り（既存のファイルを指す・親がファイル）、ライブラリの中を指すのも誤り。終了コードは単独の `-o` と同じ 2。フォルダを作るのは結果を書くときのまま（依頼が断られたときに空のフォルダを残さない）。`prepare_out_dir` は FMU の `<out>/<名前>/` の作り直しの規則を含み、ここには合わないので使わなかった | `globe-mode-cli/tests/simulate.rs` の `solvers_check_the_output_and_names_before_running`（既存のファイルと `-` の 2 つを `-o` に渡すと、終了コード 2 で標準出力が空。`-` フォルダが無い。直す前は計算してから断る・`-` を作る） | 早く失敗する（高くつく仕事の前に、前提を確かめる） |
| #120 `bdf`・`BDF`・`Bdf` が重複と見なされない（Nice） | 妥当（facade の `many_request_problem` は文字列の完全一致。ソルバ名の解決は `trim`・`to_ascii_lowercase`。CLI の `-o DIR` は依頼の名前をそのままファイル名にする） | 直した | `many_request_problem` で名前を `solver_key`（trim・小文字。`lookup` と同じ）にそろえて重複を見る。`compare.reference` の照合（`many_request_problem` と `compare_runs`）も同じ形で比べる。別名（`dassl` と `bdf`）は別の名前のまま。CLI の `-o DIR` のファイル名もそろえた名前にする。`--solvers bdf --compare 6`（1 つだけで比較）は「compare は solvers が 2 つ以上のときだけ（比べる相手が無い）」で断る（UI は 2 つ以上を要求しているので変わらない） | `globe-mode/tests/simulate_many.rs`（`["bdf","BDF"]`・`[" Bdf","bdf "]` が「2 回」で断られる。1 つで比較が「比べる相手」で断られる）と、CLI の同じ試験（`--solvers bdf,BDF` が終了コード 1 で「2 回」） | 同じものを同じ形で比べる（比較の前に正規化する） |
