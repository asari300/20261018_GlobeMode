## 1. 目的

FMI Import のコシミュレーションのマスターの最小版。複数の Co-Simulation の FMU（FMI 2.0 / 3.0）を固定の通信刻みでつなぎ、出力を入力へ受け渡して回し、全 FMU の出力を 1 つの CSV に出す（[roadmap](../../roadmap.md) の P5、[features](../../features.md)）。

## 2. 決定と理由

詳細は [ADR-0026](../../adr/0026-fmi-import-placement.md) の (q)。

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| アルゴリズム | Jacobi 型。刻みの頭で前の刻みの終わりの出力を入力へコピーし、全 FMU が同じ刻みを進む | 代数ループも実行順の決定も要らない最小の形 |
| 型 | Real（Float64）だけ。それ以外の端、出力でない始点、入力でない終点は実行の前に誤りにする | 黙って落とさない |
| 置き場 | `globe-mode-fmi-import` の `cosim.rs`。ワーカーの要求に省略可の `cosim` を足し、FMU の読み込みは今までどおり別プロセスの中 | 隔離を保つ。結果は `names`/`rows` のままなのでプロトコルは変わらない |
| 入口 | facade `run_cosim`、CLI `globe fmu cosim <spec.json> [-o out.csv]` | `run_fmu` と同じ `run_worker` を通すので timeout・中断も同じ |
| 結線の記述 | JSON `{"fmus": {...}, "connections": [["a.y","b.u"]], "start_time", "stop_time", "step", "timeout", "memory_limit_mib"}`。FMU のパスは spec.json からの相対 | 小さく、機械で書ける |

## 3. 図

```text
spec.json ─► globe fmu cosim ─► run_cosim ─► 子プロセス（fmu __worker）
                                              │ FMU a, b を <work>/a, <work>/b に展開して読む
                                              │ 刻みごと: a.out ─set_real► b.in、全 FMU を do_step
                                              ▼
                                       行（時刻, a.*, b.*）─► CSV
```

## 4. 再現手順

```bash
cargo xtask fetch-reference-fmus
cargo test -p globe-mode-cli --test fmu_cosim
globe fmu cosim spec.json -o out.csv
```

試験は Dahlquist（2.0）の `x` を Feedthrough（3.0）の入力につなぎ、b の出力が a.x の 1 刻み前の値にちょうど等しいことを見る。
