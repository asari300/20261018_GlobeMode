決定と理由 · deps_closure

識別子と、トップレベルのクラスの名前を突き合わせる

固定点（globe-mode-db の deps_closure）

  1. モデルの完全修飾名を定義するファイルを起点にする（Outline::defines）
  2. 構文の誤りのあるファイルは、いつも入れる（何を定義しているか分からない。S0 で止まる）
  3. 閉包の中のファイルの identifiers（本文の識別子。文字列の中は除く）にある名前ごとに、その名前をトップレベルに定義するファイル（class_files）を足す。増えなくなるまで繰り返す

モデルがワークスペースに無い（MSL の中のモデル、存在しないモデル）ときは空。文書を 1 つも渡さない。「見つからない」にはワークスペースのモデルを候補として足す。

入れ子のクラスを入れない理由

  • Components.mo の replaceable package Medium と、MediumFlow.mo の入れ子の Medium が同じ名前。入れ子まで数えると、無関係のファイルが入る
  • トップレベルだけで足りる: 入れ子のクラス T.N に届く道（修飾名、within、import、T を継承したクラス）には、必ず T か、T を名指すファイルが現れる

決定と理由 · S7 Pantelides 法

族ごとに階数を持ち、最高階だけをマッチングする

グラフと手順（pantelides.rs）

  • 状態 x の族は階数 0（x）と 1（der(x)）から、代数の族は階数 0 から始める
  • 方程式 e を d 回微分すると、参照（族 f、階数 o）ごとに階数 o..o+d を参照する。o + d[e] == top[f] のときだけ辺を張る
  • der の形の Hopcroft–Karp から始め、対応の無い方程式ごとに彩色つきの交互路を探す（再帰ではなくスタック）
  • 失敗したら、彩色した方程式を 1 回微分し、彩色した族の最高階を 1 つ上げて探し直す

S6 が構造特異でない（regular）ときだけ回す。S6 を通った構造なら、最後まで回せる。

IndexReport と診断

  • index = 微分の最大回数 + 1（微分が要らなければ 1）
  • dummy_candidates = 1 回以上微分した方程式が参照する状態
  • dynamic_states = 状態の数 + Σ（新しく作った微分のノード）− Σ（微分回数）。拡張した系の「未知数 − 方程式」= 積分器の数
コード重さ条件
GM-I7001Infoインデックス 2 以上（見込みと微分の内訳）
GM-I7002Info動的な状態 < 状態の数（状態選択の候補）
GM-E7001Error打ち切り（S6 を通った構造では起きないはず）

S6 の StructuralReport::diagnostics から GM-I7001 を外し、IndexReport に一本化した。

図 · 振り子の例

直交座標の振り子は、拘束を 2 回微分してインデックス 3

方程式（Index.Pendulum）微分の回数
der(x) = vx1
der(y) = vy1
der(vx) = lambda * x0
der(vy) = lambda * y - g0
x ^ 2 + y ^ 2 = L ^ 2（拘束）2
  • der の形では、拘束は状態だけを含むので、どの未知数とも対応づかない
  • 最高階: x・y は 2 階、vx・vy は 1 階、lambda は 0 階。新しく作った微分のノードは 2
  • 構造インデックス = 2 + 1 = 3。候補は x, y, vx, vy
  • fixed は x と vx の 2 つ。糸が水平（x = L）で x を固定すると 2y = 0 で y が決まらないので、x = 0.6 から放す
モデル状態＋ 新ノード− Σ 微分＝ 動的
Pendulum4242
ParallelCapacitors2011
HighIndexDuplicate1120

新ノード = 新しく作った微分のノード、Σ 微分 = 方程式の微分回数の合計。

最初の式は誤りだった

「状態の数 − Σ（状態の階数 − 1）」は、並列コンデンサ（v1 = v2 を 1 回微分するだけで、階数の上がる族が無い）で 2 になる。正しくは 1。

乱択のテスト: 3000 件で「S6 の index_reduction_needed ⇔ index >= 2」、1916 件で微分の回数が Pryce の Σ 法の最小のオフセットと一致（証明はしていない）。

決定と理由 · S8 初期化

初期条件の数と属性で判定し、Error は確かなときだけ

入力（InitStructure）

  • frontend が Rumoca の DAE から取り出す。状態・パラメータ・離散変数・代数変数のスカラーごとの fixed / has_start / has_binding と位置、初期方程式
  • has_start は明示された start。Rumoca は start を書かなくても既定の start を補う（式の位置が宣言と同じか、由来が DaeGeneration::DefaultStart）ので、それを除く
  • fixed = true の start は、ToDae では初期方程式にならない → 2 重に数えない
  • Real でない fixed = false のパラメータの式（initial_parameter_values()）と、離散変数の初期値（initial_discrete_values()）も初期方程式として数える

近似であること

  • 離散変数は pre(d) が初期化の未知数になる（MLS 8.6）ので、要る数に入れる
  • ただし、when の外の式で決まる離散変数（暗黙の pre(v) = v で初期条件が要らない）か、when の中かは InitStructure で区別できない
  • インデックスの低減で状態が減るとき、余った fixed が拘束と矛盾しないか（整合する冗長な初期条件か）は数値でしか決まらない
  • だから、離散変数を含むか状態が減るときの過剰は確定させず（GM-W8004）、不足が離散変数の数に収まるときは柔らかい GM-W8001 にする
  • 初期方程式の incidence（どれがどの変数を決めるか）は見ない（S008 以降）
