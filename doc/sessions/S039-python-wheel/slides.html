Python の wheel globe_mode

計画書の WP-G。facade を PyO3 で包み、maturin で既存の Python パッケージに入れる

入出力は JSON の文字列（wasm と同じ）。dict と polars の表は Python 側で
目的

このセッションでやること

  • 新しい crate globe-mode-py（PyO3 0.30、abi3-py312、facade だけに依存）
  • maturin で src/Python/mod/globe_mode の中の _native に入れる（uv_build から切り替え）
  • 参照シナリオ open → check → graph → simulate → 結果を表で読む、を uv run pytest で
  • 実装は計画書どおり Sonnet（effort high）のサブエージェント 1 人。Fable はコードを読み、検査と文書を担当
決定

小さく保つための判断

項目決定理由
型の受け渡しRust は JSON の文字列を返し、__init__.py が json.loadswasm と同じ形。pythonize を足さない。Rust の型を 1 つずつ写さない
結果の表table(res) が CSV を polars.read_csvpolars は既に依存にある。numpy は足さない
ビルドpyproject の build-backend を maturin にuv sync が wheel を作る。mise には入れない
CIpython のジョブに rust と rust-cache を足し、pytest を回す。facade の変更でも回すwheel が Rust をビルドするため（ci_plan.py）
スレッドunsendablesalsa のデータベースは Sync でない
