調べたこと · Rumoca の実行系

Rumoca v0.10.2 の実行系で分かったこと

外の driver から回せない

核 SolveMeKernel の導関数・イベント更新などは pub(crate)。差し替えられるのは数値積分のプラグイン MeIntegratorBackend だけ。自前の HybridSystem として包めない。

入口とソルバ

型付きの道（build_simulation → 初期化の確認 → 実行）は BDF だけで、失敗の段が分かる。ソルバは diffsol 0.13 の BDF と Dormand–Prince 5(4) の 2 つ。

時間切れは協調型

予算を見るのは積分の繰り返しと根探索だけ。初期化と積分器の 1 歩の内側では止まらない。Rumoca の MSL のハーネスも別プロセスを外から止める。

diffsol の修正版

Rumoca はルートの [patch] で diffsol 0.13.2 に BDF の修正を 4 件当てている。[patch] はルートでしか効かないので、git 依存では修正前の版が入る。

依存

wasm 以外では Cranelift の JIT が必ず付く。Cargo.lock の外部の package は 101 増えた（Windows の target と Cranelift 0.125 が多い）。ライセンスはすべて許可の区分。

無いもの

初期化系のヤコビ行列の階数を返す公開の API。wasm32 では BDF の道が Instant::now() を呼ぶので動かない見込み【未確認】。

rev 276e82bd のソースを読んだ（2026-10-19）。出典の行番号は doc/research/rumoca.md の「S011 で調べた実行系（v0.10.2）」。

決定と理由 · 選ばなかった案

自前の実行系と自前の driver は、まだ作らない

案選ばなかった理由
実行系を自前で作る（評価器・driver・ソルバ）P3 の 1 回目で MSL の例題を回せない。Rumoca は基準値で 216 本を回せる
Rumoca のモデルを自前の HybridSystem で包む公開の API では包めない。SolveRuntime の低い層は安定でない
diffsol を crates.io の版のままBDF の修正 4 件が入らず、Rumoca の数字と比べられない
時間切れを同じプロセスの協調型の予算だけで守る初期化と積分器の 1 歩の内側で止まらない
Rumoca の比較の指標を使う平均した L1 で、0.2% の管よりずっと緩い
参照結果を zip で一度に取る約 779 MiB（展開して約 2.7 GB）。要るのは OK の例題の分だけ

「Modelica と FMU は同じ driver」はどうなるか

  • Phase A では成り立たない。Modelica のモデルは Rumoca の driver で回す（architecture §3.3 に書いた）
  • 自前の HybridSystem と driver は、FMU の Import（P5）と Track B の自前コアで作る
  • Modelica のモデルを自前の driver に載せる道は (a) Rumoca の FMU の出力（C のコンパイラが要る）、(b) 低い層の SolveRuntime、(c) 上流に SolveMeKernel の公開を提案。決めるのは P5 の前
  • 自前の積分器（esdirk34・tsit45・固定刻み）は MeIntegratorBackend として差し込める見込み（S012 以降に試す）

t0 で有限にならないのは警告

eval_dae_at は start 値を状態に入れて評価する（初期化の残差ではない）。最初は Error にしていたが、骨格の段階で警告に変えた（092b888）。MSL では 3 本に出た: TestCylinder・TestOpenTank は GM-E11001 で止まり補足にこの警告が付き、TwoTanks は終了時刻まで進んで管にも収まった。

失敗の振り分け

  • Rumoca が付けた段（SimFailureStage・MeStage）→ エラーの種類（MeSessionError などを型で match）→ こちらが呼んだ位置、の順に見る
  • 型に無い 4 つだけ文言から読む: 時刻、有限でない変数の名前、位置、rk45 の lowering の [EX…] の印
  • 実行は検査段階ではないが、同じ形で返すため Stage::Run を足した

S012 — wasm の bdf と、止まった 54 本

候補（roadmap）

  1. bdf を wasm で（Node 上で）動かす（P3 の残りの完了条件）。getrandom の wasm_js、Instant::now() を呼ばない道
  2. 止まった 54 本と外れた 10 本を調べる。上流に報告するものを分ける
  3. 自前の積分器（esdirk34・tsit45・固定刻み）を MeIntegratorBackend として試す
  4. パラメータを変えた再実行（param_overrides）、MAT v4 / Arrow IPC
  5. S10 の残り: 初期化のヤコビ行列の階数
  6. S9 を omc と照らして詰める、閉包の切り替えの残り（持ち越し）
  7. Checker のメモリの上限（P4 の後）、Rumoca の制約の上流報告（ユーザーが出す）など

残したこと

  • globe-mode-exec は native だけ
  • dopri45 は組み立てから積分までを 1 回で呼ぶので、準備の時間が 0 になる
  • プリフライトは lowering を 1 回余計にする（eval_dae_at が自分で lowering する）
  • Rumoca の文言から読んでいる 4 つは、rev を上げたら exec のテストで確かめる
  • 次に Rumoca の rev か検査を変えたら、msl:funnel → msl:sim の順に回す
  • 上流への報告の候補に、SolveMeKernel が非公開、diffsol の修正、ヤコビ行列の階数の API、wasm の Instant::now() を足した
