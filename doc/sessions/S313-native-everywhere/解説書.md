## 1. 目的

[S305](../S305-check-native/解説書.md)・[S307](../S307-native-closure/解説書.md)・[S311](../S311-flat-ranges/解説書.md) で `globe check --frontend native` ができた。残りは、LSP・wasm・Python・UI から native を選べないこと。今回は facade・LSP・Python の 3 つに、検査の道を選ぶ口を足す。既定は Rumoca のまま。wasm・UI はやらない。

## 2. 決定と理由

| 決めたこと | 理由 |
| --- | --- |
| facade に `CheckFrontend { Rumoca, Native }` と `Workspace::check_with(model, frontend)`。`check` は `check_with(.., Rumoca)` | 既存の `check` の呼び出しを変えない最小の形。選び方は `FromStr`（`rumoca`・`native`）で CLI・TOML・Python が共有する |
| `Native` は、作業中のファイルと `with_libraries` のディレクトリを `NativeFrontend` に渡す | native は閉包をディスクから読む（S307）。`with_library_sources`（wasm）にはディレクトリが無いので、ライブラリが見えない |
| 応答の組み立てを `native_response` に出し、CLI の `check_native` と共有する | 同じ形（`summary` の文を含む）を 2 か所に書かない |
| feature `native` を facade・LSP に足し、CLI と Python が立てる。wasm は立てない | native の段の crate が wasm の build に入るため、大きさの測定の後に決める。立てない build で `Native` を選ぶと `GM-U0006`（この build に入っていない）で、黙って Rumoca に切り替えない |
| LSP は `globe-mode.toml` の `[check] frontend` を読み、`publishDiagnostics` の検査だけに使う | 設定ファイルの流儀（S130）に合う。`LintOptions::frontend`（文字列）に持ち、値は `from_toml` が `rumoca`・`native` に絞る。`globe/check` の要求は変えない |
| Python は `check(model, frontend="rumoca")` に引数を 1 つ | 既存の呼び出しはそのまま。知らない名前は `ValueError` |

詳しくは [ADR-0039](../../adr/0039-native-cst-parser.md) の付記（S313）と [format-style.md](../../format-style.md) の 5 章。

## 3. 図

```text
globe-mode.toml [check] frontend = "native"
  └ LSP diagnostics ──┐
Python check(frontend=) ┼─ Workspace::check_with(model, CheckFrontend)
CLI check --frontend ───┘      ├ Rumoca: 今までの検査（S0〜S10）
                                └ Native: NativeFrontend（S0〜S6。未対応は GM-U0006）
```

## 4. 結果と、やらなかったこと

- 試験: facade `tests/check_with.rs` 1 本（feature の有無で `GM-U0006`、既定は出さない）、LSP 1 本（設定で native にすると `expandable` が `GM-U0006`、設定が無ければ出ない）、pytest 1 本、`config` の単体試験に `[check]`。
- やらなかったこと: wasm・UI から選ぶこと（wasm のビルドの大きさを測ってから）。LSP の `globe/check`・補完など、`outline` 系を native にすること。

## 5. 再現手順

```bash
cargo test -p globe-mode --features native --test check_with
cargo test -p globe-mode-lsp --features native config_
uv run pytest src/Python/tests/test_api.py -k frontend
```

## 6. 次回

- wasm に native を入れたときのビルドの大きさと起動の時間を測り、入れるか決める。入れるなら UI に選ぶ口を足す。
- LSP の `globe/check` と補完・ホバーを native の道にするか決める。
