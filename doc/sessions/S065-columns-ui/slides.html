ブラウザ UI の列ごとの結果

S051 の持ち越し: wasm の列の API を UI につなぐ

CSV の解析をやめて、Float64Array をそのまま uPlot へ
目的

このセッションでやること

  • Backend に simulateColumns を足す（既存の simulate は残す）
  • ブラウザは GlobeWorker.simulateColumns、Desktop は CSV を解析して同じ形にする
  • Plot は列の形（Columns）だけを見る
  • Playwright で「列の道で来た」ことを確かめる
決定と理由

決めたこと

項目決定理由
Columns の形points を足し、data は ArrayLikeFloat64Array も number[] も同じ型で渡せる
Desktopsimulate の CSV を parseCsvsidecar に列の道が無い。UI は 1 つの形だけ見る
App の状態$state.raw$state は配列を丸ごと Proxy にして 10 万点で遅い
確認data-typed先頭の列が Float64Array かを属性に出す
結果

10 万点 × 4 状態の実行（Chromium、WSL）

CSV の道（前）列の道（後）
CSV の解析129.9 msなし
最初の描画まで151.3 ms20.7 / 27.0 ms
実行を押してから戻るまで810 ms222 / 213 ms
ChuaCircuit の実行1.3 s0.8 s
次回

残したこと

  • 列の道の NaN / Inf は uPlot の欠損にならない（CSV の道は null にしていた）
  • sidecar（Desktop）に列の道を足すかは未定
