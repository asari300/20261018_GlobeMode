ブラウザ UI の骨格（Svelte 5）

計画書の WP-B。Backend インターフェース、WorkerBackend（wasm を Web Worker で）、CodeMirror 6、診断パネル

UI のプロセスでは計算しない（ADR-0023）。計算は GlobeWorker 越しの wasm だけ
目的

このセッションでやること

  • src/Svelte に pnpm + Vite + Svelte 5 + TypeScript の最小の UI
  • Backend { setFile, check, simulate } と、S036 の GlobeWorker を包む WorkerBackend
  • CodeMirror 6 のエディタ、モデル名、「検査」、診断の一覧（段と重さで並べ、押すと範囲へ飛ぶ）
  • Tauri・プロット・グラフ・実行の UI は入れない。CSP は connect-src 'self' のまま
  • 実装は Sonnet（effort high）のサブエージェント 1 人。Fable はコードを読み、作り直しの無限ループを直した
決定

小さく保つための判断

項目決定理由
wasm の checkWorkspace::check(model) を wasm と worker.js・client.js に足した（所有の例外）検査パネルは実行せずに診断が要る。facade の check を JSON で返すだけ
型protocol の構造体から TypeScript の型を手で書く（UI が使う項目だけ）JSON Schema はまだ無い（WP-0 の持ち越し）
試験Python の Playwright 1 本（dist/ を localhost で配る）Playwright は既に開発依存。npm の試験の枠を足さない
起動で落ちた worker作り直さず、以後の呼び出しを rejectworker.js が読めないと 8 秒に 914 回の GET で無限に作り直していた
MPL-2.0Vite 8 が引く lightningcss（ビルド時だけ）は cbindgen と同じくツールとして許可dist にも配布物にも入らない。prod の 12 個は全部 MIT
