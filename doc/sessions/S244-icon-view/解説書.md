## 1. 目的

[roadmap](../../roadmap.md) の「機能の穴（P8）拡充」のうち Diagram / Icon ビューの最初の一切れ、Icon ビュー。カーソルのあるクラス（ライブラリの木・検索で開いたクラスも）の `annotation(Icon(coordinateSystem(extent), graphics))` を SVG にして、S232 の「説明」パネルの上に出す。MSL の部品のアイコンが見えると、ライブラリを眺める価値が上がる。Diagram（部品の配置と connect の線）は次の WP。

## 2. 決定と理由

詳細は [ADR-0037](../../adr/0037-icon-diagram-as-shape-data.md)。

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 渡す形 | SVG の文字列でなく形のデータ（JSON）。UI が要素を組み立てる | 第三者のファイルから来る値を文字列のまま DOM に渡さない（S232 と同じ）。Leptos・Dioxus・VS Code も同じ JSON を描ける |
| 読み方 | `globe-mode-fmt/src/icon.rs`。字句解析と `class_spans`（S232）だけ。annotation の引数を小さな再帰下降で読む | Rumoca の構文解析も新しい依存も足さない。読めない値・要素は飛ばして続ける。括弧が閉じない文書は文の切り出しで落ち、null |
| 要素 | Rectangle・Ellipse・Line・Polygon・Text・Bitmap（枠とファイル名だけ）。ほかは飛ばす | 依頼のとおり |
| 属性 | extent・points・origin・rotation・lineColor・color・fillColor・fillPattern・lineThickness・thickness・pattern・textString・textColor・fontSize・horizontalAlignment・radius・arrow・arrowSize・visible・fileName | 下の表 |
| `extends` | 基底クラスのアイコンを 1 段だけ重ねる（基底→自分）。相対名は外側のクラスから順に試す（同じファイル→ライブラリ）。`EXTENDS_DEPTH` が 1 | 依頼。2 段のもの（`SISO → BlockIcon`）の枠は出ない。上げるのは定数 1 つ |
| 口 | wasm `Workspace.icon(class, text, line, character)`、LSP `globe/icon`（`RPC_METHODS` 23 から 24）、`Backend.icon(cls, at?)` | `documentation` と同じ探し方（クラス名か、行・列のいちばん内側のクラス。文書を先に、無ければライブラリ）。共通の `target` を `documentation.rs` から使い回した |
| 更新 | `modelicaDocs` が説明と一緒に `Promise.all` で引く。アイコンが失敗しても説明は出る | App の変更は状態 1 つとコールバックの引数 1 つ、`DocsPanel` に `icon` を渡すだけ |
| 見え方 | 120px の枠、地は常に明るい。線の太さは画面の px、`viewBox` は extent（y を反転） | Modelica の色は白地が前提。暗でも読める |

対応した要素と属性:

| 要素 | 読む属性 | 描き方 |
| --- | --- | --- |
| Rectangle | extent・radius・lineColor・fillColor・fillPattern・lineThickness・pattern・origin・rotation・visible | `rect`（radius は `rx`） |
| Ellipse | extent と同じ | `ellipse`（弧の startAngle・endAngle は無視） |
| Line | points・color・thickness・pattern・arrow・arrowSize・smooth・origin・rotation・visible | `polyline`。arrow は三角（Filled）か V 字（Open・Half）。Bezier は折れ線 |
| Polygon | points・lineColor・fillColor・fillPattern・lineThickness・pattern・smooth | `polygon` |
| Text | extent・textString・textColor（無ければ lineColor）・fontSize・horizontalAlignment | `text`。`%name` は最後の名前、`%class` は完全修飾名。ほかの `%k` を含む文字列は飛ばす。fontSize 0 は枠に合わせる |
| Bitmap | extent・fileName | 破線の枠とファイル名 |

塗りは `fillPattern` が None 以外なら Solid（グラデーションは無し）。`pattern` は solid・dash・dot・dashdot・dashdotdot。`DynamicSelect(a, b)` は a、式（`2 * 3`）は読めない値。

## 3. 図

```text
エディタ ─ 300 ms ─► modelicaDocs ─ Promise.all ─► Backend.documentation / Backend.icon
                                                        │
ブラウザ・Android  wasm Workspace.icon ─┐                │
Desktop            rpc globe/icon ──────┤ (sidecar)      ▼
                    globe_mode_lsp::icon::icon ─► globe_mode_fmt::icon(src, 名前, library)
                                                        │ {class, extent, shapes}（形のデータ）
                    DocsPanel ─► IconView.svelte（y を反転して svg の要素。{@html} なし）
```

## 4. 再現手順

```bash
export CARGO_TARGET_DIR=…/target-shared CARGO_BUILD_JOBS=2
cargo test -p globe-mode-fmt --lib icon
cargo test -p globe-mode-lsp --lib icon
cargo test -p globe-mode-wasm --test decay icon
mise run wasm:node            # smoke.mjs: 文書のアイコン、MSL の Gain の polygon
mise run ui:check             # pnpm check と test_ui.py の icon_view（MSL の Gain）
```

結果（MSL 4.1.0 の `Modelica.Blocks` の最初の 50 クラス〔Math・Continuous・Sources・Nonlinear・Logical・Discrete・Routing・Interfaces の木の順〕）は 50 個すべて空でない（polygon 46・line 93・text 77・ellipse 10・rect 15）。8 つのサブパッケージの 223 クラスでは 216（空の 7 は Interfaces の部分的な基底クラス〔DiscreteSISO・SignalSource など。自分では Icon を持たず、持つのは 2 段以上先の基底〕）。

## 5. 次回

- Diagram ビュー: 部品の `Placement`（transformation・extent・rotation）と connect の `Line`。同じ形のデータに足す。編集（ドラッグ）はその後。
- 2 段以上の `extends`（`EXTENDS_DEPTH` を上げる）、グラデーションの塗り、楕円の弧、`DynamicSelect` の評価、`%k` の置き換え（パラメータの値）、Bitmap の画像（`modelica://…`）。
- VS Code の拡張には面を足していない（LSP の `globe/icon` はある）。Leptos・Dioxus 版も無し。
