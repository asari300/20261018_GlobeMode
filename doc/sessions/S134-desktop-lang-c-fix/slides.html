S134 · 2026-11-03 · P4

Desktop の C.UTF-8 の白画面

Linux の Desktop は起動時に locale を en_US.UTF-8 に替える

WebKitGTK の言語が C にならないよう、根で直した
目的

このセッションでやること

  • S125 で見つけた不具合: ランナーの既定の locale で Desktop を起動すると UI が白画面
  • 原因は RangeError: invalid language tag: C（CodeMirror の Intl.Segmenter）
  • S125 は測定の段で LANG=en_US.UTF-8 を足して避けただけ。製品を直す（P4、使える流れ）
決定と理由

なぜ言語が C になるか

  • WebKitGTK は setlocale(LC_CTYPE, nullptr) から既定の言語を作る
  • C・POSIX そのものなら en-US にする
  • C.UTF-8 は . 以降を落とすだけなので C になり、BCP 47 として不正
  • 出典: WebKit の Source/WTF/wtf/unix/LanguageUnix.cpp（確認日 2026-11-03）
決定と理由

2 つの直し方

案やること判断
(a) UIIntl.Segmenter の前に既定の言語を確かめて en を渡すuPlot も module の評価で Intl.NumberFormat・DateTimeFormat を作る。全部を包むことになる
(b) Rustmain の最初で、効いている locale が C.・POSIX. で始まれば en_US.UTF-8 に替える採った。言語の根で直すので Intl の使い手によらない
図

起動の流れ

en_US.UTF-8 が無い環境では setlocale が失敗して C のまま。WebKit はそれを en-US にする。
