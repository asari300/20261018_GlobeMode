S017 · 2026-10-22 · P3

Claude の実行場所を Raspberry Pi（aarch64）に移す

fetch-rumoca の aarch64 対応、RPi の環境、msl:funnel のメモリ

RPi でも msl:compare 20 / 20・check 全段通過。製品のコードは変えていない
目的

このセッションでやること

  • S016 までは x86_64 の機械。ユーザーの指示で Raspberry Pi（aarch64、4 コア、RAM 7.9 GiB、glibc 2.36）に移す
  • roadmap の「S017 の最初にやること」の 3 つ:
    1. cargo xtask fetch-rumoca を aarch64 に対応させる
    2. RPi の環境をそろえる（mise・uv・MSL・mise run check）
    3. msl:funnel のメモリ（最大 RSS 7.1 GiB）を RPi で回せるようにする
  • 決定は ADR-0019。検査・実行系のコードは変えない
決定と理由

決めたこと

項目決定理由
作業ツリー（ユーザー）規約どおり main から feature/s017-rpi-aarch64orca の worktree だと finish-session と合わない
mise のツール（ユーザー）全部入れる環境をそろえるそのもの
fetch-rumocaRUMOCA_ASSET を cfg!(target_arch) で選ぶURL・sha256・名前を 1 か所に。未対応の機械でもビルドは通る
メモリ（ユーザー）swap 512 MB → 8 GBデスクトップが 2.7 GiB 使い、7.1 GiB の山が収まらない
elixir今は入れないerlang の arm64 ビルドが glibc 2.38 を要求
CI変えないaarch64 は RPi の手元で足りる

RPi の環境

入った

  • mise 2026.10.15（linux-arm64）
  • rust 1.99.1、cargo-deny 0.20.2、wasm-bindgen 0.2.129
  • zig 0.17.0、julia 1.13.2、gleam 1.19.2、uv 0.13.1
  • erlang 27.3.4.19（入るが動かない）
  • uv sync、MSL 4.1.0（4213 ファイル）、Rumoca CLI（aarch64）

入らない・足した

  • elixir 1.18.3-otp-27: erlang の arm64 ビルド（ubuntu-26.04 向け）が GLIBC_2.38 を要求。RPi は 2.36
  • → MISE_DISABLE_TOOLS=elixir で外す
  • swap: dphys-swapfile 512 MB → 8 GB（再起動後も残る）
再現手順

再現と検証

curl -fsSL https://mise.run | sh
mise trust && MISE_DISABLE_TOOLS=elixir mise install --locked && uv sync
export MISE_DISABLE_TOOLS=elixir
mise run msl:compare     # fetch-msl → fetch-rumoca（aarch64）→ 20 本
mise run check           # fmt / clippy / test / deny / uv sync --locked
mise run msl:funnel      # release で 566 本（swap 8 GB）
20 / 20msl:compare 一致
1055 smsl:compare（ビルド込み）
3798 smise run check
369 / 566msl:funnel OK（x86_64 と同じ）
6.5 GiBmsl:funnel 最大 RSS（24.6 分）
