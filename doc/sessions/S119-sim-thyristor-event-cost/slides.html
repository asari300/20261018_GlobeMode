S088 の持ち越し。ThyristorBridge2mPulse_DC_Drive が esdirk34 で時間切れになる理由を測る

事象の後の最初の刻みは通常の 約 14 倍。刻みを直前の値で抑えて -29%
目的

このセッションでやること

  • 15 s で事象が約 3.75 万回（S088）。1 回ごとに esdirk34 が何をやり直しているかを測る
  • 内訳: 事象の処理 / 事象の後の最初の刻み / 通常の刻み
  • 最小の対策を 1 つ入れ、数値が変わらないこと（管・wasm:compare）を確かめる
  • 全例題は GitHub Actions（msl-sim.yml）で回す

原因: 作り直しの Hairer の見積もりが直前の刻みの約 3.8 倍。棄却が事象あたり 7.6 回（誤差）+ 2.0 回（Newton）

決定と理由

入れた対策: 最初の刻みの上限

  • rk.rs の initial_state で、刻みを「直前に diffsol が次に試すつもりだった刻み」以下に抑える
  • reset と initialize の両方に効く。抑えるだけなので刻みが大きくなる向きの変化は無い
  • 対象は session の道の SDIRK だけ。陽的 RK に当てると wasm:compare の DiodeSwitching/tsit45 が分かれた
  • 選ばなかった案: ヤコビ行列の使い回し（7% しかない）、reset の省略（Rumoca の session の約束を読み替える）
