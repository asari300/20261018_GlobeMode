進捗と中断の LSP と Desktop の段

ADR-0033 の実装の順の 5（最後の段）: globe-mode-lsp、Desktop の worker.rs、TauriBackend

Desktop でも 進捗 が見え、「止める」 で止まる。ADR-0033 は Accepted
目的

このセッションでやること

  • globe/simulate・globe/simulateColumns で facade の simulate_observed を使う
  • 進捗は $/progress（begin・report・end）、中断は $/cancelRequest
  • そのために入力の読みを別のスレッドにする。計算は 1 度に 1 つのまま
  • Desktop の UI（S133 の進捗の行と「止める」）を sidecar の道でも動かす
決定と理由

決めたこと

項目決定理由
スレッド読みのスレッドがキューに積む。計算と書き出しは元のスレッド書き手が 1 つで済む。Server は動かさない
トークン読んだ時点で id の表に置くキューで待つ要求も止められる
進捗のトークンparams の workDoneToken（クライアントが作る）ADR の決定 (3)。create の往復が要らない
report の値message・percentage に段と t を添えるUI の Progress をそのまま渡せる
DesktopCanceller と command cancel_run実行中は Worker の Mutex が握られている
応えないとき2 s で sidecar を作り直すネイティブの積分の中では止まらない（ADR の表の Desktop の行）

Desktop の「止める」

段何が起きるか
UITauriBackend.cancel() が command cancel_run を呼ぶ
シェルCanceller が sidecar の stdin に $/cancelRequest を書く（Mutex の外）
sidecar が止めた普通の応答: cancelled、途中までの列、GM-I11004
2 s 応えないsidecar を kill。次の要求で作り直し、UI は「止めた」
