決定と理由 · 方式

4 案を実測して、スキル＋スクリプトにした（ADR-0008）

案実測・事実判定
A. スキル＋スクリプト（/local-review）依存なし。分割・除外・推論の切り替え・見積もりを自分で制御できる採用
B. MCP（houtini-lm 3.3.4）✔ Connected。同じコードで 105.9 秒・1 件だが行番号がずれ、MCP サーバ側のタイムアウトで出力が切れた比較のみ
C. claude --bare -p を LM Studio へ"pong" に 179 秒（入力 1,197）。ctx を 200K と仮定する。Claude 以外は Anthropic のサポート外不採用
D. hooks で自動実行1 回 10 分以上で会話が止まる。誤検知に毎回振り回される不採用

サブエージェントの model は Claude のモデルしか選べず、接続先を変えられない。そのため「LM Studio を使うサブエージェント」という案は成り立たない。

決定と理由 · 資源の調整

メモリではなく計算が律速。ctx は「1 回に読ませる量」で決める

設定推奨根拠（実測）
ctx12,288KV は 0.75 GiB。16K の入力は読むだけで約 30 分
GPUoffmax と速さが同じ。読み込みは 53 → 8.5 秒
並列1既定の 4 は要らない
推論切る「17×23」が 126.7 → 3.8 秒
KV 量子化fp16 のままq8_0 にしても 0.35 GiB しか減らない（GUI でのみ設定）
TTL1800 秒使い終わったら RAM を返す
lms load prism-ml/bonsai-27b \
  -c 12288 --gpu off --parallel 1 \
  --ttl 1800 -y

全体の見積もり（--estimate-only）は 8K で 5.27 GiB、32K で 6.44 GiB。RAM は 31GB あるので余る。詳細は 03。

決定と理由 · 安全

いまの LM Studio は外に開いていて、プロンプトを全文ログに書いている

項目いま推奨（ユーザーが GUI で変える）
Serve on Local Network有効（0.0.0.0。LAN と Tailscale から届く）無効（127.0.0.1）。mirrored なら WSL から届く
プロンプトの全文ログ有効無効。差分がそのままログに残るため
Require Authentication無効127.0.0.1 なら任意。0.0.0.0 にするなら必須
  • スクリプト側でも、ロックファイル、data/、log/、.env*、鍵らしいファイル、バイナリは送らない
  • トークンは LMSTUDIO_API_TOKEN の環境変数で渡し、リポジトリには書かない（02 の S04）
結果 · 実際にかけた

分かりやすい問題は拾う。境界の計算は見逃す（1 / 3）

対象入力合計結果
lmstudio_review.py の 1 塊6,15419.4 分NO_FINDINGS
バグを 3 つ仕込んだ 24 行62091 秒指摘 1 件
場所中身判定
stats.py:6ファイルを閉じない（指摘）採用・行番号も正しい
stats.py:13range(len - window) の off-by-one見逃し
stats.py:22窓が長いと avg[-1] が IndexError見逃し
stats.py:23空の入力で ZeroDivisionError見逃し

「指摘なし」は「問題なし」ではない。分かりやすい問題は拾うが、境界の計算は見逃す。主のレビューは Claude が行う。

同じコードを MCP（houtini-lm）に渡すと 105.9 秒で同じ 1 件。行番号がずれ（4、正しくは 6）、出力も途中で切れた。詳細は 04 と 05。
