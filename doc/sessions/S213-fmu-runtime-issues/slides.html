結果

4 点の振り分け

#指摘再現対応
1入口の panic が境界を越えるしない直さない。入力が見つからない

決定と理由

2: x の start 値が消える

  • fmi2SetReal は状態を直接書くが、パラメータが変わると ExitInitializationMode が作り直す。
  • FMPy の start_values={'x': 5, 'k': 2} と同じ順で、x は 5 でなく 1 に戻っていた。
  • inputs と同じ表（添字 → 値）を持ち、作り直した後に置き直す。
  • fmi2Reset が既定に戻るのは規格どおりなので、変えない。
[1, 2]直す前
[5, 2]直した後
決定と理由

1 を直さなかった理由

  • Rust 2024 の extern "C" は unwind を abort にする。UB ではない。
  • 落ちる入力が無い。範囲外の値参照、NaN、空のモデル、1/0、代数ループ、when はどれも Error か NULL で返った。
  • MSL の全例題で panic は 0 本。
  • 見つかったら each・states・instantiate・rebuild の 4 か所を包む。
決定と理由

3 と 4

3 CC を分ける

export.rs の build の 1 か所。split_whitespace で最初を実行ファイル、残りを引数にした。write_fmu には触れていない。

4 ドライブ文字

resource_path に切り出し、/C:/… の先頭の / を落とす。単体は文字列で試す。実機は CI の Windows。
