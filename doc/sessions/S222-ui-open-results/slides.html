UI の「結果を開く」

「開く」が .mat と .csv も受け付け、実行の結果と同じプロットで見られる

新しい描画は書かない。Plot.svelte をそのまま使う
Rust

バイト列から読む入口を 1 つ

  • mat::read_results_bytes(名前, バイト列)。read_results(path) はファイルを読んでこれを呼ぶ
  • facade の open_results が simulate_columns と同じ列の形にする
  • 既定で描く信号は先頭の 3 本（読んだ結果に役割は無い）
道

ブラウザと Desktop で道を分ける

面道理由
ブラウザ・Androidwasm の read_results(名前, bytes)ファイルの中身は JS が持つ
Desktopsidecar の globe/readResults {path}wasm が無い。bytes を JSON で往復しない
UI

タブの種類は 1 つ足しただけ

  • Tab.results に読んだ列を持つ。編集はできず、エディタは隠れる
  • activate が columns = t.results にするので、プロットは実行の結果と同じ
  • 実行・保存は断る。自動保存と再読み込みの対象外
試験

確かめたこと

  • Rust: バイト列の往復、LSP の globe/readResults、wasm の Node（MAT の実物と CSV）
  • Playwright: .csv と omc の .mat を開いてプロット、タブの切り替え、保存は断る、読めないファイルは理由
次回

持ち越し

  • 結果のタブは再読み込みで戻らない（列を localStorage に持たない）
  • MAT のパラメータは UI に出さない
