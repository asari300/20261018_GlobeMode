## 1. 目的

[roadmap.md](../../roadmap.md) の P8「Diagram ビュー」の編集の最初の一切れ。図の部品をドラッグして離したら、その宣言の `annotation(Placement(transformation(origin = {x, y})))` をソースのテキスト編集で書き換える。S245 の読み取りの図に、書き込みの道を 1 本通す。

## 2. 決定と理由

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 何を書き換えるか | `origin` だけ（`extent` は触らない） | `extent` は `origin` からの相対、`rotation` があっても `origin` は図の座標の平行移動（`diagram.rs` の `matrix`）なので、`origin += (dx, dy)` で図の上の動きと一致する |
| `origin` が無い宣言 | `transformation(` の直後に `origin = {dx, dy}, ` を足す | 既定の `origin` は `{0, 0}`。足せば `extent` だけの宣言も動く |
| 動かさないもの | Placement の無い宣言、`origin` が数の並びでない（式）宣言 | 読めない値を勝手に書き換えない（null を返し、UI は元の位置に戻す） |
| 誰が決めるか | Rust の `globe_mode_fmt::move_part`（字句解析。バイト範囲と文字列） | 業務ロジックを UI に置かない。範囲の UTF-16 の列への変換は LSP 層（`position`） |
| 口 | LSP `globe/movePart`（`RPC_METHODS` 26 → 27）、wasm `move_part`、`Backend.movePart` | `rename` と同じ形（TextEdit の配列）。UI は `rename` と同じく 1 回の `dispatch`（undo 1 回） |
| 保存 | しない | ファイルを書くのはユーザー。編集はエディタの中だけ |
| 吸着 | UI で 2 単位の格子（移動量に対して） | Modelica の図の慣習。原点に対してでなく移動量に対する吸着にしたのは、UI に `origin` を持たせないため |
| クリックとの区別 | 4 px 未満は移動でない。移動の直後のクリックは宣言へ飛ばさない | S245 のクリック、S248 のダブルクリックを壊さない |
| 結線 | 点は動かさない | `Line(points)` を持たない connect は中心どうしなので、図が読み直されると部品に追従する。点つきの線は次回 |

## 3. 図

```text
pointerdown(部品の <g>) → pointermove(transform だけ動かす、2 単位に吸着) → pointerup
  → backend.movePart(diagram.class, part, dx, dy)   … Rust: origin の書き換え編集
  → view.dispatch(changes)                           … エディタが変わる（Ctrl+Z で戻る）
  → 300 ms 後に図が読み直され、見た目の transform を捨てる
```
