## 1. 目的

変換デバッガの最初の一切れとして、モデルが段ごとにどう変わるかを CLI で見せる（[roadmap](../../roadmap.md) の P8、[features](../../features.md) の変換デバッガの行）。S256 の `globe blt` は BLT だけだった。

## 2. 決定と理由

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 段 | flat → DAE → インデックスの低減（S7）→ BLT → tearing（S9） | 既存の検査の結果から取れるものだけ。新しい解析は足さない |
| flat → DAE | 数だけ（変数・方程式の増減） | Rumoca の DAE は別名を畳まない（`y = x` の別名も方程式のまま残る）ので、増減は 0。flat の変数名は `FlatSummary` が持たず、名前の対応は取れない |
| 名前で出す差分 | 微分した方程式（ラベルと回数）、増えた未知数（`der(der(x))`）、状態選択の候補、tearing 変数と残差 | S7 と S9 が添字で持っているものを `DaeStructure` の名前に引き直すだけ |
| 型 | `StagesReport`（`globe-mode-analysis::stages`）。既存の型は変えていない | `LoopReport` に足すと S9 の JSON と snapshot が変わる |
| 経路 | `GlobeDb::stages` → `Workspace::stages`。検査が通らなければ診断（`blt` と同じ） | LSP・Svelte は他の WP が触るので今回は CLI と facade だけ |
