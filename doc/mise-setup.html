2. Nix と mise

結論: このリポジトリでは mise を選びます。 1 人で使う実験用のモノレポで、6 言語のツールチェーンを揃えてバージョンを固定できれば足りるためです。

観点miseNix
学習コスト低い。TOML 1 ファイル高い。Nix 言語と flakes を覚える
uv / Cargo との関係そのまま併用できるNix 側と二重管理になりやすい (Python の取得、ホイール、Cargo の依存など)
再現性ツールのバージョンまで (mise.lock)OS ライブラリを含めてほぼ完全に再現できる
タスク実行標準機能標準のタスクランナーはない
WSL2 (Ubuntu)そのまま動く動くが、導入と設定の手間が増える

Nix が向くのは、ネイティブライブラリまで含めた厳密な再現が必要になったとき (チーム共有や CI で環境差が問題になったとき) です。その段階で移行を検討すれば十分です。

3. セットアップ手順

3-1. mise を入れる (Homebrew)

この環境には Homebrew (/home/linuxbrew) があるので、それで入れます。apt には mise のパッケージがありません。

shell
brew install mise
mise --version

3-2. zsh に有効化を追加する

Homebrew の shellenv を読み込む行より後ろに書いてください。ディレクトリに入ると mise.toml のツールが PATH の先頭に出るようになります。

shell
echo 'eval "$(mise activate zsh)"' >> ~/.zshrc
exec zsh

IDE のタスクや cron のような非対話シェルから使う場合は、~/.zshenv に shims 版を足します。

~/.zshenv (任意)
eval "$(mise activate zsh --shims)"

3-3. Erlang のビルド依存を入れる (ソースビルドする場合のみ)

Ubuntu 26.04 は mise の Erlang プリコンパイル版の自動判定に含まれません。まず 4 章の precompiled_os 指定を試し、「プリコンパイル版が見つからない」と失敗したときだけ、compile = true にして kerl でソースビルドします。そのときは次のパッケージが必要です (現時点では未導入)。

shell
sudo apt install -y autoconf m4 libssl-dev libncurses-dev unzip

3-4. バージョンを確認する

各ツールの利用可能なバージョンを確認してから mise.toml を書きます。Elixir は X.Y.Z-otp-NN という形式で、OTP のメジャー番号ごとにビルドがあります。

shell
mise ls-remote erlang
mise ls-remote elixir 1.18
mise ls-remote zig
mise ls-remote julia
mise ls-remote gleam
mise ls-remote uv 0.12

3-5. mise.toml を作って導入する

mise.toml は 4 章の内容でリポジトリのルートに作ります。その後、次の順に実行します。

shell (リポジトリのルートで)
mise trust
mise install
mise lock
uv sync

mise trust は、その mise.toml を信頼すると mise に伝えるコマンドです。初回だけ必要です。mise lock は解決結果を mise.lock に書きます。

4. mise.toml の完成例

リポジトリのルートに置きます。ポイントは次の 4 つです。

  • Python は書かない。 Python 本体は uv が .python-version (3.12) から取得します。mise にも python を入れると、どちらの Python が使われるかが曖昧になります。
  • uv は 0.12 に固定。 pyproject.toml のビルドバックエンドが uv_build>=0.12.6,<0.13.0 を要求しているためです。
  • Erlang と Elixir は OTP 番号を揃える。 elixir = "latest" は最新の OTP 向けビルドを選ぶので、erlang を古い版に固定していると食い違います。
  • Ubuntu 26.04 では precompiled_os を明示する。 自動判定されないためです。
mise.toml
[settings]
lockfile = true                    # 解決した正確なバージョンを mise.lock に記録する

[settings.erlang]
precompiled_os = "ubuntu-26.04"    # Ubuntu 26.04 は自動判定されないので明示する
# compile = true                   # プリコンパイル版が無いときは kerl でソースビルド (3-3 の apt が必要)

[tools]
uv     = "0.12"                    # pyproject.toml の uv_build>=0.12.6,<0.13.0 に合わせる
rust   = { version = "stable", profile = "default", components = ["rust-analyzer"] }  # edition 2024 は 1.85 以上
zig    = "latest"
julia  = "latest"
erlang = "27"                      # いま apt で入っている組み合わせと同じ
elixir = "1.18.3-otp-27"           # erlang のメジャー番号と -otp-NN を必ず揃える
gleam  = "latest"

# python は書かない。Python 本体は uv が .python-version (3.12) から取得する。

latest や stable を使っても、mise.lock に正確なバージョンが記録されるので再現性は保たれます。新しい OTP に上げるときは、erlang と elixir の OTP 番号を同時に変えてください。

Rust の stable 指定が通らない場合は、rustc --version で確認した 1.85 以上の数値 (例: version = "1.xx") に置き換えてください。profile = "default" には clippy と rustfmt が含まれます。

.gitignore に追加する

.gitignore
# mise (個人用の上書き)
mise.local.toml
mise.local.lock

5. 言語別の使い方

mise は PATH にツールを出すだけなので、日常の操作は各言語の標準コマンドのままです。

Python (uv)

uv が .python-version を読み、必要なら CPython 3.12 を取得します。

shell
uv sync
uv run 20261018-globemode
uv run python -V

Rust (Cargo)

ルートの Cargo.toml と src/main.rs をそのまま Cargo で扱います。rust-toolchain.toml は作らず、バージョンは mise.toml に一本化してください (mise が設定する RUSTUP_TOOLCHAIN が優先され、ファイルが無視されるため)。

shell
cargo build
cargo run
cargo fmt --check
cargo clippy -- -D warnings

Zig

shell
cd src/Zig
zig init
zig build run

Julia

src/Julia に Project.toml ができた後の操作です。

shell
julia --project=src/Julia -e 'using Pkg; Pkg.instantiate()'
julia --project=src/Julia

Elixir

初回に Hex と rebar を入れておくと、対話の確認で止まりません。

shell
mix local.hex --force
mix local.rebar --force
cd src/Elixir
mix new . --app globe_mode
mix deps.get
mix test

Gleam

Gleam のプロジェクト名は小文字とアンダースコアのみなので、--name を付けます。

shell
cd src/Gleam
gleam new . --name globe_mode
gleam test
gleam run

6. タスク定義の例

任意です。実際にプロジェクトがある Python と Rust だけを定義しています。空の src/Elixir などは、プロジェクトを作った後に同じ形で足してください。コロンを含むタスク名は、TOML のキーとして引用符で囲む必要があります。

mise.toml (末尾に追記)
[tasks.setup]
description = "ツールを導入して Python 依存を同期する"
run = ["mise install", "uv sync"]

[tasks."py:run"]
description = "Python のエントリポイントを実行する"
run = "uv run 20261018-globemode"

[tasks."rust:run"]
description = "Rust のバイナリを実行する"
run = "cargo run"

[tasks.check]
description = "uv.lock の整合と Rust の fmt / clippy を確認する"
run = ["uv sync --locked", "cargo fmt --check", "cargo clippy -- -D warnings"]
shell
mise tasks ls
mise run setup
mise run check
mise run py:run

7. ロックファイルの運用

mise.toml には「許容する範囲」、mise.lock には「実際に解決した正確なバージョン」が入ります。両方をコミットします。

shell
# ロックの記録どおりに導入する (別マシン・CI 向け)
mise install --locked

# 更新の差分だけ確認する (何も書き換えない)
mise lock --bump zig --dry-run

# 許容範囲の最新を導入して mise.lock も更新する
mise upgrade zig

ロックの対象はツールだけです。uv.lock や Cargo.lock など各言語のロックファイルも引き続きコミットします。

8. 既存環境との共存

このマシンには mise 以外の経路で入ったツールがあります。mise activate したシェルでは mise のツールが PATH の先頭に来るので、基本的には mise 側が優先されます。どれが使われているかは mise which で確認できます。

  • apt の Erlang / Elixir (/usr/bin/erl, OTP 27 / Elixir 1.18.3): 消さずに残して構いません。mise の版が優先されます。
  • uv (~/.local/bin/uv 0.12.6): mise の uv = "0.12" と併存します。どちらも 0.12 系なので実害はありません。
  • rustup (~/.rustup, ~/.cargo): mise は既存の rustup を使い、RUSTUP_TOOLCHAIN を設定してツールチェーンを選びます。cargo install の成果物は ~/.cargo/bin に入り、全ツールチェーンで共有されます。
  • juliaup (~/.juliaup): ~/.profile で PATH に追加されていますが、確認時点では julia コマンドは見つかりませんでした。mise の Julia を使う限り juliaup は不要です。両方が見える状態になったら which -a julia で順序を確認してください。
  • Homebrew の Python: uv の Python 一覧に出てきますが、このリポジトリの Python 3.12 は uv が取得するものを使います。

おかしいときは、まず次を実行してください。

shell
mise doctor
mise ls
mise which erl
mise which uv
which -a julia

9. 動作確認チェックリスト

リポジトリのルートで、すべてがエラーなく版数を返せば導入は完了です。Elixir の出力に含まれる compiled with Erlang/OTP NN が、mise.toml の OTP 番号と一致していることも確認します。

shell
mise doctor
uv --version
uv run python -V
rustc --version
cargo --version
zig version
julia --version
elixir --version
gleam --version

mise を有効化していないシェルで試すときは、各コマンドの前に mise exec -- を付けます (例: mise exec -- zig version)。
